# Опытный системный VPN Windows

Отдельный ARM64-пакет для проверки архитектуры на собственной Windows 11 VM. Не распространять пользователям. Исходный клиент `.8`, его служба и Wintun пока не заменяются.

Сборка: `scripts/build.ps1 -Architecture arm64 -SdkVersion 10.0.26100.0`. Нужны Windows SDK 10.0.26100.0, MSVC v143, CMake и PowerShell 7. Артефакт содержит подписанный MSIX, отдельный пакет отрицательной проверки, публичный `.cer`, SHA256 и скрипты установки/отката. Закрытый ключ не экспортируется и удаляется со сборочного runner.

`install-test.ps1` запускается администратором **от имени владельца VM**. Он проверяет хеш, издателя и подпись, добавляет только опытный публичный сертификат в TrustedPeople и устанавливает пакет для текущего пользователя. Trusted Root, Defender, UAC и настройки обновления не изменяются.

## Управление и диагностика

Команды `aheadscale-vpn-prototype.exe`: `add`, `status`, `connect`, `disconnect`, `remove`. Команда `add` создаёт штатный пользовательский профиль Windows через `Add-VpnConnection` с собственными `PlugInApplicationID` и `CustomConfiguration`; имя чужого профиля занимать запрещено. Остальные команды используют `VpnManagementAgent`. Регистрация только в приватной телефонной книге пакета не означает появления в системных настройках.

`broker` открывает AppService фиксированной Package Family Name. Windows сообщает обработчику реальную `CallerPackageFamilyName`; допускается только свой пакет в текущем пользовательском сеансе, удалённый вызов запрещён. Посредник выполняет штатный RPC status через прежний защищённый IPC службы. Пароли, токены и ключи не передаются. Открытие AppService само по себе недостаточно: вызывающая сторона должна получить успешный ответ на регистрацию.

`broker-packet-probe` дополнительно передаёт известный 28-байтный IPv4/ICMP-пакет в обе стороны AppService и проверяет точные байты. Бинарный payload ограничен 65535 байтами; это проверка локальной границы процессов, **не обмен с другим устройством**. Запускать Connect после сообщения `app-service-broker-ready`. Посредник ждёт не более 90 секунд. Пакет `Aheadscale.VpnNegativeProbe` предназначен только для проверки отказа другой подписанной идентичности через `probe-service`; устанавливается оператором после проверки манифеста и подписи, с записью полного имени в квитанцию.

Проба прямого AppContainer pipe сохранена в `ipc_probe.cpp` для воспроизведения ограничения Windows: pipe открывается, но проверка личности desktop-процесса из AppContainer возвращает Access Denied. Активный путь использует AppService; прежние проверки не ослаблены.

## Граница готовности

**Connect намеренно завершается ошибкой даже после успешной проверки IPC**: канал IP-пакетов ещё не подключён к движку. Это не рабочая VPN-интеграция. Диагностика `vpn-plugin.json`, `vpn-background.json`, `app-service.json` находится в LocalState пакета; токены, ключи и содержимое IP-пакетов не журналируются.

Откат: `remove-test.ps1`. Он сверяет квитанцию `%LOCALAPPDATA%\AheadscaleVpnPrototype\install.json`, удаляет принадлежащие установке профиль, основной и записанный отрицательный пакет, затем только добавленное при установке доверие. Рабочая регистрация обычного Aheadscale сохраняется.

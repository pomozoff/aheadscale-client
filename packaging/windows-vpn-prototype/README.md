# Опытный системный VPN Windows

Закрытый preview системного VPN для собственных Windows 11 VM. Поддерживаются сборки `arm64` и `amd64`; архитектуру MSIX `x64` не следует путать с именем Go `amd64`. Не распространять пользователям: публичной подписи пока нет. Стандартный CLI сохраняет собственную службу и Wintun; desktop preview переключает службу на проверенный native-компонент с резервом для восстановления.

Сборка: `scripts/build.ps1 -Architecture amd64 -SdkVersion 10.0.26100.0`. Нужны Windows SDK 10.0.26100.0, MSVC v143, CMake и PowerShell 7. Артефакт содержит подписанный MSIX, отдельный пакет отрицательной проверки, публичный `.cer`, SHA256 и скрипты установки/отката. Закрытый ключ не экспортируется и удаляется со сборочного runner.

`install-test.ps1` запускается администратором **от имени владельца VM**. Он проверяет хеш, издателя и подпись, добавляет только опытный публичный сертификат в TrustedPeople и устанавливает пакет для текущего пользователя. Trusted Root, Defender, UAC и настройки обновления не изменяются.

С согласия владельца опытной ВМ установщик также создаёт постоянное входящее правило UDP 51830 во всех сетевых профилях с любых удалённых адресов. Оно привязано только к `AheadscaleNativeDaemon.exe` установленного пакета; его SHA256 проверяется по манифесту. Имя правила включает SID владельца и сохраняется в квитанции. Удаление сверяет область правила до изменения профиля или пакета и отказывает, если параметры изменены вручную. Прежние квитанции без правила поддерживаются.

## Управление и диагностика

Команды `aheadscale-vpn-prototype.exe`: `add`, `status`, `connect`, `disconnect`, `remove`. Команда `add` создаёт штатный пользовательский профиль Windows через `Add-VpnConnection` с собственными `PlugInApplicationID` и `CustomConfiguration`; имя чужого профиля занимать запрещено. Остальные команды используют `VpnManagementAgent`. Регистрация только в приватной телефонной книге пакета не означает появления в системных настройках.

`broker` открывает AppService фиксированной Package Family Name. Windows сообщает обработчику реальную `CallerPackageFamilyName`; допускается только свой пакет в текущем пользовательском сеансе, удалённый вызов запрещён. Посредник выполняет штатный RPC status через прежний защищённый IPC службы. Пароли, токены и ключи не передаются. Открытие AppService само по себе недостаточно: вызывающая сторона должна получить успешный ответ на регистрацию.

`broker-packet-probe` дополнительно передаёт известный 28-байтный IPv4/ICMP-пакет в обе стороны AppService и проверяет точные байты. Бинарный payload ограничен 65535 байтами; это проверка локальной границы процессов, **не обмен с другим устройством**. Запускать Connect после сообщения `app-service-broker-ready`. Посредник ждёт не более 90 секунд. Пакет `Aheadscale.VpnNegativeProbe` предназначен только для проверки отказа другой подписанной идентичности через `probe-service`; устанавливается оператором после проверки манифеста и подписи, с записью полного имени в квитанцию.

Проба прямого AppContainer pipe сохранена в `ipc_probe.cpp` для воспроизведения ограничения Windows: pipe открывается, но проверка личности desktop-процесса из AppContainer возвращает Access Denied. Активный путь использует AppService; прежние проверки не ослаблены.

## Граница готовности

Опытная сборка подключает канал IP-пакетов к движку и согласует управление из приложения и Windows Settings. На ARM64 ВМ проверены реальный обмен с Ubuntu и перезапуск службы. Это комплект только для собственных испытаний; перезагрузка ОС и оставшиеся критерии полного прогона отмечаются отдельно в отчёте. Диагностика `vpn-plugin.json`, `vpn-background.json`, `app-service.json` находится в LocalState пакета; токены, ключи и содержимое IP-пакетов не журналируются.

Откат: `remove-test.ps1`. Он сверяет квитанцию `%LOCALAPPDATA%\AheadscaleVpnPrototype\install.json`, удаляет принадлежащие установке профиль, основной и записанный отрицательный пакет, собственное неизменённое правило UDP, затем только добавленное при установке доверие. Рабочая регистрация обычного Aheadscale сохраняется.

Фактические результаты: [ARM64, GUI и обмен](../../docs/aheadscale/smoke-results/2026-10-20-windows-vpn-gui.md), [x64, единый EXE и перезагрузка](../../docs/aheadscale/smoke-results/2026-10-24-windows11-x64-native.md).

## Единый установщик x64

`package-desktop.py` объединяет native-артефакт CI и стандартный desktop EXE
одной версии в один тестовый EXE. Требуются Python 3, 7z и закреплённый NSIS
с x86-unicode ShellExecAsUser. Сборщик сверяет SHA256 native-файлов и содержимое
стандартного установщика с указанными CLI/UI. Пример из корня репозитория:

```bash
python3 packaging/windows-vpn-prototype/package-desktop.py \
  --native /path/to/aheadscale-windows-vpn-amd64-PROTOTYPE \
  --standard-installer dist/aheadscale_0.80.0-aheadscale.11_windows_amd64_public.exe \
  --standard-cli build/windows-amd64-public/aheadscale.exe \
  --standard-ui build/windows-amd64-public/aheadscale-ui.exe \
  --output dist/aheadscale_0.80.0-aheadscale.11_windows_amd64_native-preview.exe
```

Этот preview требует Windows 11 24H2+ и административную учётную запись
текущего пользователя. Перед изменениями он проверяет все вложенные файлы,
удерживая их открытыми без разрешения записи/удаления. Резерв настройки SCM
хранится отдельно с доступом только SYSTEM/Administrators; ключи и токены
устройства в него не копируются. При ошибке переключения возвращается исходная
служба. Удаление использует квитанцию для собственного пакета, профиля, правила
UDP и добавленного доверия; изменённые извне ресурсы сохраняются с ошибкой.

Native VPN является пользовательским профилем Windows. UI возобновляет
подключение после входа в Windows, если включено автоматическое подключение.
Стандартный headless CLI и native desktop — разные способы запуска; работа
native-плагина до входа пользователя этим установщиком не обещается.

# RG40: доступ macOS к собственному IPv4 Aheadscale

Владелец согласовал реализацию 27.10.2026: направлять обращения к собственному
VPN-IPv4 через lo0, сохраняя исходный VPN-адрес. Изолированный UTUN-прототип
подтвердил HTTP 200 после `route change -host IP -ifp lo0 -ifa IP`;
смена способа назначения адреса не помогла. Маршрут сохраняется после закрытия
UTUN, поэтому необходимы журнал намерения и уборка после аварии.

Клиент меняет только локальный /32, который ядро создало для его UTUN.
Перед изменением сохраняет намерение в штатном закрытом журнале statemanager;
проверяет маршрут ещё раз после сохранения. Уборка удаляет только точное
совпадение записанного адреса, lo0, собственного gateway и LOCAL/HOST.
Метки PROTO при `route change` ядром не сохраняются; полагаться на них нельзя. Неизвестный или изменённый
маршрут не удаляется. Ошибка уборки сохраняет журнал для повторной попытки.
Disconnect, отказ создания устройства, Close и смена адреса выполняют уборку.
При старте службы штатное RestoreResidualState убирает остаток после аварии.
Netstack, IPv6, маршруты других узлов, firewall, sysctl и RG39 не меняются.
Проверки выполняются на macOS ARM64 в изолированной тестовой ВМ и CI;
публичного выпуска, Developer ID и Network Extension эта работа не включает.

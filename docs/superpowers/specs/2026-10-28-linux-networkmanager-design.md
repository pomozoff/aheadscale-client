# Полное управление Aheadscale через NetworkManager

Дата: 28 октября 2026 года. Статус: дизайн для согласования, реализация не начата.
Подход выбран владельцем: адаптировать официальный VPN-плагин NetBird `v0.1.12`.

## Цель и пользовательский результат

В первом выпуске Linux пользователь устанавливает один Desktop DEB/RPM и входит
в Aheadscale. Постоянный VPN-профиль Aheadscale появляется автоматически в штатной
сетевой панели. Connect, Disconnect и Cancel работают и там, и в приложении;
CLI того же Desktop-комплекта управляет тем же соединением. Ввод адреса сервера,
ручное создание профиля, установка второго пакета и команды настройки не нужны.

Настоящий туннель и устройства остаются прежними. При системном Disconnect сеть
действительно выключается, приложение перестаёт показывать Connected; при Cancel
поздний ответ входа/Up не поднимает отменённое соединение. После перезапуска
NetworkManager управление продолжает работать.

## Исходное состояние и подтверждённый дефект

В `.26` NetworkManager принимает уже созданный демоном WireGuard-интерфейс.
Его профиль имеет Flags=15 и исчезает при Disconnect. После restart NetworkManager
старый обработчик остаётся подписанным на прежнего владельца D-Bus/путь устройства.
На Ubuntu и Fedora ARM64 системный OFF удалил адреса, но GUI/CLI сохранили
Connected и старый IP. Это RG43; [живой отчёт](../../aheadscale/smoke-results/2026-10-28-linux26-r05.md).

Это расширение реализации R05, уже включённое владельцем в первый выпуск.
Существующие PASS других ОС и прежних установщиков сохраняют свои границы.

## Рассмотренные подходы

1. **Адаптировать официальный плагин — выбран владельцем.** Есть реализация
   D-Bus VPN API, gRPC, входа и отмены. Цена: сопровождение отдельного исходника,
   проверка совместимости и привязка сборки к двум коммитам.
2. **Свой компонент в репозитории клиента.** Один репозиторий и общий protobuf,
   но реализация входа, VPN API и жизненного цикла полностью ложится на проект.
   Этот путь не выбран.

## Основа и границы совместимости

- Upstream: `netbirdio/network-manager-vpn-plugin`, стабильный тег `v0.1.12`,
  коммит `1c1e87d67e2d1e20e52d40a752bae304a7f1d48a`; изменяемый `main` не используется.
- Лицензия BSD-3-Clause, исходные лицензии/notices сохраняются. Названия
  исполняемых файлов, служб, профиля, auth-dialog и видимые строки — Aheadscale.
- Изменения адаптации ведутся отдельным локальным форком; источник пакетов
  фиксируется в манифесте вместе с коммитом клиента. Не переписывать Go-import
  пути и юридические notices ради косметической замены названия.
- Upstream использует daemon API NetBird `v0.73.2`; совместимость с форком
  `0.80.0` проверяется по реальным RPC, а не только по успешной компиляции.
- В исходнике тега проверен `DisableProfiles`: он позволяет работать с default
  без создания дополнительного daemon-профиля. Для Aheadscale это обязательный
  режим: одна активная сеть и прежние ключ/учётка/устройство.
- Инструменты сборки клиента остаются закреплёнными, включая Go `1.26.7`.
  GTK/libnm-компоненты собираются под заявленный минимум ОС.

## Компоненты и владение сетью

Постоянный профиль типа VPN использует собственный service-type Aheadscale.
Компонент `nm-aheadscale-service` принимает команды NetworkManager и обращается
к существующему демону через `/var/run/aheadscale.sock`. Демон сохраняет
ответственность за WireGuard, IP, маршруты, приватный DNS и firewall.

Плагин отправляет NetworkManager минимальный Config без повторного применения
IP-конфигурации. Такой контракт предусмотрен
[архитектурой upstream](https://github.com/netbirdio/network-manager-vpn-plugin/blob/1c1e87d67e2d1e20e52d40a752bae304a7f1d48a/docs/architecture.md).
Это контроллер настоящего движка: системный Connected допускается только после
успешного запуска движка и наличия ожидаемых адресов на его интерфейсе.

Старое внешнее WireGuard-представление заменяется постоянной VPN-строкой.
NetworkManager не управляет самим транспортным интерфейсом Aheadscale; правило
ограничено его точным именем и принадлежностью установке. Чужие интерфейсы,
включая NetBird/Tailscale, не попадают под маску.

**Особая адаптация текущего форка:** его DNS-менеджер предпочитает NetworkManager
при forwarding в systemd-resolved. Простая установка unmanaged-правила здесь
недостаточна. Native-режим обязан выбирать совместимый DNS-backend, который
работает с принадлежащим демону интерфейсом; на проверяемых Ubuntu/Fedora это
systemd-resolved. Нельзя менять глобальный DNS ОС или отключать проверку имён,
чтобы обойти конфликт. Другой DNS-backend сначала требует отдельной приёмки.

## Один поток команд и согласованные состояния

- В Linux добавляется реализация существующего интерфейса `nativeVPNController`.
  GUI активирует/деактивирует постоянный профиль через NetworkManager.
- CLI Desktop-комплекта использует тот же путь для Up/Down/Cancel при включённом
  native-режиме. Чистый серверный CLI сохраняет самостоятельный режим без NM.
- Режим контроллера явно задаётся установленной службе и доступен клиентам через
  совместимое определение возможностей демона. Он включается только при
  согласованно установленном комплекте. Исчезновение плагина не должно приводить
  к молчаливому запуску обходного туннеля из GUI.
- В native-режиме используется существующая точка `connectOnServiceStart`:
  обычный демон обслуживает RPC, запуском двигателя управляет контроллер.
  Пользовательский `DisableAutoConnect` не переписывается ради технического режима.
- Контроллер запускается системной службой без ожидания GUI. После загрузки
  зарегистрированное устройство подключается по сохранённому выбору через
  активацию своего NM-профиля. Графический вход нужен только там, где действительно
  требуется интерактивная авторизация, а не для восстановления действующего ключа.
- Переходы: Disconnected → Connecting → Connected; из Connecting/Connected
  отключение ведёт через очистку в Disconnected. Вход пользователя — отдельное
  состояние, а не фиктивный Connected.
- Команды сериализуются. У каждой попытки есть поколение; Cancel отменяет вход,
  Up, повторные попытки и поздние завершения только своей попытки. Новый Connect
  ждёт завершения Down/очистки предыдущей и не получает её поздний результат.
- Намерение текущего сеанса и поколение контроллера хранятся без секретов в
  root-owned runtime-состоянии. Явный OFF сохраняется при restart плагина,
  демона и NetworkManager. После настоящей загрузки ОС применяется сохранённый
  пользовательский выбор автоподключения. Служебный restart не считается новым
  пользовательским Connect или Disconnect.
- Потеря владельца D-Bus не считается пользовательским OFF. Контроллер повторно
  находит NetworkManager и свой профиль, восстанавливает согласование с движком;
  старые sender/path/session не принимаются. При намерении OFF позднего Up нет.
- Падение/остановка демона снимает системный Connected. Состояние одного
  пользовательского процесса GUI не служит источником истины.

## Вход и настройки

При действующей регистрации Connect не требует новой вкладки/входа. Если вход
истёк или это первое подключение, используется браузер и штатный auth-dialog
адаптированного плагина. Одна попытка открывает одну вкладку; отмена завершает
ожидание, старый callback/код не применяется к новой попытке.

И GUI, и системная панель продолжают единую попытку входа, без смены default-профиля
и создания шестого устройства. `auth=sso` должен поддерживать неинтерактивное
восстановление уже зарегистрированного устройства; upstream-ограничение,
отклоняющее всякий неинтерактивный SSO, нельзя переносить без адаптации.

Public/internal параметры совпадают с каналом клиента. По умолчанию используются
адреса Aheadscale, а не NetBird; адреса скрыты от обычного пользователя. Серверная
конфигурация с CDN остаётся следующим этапом по прежнему решению владельца.
Ключи и токены остаются в хранилище демона; постоянный профиль не дублирует
WireGuard private key и не содержит пользовательский пароль.

## Установка, обновление и удаление

Desktop DEB/RPM amd64/arm64 включает службу плагина, метаданные NetworkManager,
auth-dialog и необходимые UI-компоненты. Постоянный профиль Aheadscale создаётся
автоматически, его UUID стабилен при upgrade/reinstall. Не требуется редактор
с ручными полями сервера; наличие и активация профиля проверяются в GNOME и KDE.

Установка учитывает уже работающую `.26`: выполняет контролируемый переход,
сохраняет ключи, ID/IP/FQDN, preferences и пользовательский autostart. Не удаляет
произвольный профиль только из-за совпадающего отображаемого имени. Созданные
ресурсы отмечаются квитанцией: UUID, пути, принадлежность/контрольные суммы.

Удаление очищает только собственные профиль, службу, D-Bus policy и сетевые
правила; регистрация сохраняется согласно существующему контракту. CLI-вариант
для серверов не получает обязательных GTK/NetworkManager-зависимостей.
Desktop ↔ CLI и ON/OFF остаются обязательными случаями C13.

Управление плагином разрешено доверенному NetworkManager и контролируемым
системным службам; unprivileged-процесс не может подменить адрес daemon, запустить
произвольную команду, прочитать ключи или выдать себя за системный контроллер.
SELinux/firewalld/Polkit не отключаются; необходимые политики поставляются пакетом.

## Порядок проверки и критерии приёмки

1. **Проверка совместимости до интеграции в установщики.** Плагин тега с
   адаптацией socket/service/URL, режим DisableProfiles, stock GNOME/KDE,
   единственный владелец IP/DNS. Отдельно охарактеризовать реакцию upstream на
   restart NetworkManager, неинтерактивное восстановление и SSO в обоих desktop.
   Несовместимость означает исправление/уточнение дизайна, а не отключение проверок.
2. **Автоматические регрессии.** Реальный изолированный D-Bus/RPC lifecycle,
   смена владельца/пути, старый sender, чужой профиль, задержанный Up после Cancel,
   отказ входа, остановка контроллера/демона и недоступный NM. Тест RG43 должен
   сначала воспроизвести ошибку. Старый режим без native-компонента тоже проверяется
   после смены владельца NM; повторная подписка не остаётся сломанной.
3. **Живые Ubuntu/Fedora ARM64.** Настоящие системные Connect/Disconnect и Cancel
   при наблюдаемом Connecting; те же действия из GUI и CLI. После Cancel —
   Disconnected и отсутствие адреса/трафика без позднего подключения, включая
   завершение старой попытки; затем новая попытка успешно соединяется.
4. **Восстановление.** Restart NetworkManager/демона/плагина из ON и OFF, затем
   настоящий системный Disconnect; исходная регистрация и управление сохранены.
   Reboot до графического входа, UI autostart ON/OFF и повторный вход пользователя.
5. **Трафик и пакеты.** T01 IPv4/FQDN/короткое имя в обе стороны; удаление адресов,
   DNS/маршрутов при OFF; сохранность обычного интернета. Desktop/CLI DEB/RPM
   x64/ARM64, чистая установка, upgrade `.26`, remove/reinstall и смена варианта.
   Результаты привязаны к манифестам и реально работающим бинарникам.

Приёмка требует настоящего VPN-трафика и штатных системных панелей; появление
строки VPN, один RPC Connected или один положительный health-check недостаточны.
Скорость VPN/загрузки ОС по-прежнему не исследуется этим этапом.

## Не входит в этот этап

Серверные квоты, регистрация email, горизонтальное масштабирование, лендинг,
новые пользовательские сети/профили, Exit Node и смена upstream NetBird клиента.
Windows/macOS не пересобираются без собственной причины. Публичные подписи,
CDN-обновления и весь стабильный выпуск этим компонентом не объявляются готовыми.

## Принятые технические решения и проверка документа

Владелец выбрал полное системное управление в первом выпуске и адаптацию `v0.1.12`.
Постоянный профиль, единый контроллер намерений, отдельный native-режим,
квитанция ресурсов и DNS-адаптация — предложения исполнителя для утверждения.
Проверка дизайна выполнена одним агентом по требованию владельца; независимого
ревью не было. До согласования документа продуктовый код и зависимости не меняются.

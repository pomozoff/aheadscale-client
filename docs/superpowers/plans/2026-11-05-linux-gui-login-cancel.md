# Linux GUI: один вход и корректная отмена

Согласовано владельцем в AHEAD-14 05.11.2026. Исполнитель /root, ветка `codex/linux-auth-stop`.

## Границы

Повторный Login присоединяется к текущей native-активации Linux. Отмена ожидающего запроса не отменяет владельца; явный Disconnect отменяет всю активацию. Поведение Windows по умолчанию не меняется. GUI слушает Cancel до ожидания Login, убирает обработчики после завершения и не показывает техническую ошибку штатной отмены.

## Шаги и проверки

1. В Actions воспроизвести замену активации и ошибку раннего Cancel. Проверки выполняют настоящий SessionController и модуль connection.ts; только Wails IPC и внешние диалоги заменены тестовыми границами. Зависимости не добавлять.
2. Добавить явное присоединение к SessionController и использовать только в Linux. Зарегистрировать Cancel до Login, сохранить обычный SSO и реальные ошибки.
3. Получить GREEN выбранного набора networkmanager с race и регрессиями.
4. Собрать следующий Linux x64 кандидат с существующим KDE producer. На чистой Kubuntu проверить одну активацию на GUI Connect, ранний Cancel без ошибки, закрытие callback и ручной повторный Connect.
5. Сохранить evidence и интегрировать проверенные изменения. AHEAD-14 не закрывать до выполнения всех критериев; успешная сборка не означает допуск платформы.

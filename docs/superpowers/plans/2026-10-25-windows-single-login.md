# Один браузерный вход в Windows

> Для исполнителя: использовать `superpowers:executing-plans`, последовательно одним агентом.

**Цель:** одно нажатие Connect открывает одну актуальную вкладку; прежняя попытка системного VPN не отменяет новый вход.

**Архитектура:** UI владеет браузерным входом. Посредник запускает штатный CLI `up --no-browser`; перед GUI Login общий контроллер завершает прежний Connect и его cleanup. Серверная проверка пользователя, полномочия и PKCE сохраняются.

**Технологии:** существующие Go RPC, SessionController, C++ broker; без новых зависимостей и RPC.

**Основание:** журнал ВМ показывает две попытки PKCE 05:42:22/26, отмену первого ожидания и успешный SSO второго при ошибке команды системного VPN. Начальный CLI up запускает браузер; frontend реагирует на NeedsLogin своим Login и WaitSSO.

## Ограничения и риски

- Не отключать PKCE/state, проверку владельца, подписи и защиту Windows.
- Обычные Linux/macOS/CLI сохраняют прежний Login без принудительного Down.
- Отмена и ошибка cleanup не должны пропускать новый Login.
- Поздний startup не должен отменить уже начавшийся вход.
- Живой вход проверяет пользователь; пароль и OAuth-коды не сохранять в отчёте.

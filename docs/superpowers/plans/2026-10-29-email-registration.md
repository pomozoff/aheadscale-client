# Реализация подтверждения email Aheadscale

> Для исполнителя: использовать superpowers:executing-plans, выполнять задачи последовательно одним агентом. Реализация уже разрешена владельцем; повторное согласование порядка работы не требуется.

**Цель:** аккаунт и сеть появляются только после одноразовой ссылки и задания пароля.
**Архитектура:** ожидающие заявки в существующей БД Management, стандартный SMTP,
сохраняемый идентификатор будущего пользователя для идемпотентного завершения в Dex.
**Стек:** существующие Go, GORM, Dex, HTML/JavaScript и Playwright; без новых зависимостей.
**Схема:** [утверждённый проект](../specs/2026-10-29-email-registration-design.md).

## Общие ограничения

- Ссылка 30 минут, пауза повторной отправки 1 минута; значения настраиваются.
- Не создавать личность/сеть до доказательства владения адресом.
- Не изменять пароль существующего аккаунта или связывать социальные личности по email.
- Секреты только в защищённой серверной конфигурации; Actions используют синтетическую почту.
- Сохранять исходную OAuth-попытку только для исходного браузера; новые произвольные redirect URL запрещены.
- Старые аккаунты сохраняют доступ, но не помечаются проверенными задним числом.
- Runtime-тесты выполнять в выбранных Actions; не собирать установщики всех ОС.

## Особое внимание при проверке

1. Запрос письма на чужой адрес не даёт инициатору сессию после перехода владельца по ссылке.
2. Сканер ссылки не расходует токен и не создаёт аккаунт.
3. Сбой после записи в Dex допускает безопасный повтор с тем же зарезервированным ID.
4. Перезапуск не обнуляет ограничения частоты и не возвращает использованную ссылку.
5. Отказ SMTP/TLS или неверная конфигурация закрывает регистрацию, не отключая обычный вход.

# Автоматизация проверок Aheadscale через GitHub Actions

> **Для исполнителя:** использовать `superpowers:executing-plans`, работать одним агентом. Шаги отмечать `- [ ]`; повторного согласования утверждённой схемы не требуется.

**Цель:** заменить ручной запуск тестов агентом выбранным Actions-прогоном и единым отчётом.
**Архитектура:** публичные hosted-наборы без секретов; приватный coordinator и одноразовые гости для GUI/VPN/reboot; отдельный сервер и аккаунты для полного auth/device E2E.
**Инструменты:** существующие GitHub Actions, Python standard library, Go 1.26.7, существующие Go/Python/CTest проверки, штатные интерфейсы доступности ОС; Playwright из существующего dashboard-проекта для web E2E.
**Спецификация:** `docs/superpowers/specs/2026-10-29-actions-test-automation-design.md`.

## Приоритет после уточнения владельца 29 октября

Текущий порядок: завершение функций первой версии с целевыми проверками →
короткий smoke затронутого блока → стабилизация → полный предрелизный регресс.
Готовые Actions использовать выборочно. Незаконченные этапы автоматизации ниже
сохранены как дальнейшие задачи; они не блокируют разработку продукта и не
выполняются раньше неё без необходимости для конкретной функции.
Критерии публичного выпуска и существующие результаты не ослабляются.
Подробности: [порядок проверок](../../../testing/aheadscale/README.md#порядок-разработки-и-проверки).

## Общие ограничения

- Сначала быстрые hosted-проверки, затем lab; никаких локальных длинных тестов вместо Actions.
- Не публиковать production-секреты, GPG-ключи и доступ к личной сети; runner только в приватном репозитории и отдельной управляющей ВМ.
- Не менять основную ветку публичного клиента, не выпускать публичные установщики, не чинить RG39 и не исследовать отложенные задержки. Bootstrap приватного тестового репозитория разрешён владельцем и слит в main через PR #1.
- SHA исходников и установщиков обязательны; одинаковая ревизия Desktop/CLI; очистка при PASS/FAIL/Cancel.
- Результаты привязаны к сценарию/ОС/архитектуре. MANUAL/NOT_RUN/BLOCKED не превращаются в PASS.

## Наиболее важные ошибки

1. Неизвестный suite/case или устаревший артефакт случайно засчитан как успешный.
2. Программа теста падает/зависает, а оболочка/агрегатор скрывает её exit code.
3. Ошибка очистки/прерывание теряет отчёт либо оставляет fixture.
4. Unit-тест подменяет реальные GUI/SSO/лимит/изоляцию аккаунтов.
5. Несогласованные ревизии или небезопасный публичный runner получают доступ к стенду.

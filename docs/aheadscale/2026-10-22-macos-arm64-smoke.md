## Системный список VPN macOS — выявлено 23 октября

В текущем клиенте `client/iface/device/device_darwin.go` создаёт интерфейс непосредственно через `tun.CreateTUN`. Упаковка `packaging/aheadscale/package.py` включает службу и GUI с ad-hoc подписью; компонент macOS Network Extension и его профиль конфигурации отсутствуют. Присутствующий в репозитории код iOS с `NEPacketTunnelProvider` не включён в сборку Darwin.

Это объясняет отсутствие Aheadscale в системном списке VPN. Работу туннеля, маршрутов и DNS нужно проверять отдельно; по одному статусу Connected она не подтверждена.

Для интеграции потребуется компонент `NEPacketTunnelProvider` с настройкой через `NETunnelProviderManager` и согласованным управлением подключением. Для распространения вне Mac App Store Apple предусматривает system extension с подписью Developer ID и provisioning profile с Network Extensions entitlement:

- [Apple: развёртывание Network Extension, TN3134](https://developer.apple.com/documentation/technotes/tn3134-network-extension-provider-deployment).
- [Apple: NETunnelProviderManager](https://developer.apple.com/documentation/networkextension/netunnelprovidermanager).
- [Apple: Network Extensions entitlement](https://developer.apple.com/documentation/bundleresources/entitlements/com.apple.developer.networking.networkextension).

23 октября владелец подтвердил, что Apple Developer Program ещё не оформлена. Реализация и проверка системной интеграции остаются отдельным этапом. Критерии готовности: Aheadscale виден в VPN; подключение и отключение работают из приложения и системных настроек; статусы совпадают; реальный трафик и приватные имена работают; регистрация сохраняется после перезагрузки.

SSH-проброс обновлён владельцем на новый LAN-адрес ВМ; доступ восстановлен. Повторная проверка показала LoginFailed, пустой VPN-адрес и ошибку Management «peer login has expired». После нажатия Connect новый браузерный вход не начинался из-за тайм-аута подключения к серверу. Потребуется повторный вход после устранения сетевой причины ниже.

## Восстановление публичного HTTPS — 23 октября

Интернет в macOS работал (внешний HTTPS возвращал 200), но TCP 80/443 сервера Aheadscale завершался тайм-аутом. A-запись совпадала с действующим WAN IP. Локальный HTTPS сервера возвращал 200. Захват заголовков TCP на сервере показал входящие SYN от сети ВМ и исходящие ответы: отказ находился на обратном маршруте.

На недавно перезапущенном роутере отсутствовали исключения `platform-ingress-replies` и `aheadscale-stun-replies` как в активной цепочке Podkop, так и в `/usr/bin/podkop`. Политика направления всего LAN-трафика в прокси срабатывала раньше штатного `ct status dnat return`. Причина, по которой прежняя правка генератора была утрачена, отдельно не установлена.

Восстановлены прежние правила из `platform/router/podkop-ingress-replies.patch` и `platform/router/aheadscale-stun.sh`: исключения для ответов уже опубликованных HTTP(S) и STUN. Сначала восстановлено активное правило HTTP(S), после чего HTTPS из macOS сразу вернул 200. Затем проверены синтаксис генератора (`sh -n`) и обоих правил (`nft -c`), сохранена резервная копия генератора, выполнена его атомарная замена и восстановлено активное исключение STUN. Сервисы для этого не перезапускались.

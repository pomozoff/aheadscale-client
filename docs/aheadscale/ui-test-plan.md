# Проверки графического клиента Aheadscale

Общие условия, матрица, сеть и шаблон отчёта — в [едином плане](smoke-test-plan.md). Прогон выполняется **на каждой выбранной ОС и архитектуре**, обычным пользователем. Windows ARM64 не подтверждает x64; дополнительный DE не подтверждает чистый дистрибутив.

## Готовность рабочего стола перед UI-проверкой

На Windows-ВМ перед открытием Settings или Aheadscale подтвердить активный разблокированный сеанс и включённый виртуальный экран. SSH и наличие окна сами по себе этого не доказывают. Для автоматического прогона разово пробудить дисплей из того же интерактивного сеанса через `SetThreadExecutionState(ES_SYSTEM_REQUIRED | ES_DISPLAY_REQUIRED)` и зафиксировать `GUID_CONSOLE_DISPLAY_STATE=1`. Вызов без `ES_CONTINUOUS` сбрасывает таймер, не меняя постоянный план питания.

Пока экран выключен либо сеанс недоступен, UI-результат — **NOT_COMPLETED: окружение**, а системный API проверяется отдельно. `Responding=false`, приостановленные потоки и отсутствие строки при Off не являются достаточным доказательством дефекта VPN. Не перезапускать Settings и не удалять профиль до проверки этих условий. Если страница не готова при включённом экране — сохранить точное окно, PID, состояние дисплея и профиль, затем диагностировать как отдельный отказ. [Воспроизведение RG29](smoke-results/2026-10-26-windows11-arm64-settings.md).

При самопроизвольной перезагрузке прервать приёмку текущего действия: сохранить bugcheck/дамп и определить модуль, прежде чем переустанавливать клиент. Совпадение по времени не доказывает дефект VPN; незавершённая отмена не становится PASS. [Разбор сбоя графического драйвера ARM64](smoke-results/2026-10-27-windows11-arm64-final.md).

При сравнении конфигов отличать неизменность установки/удаления от осознанного изменения настроек GUI. После GUI roundtrip необязательные null могут стать явными false/0: сначала установить точные отличия и эффективные значения, сохранить ключ/профиль; не перезаписывать рабочий конфиг старым снимком ради совпадения SHA256. [Подтверждённый случай ARM64](smoke-results/2026-10-27-windows11-arm64-final.md).

Пробуждение относится к подготовке UI-стенда; его время не включать в замер подключения VPN на прогретой ОС. Проверку сна/пробуждения проводить отдельно, с явным изменением состояния дисплея. Продукт не должен постоянно удерживать экран включённым ради VPN.

Для автоматизации macOS отдельно подтвердить Accessibility, а для снимков — Screen Recording, реальное окно Aheadscale и готовое содержимое WebView. Разрешения выдаёт пользователь в штатных настройках; отказ запроса по SSH не обходить изменением TCC. Снимать только проверенные окно/значок приложения. После обновления сверять фактически запущенный GUI: версия CLI на диске не доказывает загрузку новой UI-сборки. См. [RG31/RG32 и проверку `.20`](smoke-results/2026-10-26-macos-arm64-menubar.md).

## Особенности установки и системной интеграции

- **Linux:** desktop DEB и нативный RPM; systemd, реальные GTK4/WebKit6 из штатных репозиториев, автозапуск в сеансе. Проверить GNOME/Wayland, Plasma/Wayland и Xfce/X11; версию NetworkManager и фактический DNS записать. Не исправлять результат ручной подменой библиотек или WireGuard-порта.
  Для S04/R03 проверить не только `ip link`, но и `nmcli -t -f NAME,TYPE,STATE connection show --active`: штатный интерфейс должен иметь активное подключение `Aheadscale:wireguard:activated`. Сверить ту же строку в системном меню. После Disconnect строка неактивна или отсутствует, ложного уведомления нет; после Connect и restart службы она возвращается. Проверить приватные FQDN/короткие имена и T01, сохранение фактического UDP-порта и адресов после настройки DNS. Отсутствие NetworkManager на headless-сервере — отдельный допустимый вариант, а не PASS системной панели.
  Для автоматизации открытия Linux GUI использовать штатный повторный запуск `/usr/bin/aheadscale-ui` и проверить, что основной PID сохранился. Не посылать `SIGUSR1`: JavaScriptCore использует его для остановки/возобновления собственных потоков. Отдельно повторить открытие приложения и отмену/повтор входа; сбой из-за внесённого тестовой оснасткой сигнала учитывать отдельно от обычного запуска.


- **Windows:** чистая установка с/без WebView2; служба Automatic, ARM64/x64 бинарники и драйверы; правильная иконка EXE, ярлыков и панели задач. Native VPN требует согласованных службы, GUI, плагина и посредника. Проверить правило входящего UDP 51830 только для проверенной службы во всех согласованных профилях и его удаление по квитанции; Defender и UAC не отключать.
- **macOS:** PKG, `/Applications`, launchd, приложение от обычного пользователя; системные запросы защиты, подпись и карантин записать. Текущий ad-hoc preview не заменяет Developer ID/нотаризацию. Проверить `/Applications/Uninstall Aheadscale.command`; реальный системный VPN требует отдельного Network Extension и подписания.

Проверка подлинной подписи скачанного установщика и всех компонентов обязательна перед публичным выпуском. Тестовое добавление доверия сертификату и ручное копирование компонента не считаются пользовательской установкой за один шаг.

## Время и диагностический прогон

Следовать [P01–P06](connection-performance-test-plan.md): раздельно обычное подключение, первый запуск UI, вход в сеанс, reboot и SSO. Фиксировать фактическое действие пользователя и завершение cleanup предыдущей попытки; при проверке UI не запускать второй `up` из CLI. Автоматизация переключателя должна вызывать то же действие UI, а её накладные расходы и права наблюдателя записываются. Диагностический исходящий HTTP не заменяет весь T01.

## Приёмка Linux-пакетов `.26`, 28 октября

[Linux-пакеты `.26`](smoke-results/2026-10-28-linux26-packages.md): public Desktop Fedora x64/ARM64 и Ubuntu ARM64, CLI-only Ubuntu Server 24 x64 обновлены с сохранением конфигураций; действующие GUI сверены с установленным payload. Реальный системный Disconnect на трёх Desktop согласован с GUI/CLI и удалением интерфейса; на ARM64 выдержан OFF 12 секунд и выполнен GUI Connect без SSO. Restart службы четырёх узлов и 72 HTTP/DNS приняты. На CLI x64 проверены статусы/справки и три положительных health-check; переходный Connecting не трактовался как готовность трафика. Это частичные R05/C01/C02/C05/C07/C09/C10/C13, без reboot/lifecycle новых пакетов и полного UI/CLI. Предыдущие PASS `.24/.24.1` не переобозначаются результатами `.26`.

[Linux `.26`: lifecycle](smoke-results/2026-10-28-linux26-lifecycle.md): Desktop Ubuntu/Fedora ARM64: автозапуск GUI после загрузки наблюдался; Desktop ↔ CLI, сохранение OFF при удалении/переустановке и возвращение прежнего ON приняты. Работающие GUI совпали с установленными бинарниками, NM активен, 42 HTTP/DNS с headless CLI. Это не полный UI/R05: отдельный GUI autostart OFF и новый вход после последней reinstall не проверялись; самостоятельный graceful reboot Ubuntu Desktop не доказан.

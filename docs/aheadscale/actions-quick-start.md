# Сборки и выбранные проверки в GitHub Actions

Все перечисленные jobs выполняются на GitHub-hosted runners. Рабочий сервер на Mac mini остаётся на месте; workflow не развёртывает собранные пакеты.

## Обычная работа

- Push в `main`, `aheadscale` или `codex/**` выполняет только короткий контракт выбора тестов и отчётов. Он не собирает установщики.
- PR в `main` или `aheadscale` дополнительно выбирает продуктовые тесты по изменённым файлам: клиент, упаковка, регистрация. Общий или неизвестный код включает все короткие наборы; документация не запускает продуктовые jobs.
- Исправление проверяется нужным набором. Полный прогон всех пакетов и приёмка ОС выполняются для релизного кандидата, а не при каждом изменении.

## Ручной запуск

В Actions → **Aheadscale desktop previews** → **Run workflow** выбрать ветку, `suite` и, для установщика, `targets`.

| `suite` | Результат |
| --- | --- |
| `ci-contract` | Короткие проверки запуска и выбора наборов; значение по умолчанию |
| `unit` | Клиентские unit-тесты, DNS/служба, политика обновлений |
| `packaging` | Регрессии упаковки и синтаксис сценариев без пересборки GUI |
| `auth` | Подтверждение email, восстановление регистрации, изоляция аккаунтов и квоты |
| `windows` | Проверка идентификатора адаптера на Windows |
| `checks` | Все перечисленные продуктовые наборы без установщиков |
| `build` | Установщики выбранных платформ и применимые предварительные проверки |
| `server` | Серверный бинарный файл и готовый контейнер Linux x64, проверка запуска без сети |
| `full` | Все продуктовые наборы и установщики выбранных платформ; не заменяет приёмку на ВМ |

`targets`: одна из `linux-amd64`, `linux-arm64`, `windows-amd64`, `windows-arm64`, `macos-arm64`; `all` — все пять. Старые группы `current` и `arm64` сохранены. По умолчанию выбрана только `linux-amd64`. macOS Intel не добавлена.

Примеры для агента:

```bash
gh workflow run aheadscale-client.yml --repo pomozoff/aheadscale-client --ref <ветка> -f suite=auth
gh workflow run aheadscale-client.yml --repo pomozoff/aheadscale-client --ref <ветка> -f suite=build -f targets=linux-arm64
gh workflow run aheadscale-client.yml --repo pomozoff/aheadscale-client --ref <ветка> -f suite=server
```

Отдельный workflow **Aheadscale Windows VPN prototype** запускается вручную для выбранной архитектуры; его сборка также не начинается при push. Он включает native VPN-компонент и объединённый установщик, которых нет в обычной сборке `build`.

## Как читать результат

Сначала смотреть Summary. Наборы `ci-contract`, `unit`, `packaging`, `auth` сохраняют JSON, JUnit, краткую сводку и логи в `test-results-*`. Агент скачивает подробный лог только при ошибке. Повторные запуски одной комбинации ветки/набора/платформы отменяют устаревший запуск.

Установщики содержат манифест исходного коммита и SHA256. Серверный артефакт `aheadscale-server-linux-amd64` содержит бинарный файл, архив образа для `docker load`, идентификатор образа, сведения сборки, исходный коммит и `SHA256SUMS`. Базовый runtime закреплён digest; локального базового образа для сборки не требуется.

Артефакты основного workflow хранятся 7 дней. Они предназначены для испытаний, не заменяют CDN и подписанный релиз. Привилегированные self-hosted runners, рабочие аккаунты, production SMTP и БД здесь не используются.

Системные панели VPN, установка/обновление/удаление, перезагрузка, разрешения macOS и реальный обмен двух устройств остаются отдельной приёмкой на изолированных ОС. Успешные unit-тесты или сборка не переводят эти случаи из NOT_RUN в PASS.

## Объём первой версии

Целевой продукт: [личная сеть и SOHO под одним аккаунтом владельца](first-release-features.md), до пяти зарегистрированных устройств, автоматическое подключение к `aheadscale.ru`, каталог устройств, приватные имена, SSH/RDP/SFTP/SMB и внутренние сайты поверх частной сети. Обычный интернет остаётся через исходное подключение.

Приглашения сотрудников, роли, несколько одновременно активных сетей, exit node, публикация сервисов и управление офисными подсетями пока не входят в обещания первой версии. Профили в текущих установщиках отключены. Унаследованные CLI-команды проверяются отдельно: наличие команды не означает готовность соответствующего серверного сервиса.

## Как пользоваться

1. Выбрать строку матрицы, точный установщик и второй узел; заполнить паспорт прогона ниже.
2. Для настольного пакета последовательно выполнить [план UI](ui-test-plan.md); для CLI-пакета — [полный план CLI](cli-test-plan.md). Наличие CLI внутри desktop-пакета не заменяет установку отдельного CLI-варианта.
3. Выполнить общие сетевые проверки T01–T07 ниже и применимые [регрессии RG01–RG32](regression-test-plan.md).
4. Записать каждую проверку отдельно, приложить доказательства и ограничения. Исторические результаты искать в [индексе отчётов](smoke-results/README.md).
5. Перед публичным выпуском пройти [критерии приёмки](acceptance.md). Базовый smoke и готовность публичного сервиса — разные результаты.

## Подготовка стенда

- Чистый снимок A до установки и регистрации; узел B того же аккаунта с другим именем. Для изоляции нужен независимый аккаунт C. Не клонировать зарегистрированную ВМ вместе с ключами.
- Записать сборку ОС, архитектуру, рабочий стол/Wayland/X11, браузер, сетевой менеджер и владельца DNS. Сохранить доступ к консоли при остановке VPN.
- Скачать нужный preview, записать SHA256, источник/CI/commit. `public` использует `aheadscale.ru`; внутренний канал не подменять им на зарегистрированном устройстве. CDN-конфигурация — следующий этап, сейчас параметры зафиксированы в сборке.
- Проверить свободные места аккаунта: выключенные устройства тоже входят в лимит пяти. Откат снимка и удаление пакета не удаляют устройство на сервере.
- Проверить интернет, системный DNS, время, HTTPS `aheadscale.ru` и доступность серверной авторизации **из гостевой сети**. Локальный ответ сервера на Mac mini не доказывает доступность из интернета.
- Перед UI-проверкой Windows-ВМ подтвердить активный разблокированный сеанс и включённый виртуальный экран; при автоматизации разово пробудить его и записать состояние дисплея. Иначе результат UI — NOT_COMPLETED окружения, а не FAIL VPN. Порядок — в [UI-плане](ui-test-plan.md).
- SELinux, firewalld, Defender, UAC и защита macOS остаются включены. Если нужны узкие временные правила для тестового сервиса, записать и удалить их после прогона.
- Подготовить HTTP-сервис на VPN-адресе узла B, порт 8765, уникальный маркер `aheadscale-smoke-peer-b`; на A — другой маркер. Проверить сервис локально, прежде чем оценивать VPN. Не публиковать его через LAN/интернет.

## Общие сетевые сценарии

| ID | Последовательность | Критерий |
| --- | --- | --- |
| T01 | На A сравнить каталог с B; разрешить полное и короткое имя B системным резолвером; выполнить HTTP к VPN IP, FQDN и короткому имени; повторить B → A | Шесть HTTP 200, точные разные маркеры, `remote_ip` равен VPN-адресу ожидаемого узла; без hosts, ручного DNS и LAN-адресов |
| T02 | Отключить A; проверить отказ T01 к A и обычные DNS/HTTPS; снова подключить и повторить T01 | Реальный трафик следует состоянию, нет утечки обычного DNS и самоподключения после намеренного Disconnect |
| T03 | Раздельные случаи T03-SVC (служба) и T03-OS (вся ОС); после входа desktop проверить автоматический запуск UI, T01 и прежнюю идентичность; P04 | Отдельный вердикт на каждый случай. Не нужен SSO, то же устройство/адрес/имя; шесть HTTP с правильным remote_ip. Для поддерживаемого CLI/backend сеть восстанавливается без графического сеанса |
| T04 | На минуту отключить сеть A, вернуть; отдельно сменить NAT/сеть и повторить T01 | Восстановление без ручного исправления интерфейса/порта/DNS и без новой регистрации |
| T05 | Поместить A и B за разные интернет-подключения/NAT; подтвердить Direct средствами диагностики | T01 проходит; записан фактический маршрут и время восстановления |
| T06 | На контролируемом стенде сделать Direct недоступным, сохранив доступ к серверу/Relay; подтвердить Relayed и повторить T01; вернуть Direct | Работает настоящий Relay и переход обратно. Если стенда нет — NOT_RUN, успешный Direct не заменяет этот случай |
| T07 | Открыть по приватному имени SSH/SFTP на Linux/macOS и RDP на Windows; скопировать файл и сравнить SHA256; отдельно SMB, если заявлен в выпуске | Полезная сессия и целый файл, без публичного проброса прикладного порта. Сначала подтвердить, что целевой сервис вообще настроен |

Бюджеты DNS/HTTP: повторный Connect с действующей регистрацией — до 30 секунд от действия; восстановление сети — до 60 секунд от подтверждённой готовности обычной сети. Скорость Connect измерять на прогретых ОС и готовом UI. Перезагрузка/автозапуск — отдельные функциональные проверки, без замера загрузки ОС/UI в текущей задаче. Методика, SSO и границы точек отсчёта — в [плане измерений P01–P06](connection-performance-test-plan.md). Превышение — FAIL текущего smoke-бюджета. HTTP клиента выполняется без HTTP-прокси. Ping и Connected сами по себе недостаточны.

Системные резолверы: Linux `getent ahostsv4`, Windows `[System.Net.Dns]::GetHostAddresses()`, macOS `dscacheutil -q host -a name`. Имена/суффикс брать из каталога, не подставлять предполагаемый домен. Внешний DNS тестировать отдельно от приватного.

Пример сервиса на Linux/macOS (подставить VPN IP этого узла):

```bash
probe_dir="$(mktemp -d -t aheadscale-smoke.XXXXXX)"
printf '%s\n' 'aheadscale-smoke-peer-b' > "$probe_dir/probe.txt"
python3 -m http.server 8765 --bind VPN_IP_ЭТОГО_УЗЛА --directory "$probe_dir"
```

Каждый адрес проверять отдельным запросом, например `curl --noproxy '*' --fail --connect-timeout 5 --max-time 10 --write-out '\nHTTP=%{http_code} remote_ip=%{remote_ip}\n' http://VPN_IP_УЗЛА_B:8765/probe.txt`. В Windows использовать `curl.exe`, чтобы не попасть в псевдоним PowerShell. Нулевой код цикла не заменяет проверку всех шести ответов.

## Проверки сервера на выпуск

| ID из прежнего плана | Проверка | Условие успеха |
| --- | --- | --- |
| R06 | Аккаунт C, включая такой же email-домен; каталог, DNS, API и TCP/UDP к сети A; неверный/истёкший токен | Чужая сеть недоступна на сервере и в трафике. Одновременно тот же сервис доступен законному B; отказ не объясняется выключенным сервисом |
| R07 | Пять устройств, включая offline; шестое; удаление одного; две одновременные регистрации на последнее место | Шестое отвергнуто сервером, место освобождается после удаления, при гонке проходит ровно одна регистрация |
| R08 | Первый и повторный вход VK ID и Яндекс ID в чистом профиле; отказ/отмена провайдера | Возврат в правильный аккаунт и продолжение подключения. Для Mail/ОК используется согласованный вариант VK ID |
| SR01 | Новая регистрация email; без перехода по письму; ссылка один раз, второй раз, после срока; неверный адрес; повторная отправка | Без подтверждения нет активного аккаунта/подключения; повторная и просроченная ссылка безопасно отклоняются. **Сейчас требуется доработка сервера**, прежняя регистрация без письма не PASS |
| SR02 | Ошибка доставки письма/временная недоступность IdP/management; восстановление | Понятная ошибка и повтор без дублирования аккаунтов/устройств; существующие пользователи не объединяются по email-домену |

Серверные R06–R08/SR01–SR02 проверять на серверный выпуск, затем выборочно повторять браузерный возврат на каждой ОС. Нельзя исключить подтверждение email из приёмки только потому, что клиент уже работает.

## Результаты и паспорт прогона

- **PASS:** действие выполнено и ожидаемый результат подтверждён для точной сборки.
- **FAIL:** ожидание нарушено; сохранить первый отказ, обходной путь и результат нового прогона раздельно.
- **BLOCKED:** не хватает пакета, доступа, подписи, второго узла либо серверной функции.
- **NOT_RUN:** не выполнялось. **N/A:** неприменимо по явно зафиксированной границе продукта, с причиной.
- **Частично:** сводное описание нескольких разных результатов; не заменяет статус отдельного случая и не считается PASS.

Для настольной платформы smoke PASS требует S01–S08 и T01/T02; полный кандидат — все применимые UI/CLI, T01–T07, регрессии и критерии приёмки. Для macOS текущее отсутствие системного VPN записывать как известный пробел/FAIL требования интеграции, отдельно от проверки базового туннеля. Для Windows опытный комплект не выдавать за итоговый установщик.

Полные журналы, email, приватные ключи, OAuth code/state и пароли не публиковать. Операторские временные файлы не являются долговременным доказательством: в отчёте сохранить команды, версии, хеши и обезличенные результаты. Исторический отчёт не переписывать после нового исправления — добавить новый результат и ссылку.

Для проверки лимита сначала сохранить количество серверных записей, включая offline; шестой узел должен завершить вход в тот же аккаунт, получить отказ без VPN-IP и не появиться в каталоге. Записать точный пользовательский текст, отдельно от корректности PermissionDenied. Device Authorized в браузере не заменяет результат admission.

# AHEAD-66: диагностика без остановки VPN

Согласование: владелец подтвердил безопасный снимок под блокировкой и построение архива вне общей блокировки. Тайм-ауты не увеличивать. Один агент.

1. RED: реальный генератор ждёт контролируемого чтения UI-журнала; Status и Down должны завершаться до освобождения чтения. Запуск только в Actions.
2. GREEN: отделить снимок данных от генерации; скопировать изменяемую конфигурацию/буферы, передать владение capture текущему архиву. Отдельно проверить, что последующая очистка не затрагивает новый capture/CPU-буфер. Сохранить проверки прав открытия/выдачи архива.
3. Проверки: регрессия и race затронутых пакетов в Actions; сборка Linux, native Status/HTTP во время архива, Disconnect. До native-проверки не объявлять дефект исправленным на пользовательском пакете.

## Ход исполнения

- RED42536621694 на a196a98: оба RPC блокируются, ошибок фикстуры нет. Предыдущие42536227229/42536428065 обнаружили неполную конфигурацию тестового сервера; фикстура заменена штатно созданным синтетическим профилем.
- Решение: архивы сериализуются отдельным mutex, который управляющие RPC не используют. Снимок конфигурации копируется; завершённый CPU-буфер и остановленный capture передаются конкретному архиву.
- Решение: архив использует текущие синхронизированные данные recorder, не запускает принудительный сетевой health-check старого движка после Disconnect. Иначе фоновая диагностика могла бы пометить новую сессию состоянием старой.
- Два прохода анализа гонок: (1) все обращения к полям Server при снимке под s.mutex; mutable config скопирован, sync-store Get возвращает собственный protobuf. (2) CPU/capture отделены до unlock; cleanup конкретного capture не обращается к s.bundleCapture; новые capture/CPU не удаляются старым архивом. Отдельный mutex не входит в цепочку Status/Down.
- GREEN и native ещё ожидаются. SDK на Mac mini не устанавливался; gofmt и тесты выполняются в Actions.

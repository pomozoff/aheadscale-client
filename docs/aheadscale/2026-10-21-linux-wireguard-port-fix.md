# Сохранение параметров WireGuard при настройке DNS

Дата: 21 октября 2026. Проверка выполнена одним агентом.

В тестовом клиенте `.7` Fedora 44 ARM64 и Ubuntu 26.04 ARM64 показывали Connected/P2P, но пакеты не проходили. Клиент объявлял UDP 51830, а ядро слушало 35010/51404 на Fedora и 41443 на Ubuntu. Причина — DNS Reapply в NetworkManager повторно применяет также WireGuard-настройки из снимка, который может предшествовать настройке транспорта. Ручное возвращение 51830 на обеих ВМ восстановило трафик и подтвердило причину.

Исправление перед DNS Reapply читает фактический порт и routing mark собственного интерфейса из ядра и сохраняет их в передаваемых настройках. Закрытый ключ и настройки соседей при этом не копируются и не заменяются. Ошибка чтения возвращается вызывающему коду; устаревший снимок не применяется молча. Тест покрывает сохранение порта, routing mark, соседей и DNS, отсутствие копирования закрытого ключа и динамически выбранный порт вместо жёстко заданного 51830.

## Проверено

- Регрессионные тесты сначала падали на порте и routing mark; `go test ./client/internal/dns -run TestNetworkManager -count=1` после исправления завершился с exit 0.
- Собрана только ARM64-служба `.8` с Go 1.26.7. Основа — точный снимок проверенной `.7`, SHA256 `7b2b15bbdf51845aeb3260249136745c5595831445e716292972ed907ea884f0`, с двумя файлами исправления и его теста. Остальные незавершённые изменения в сборку не переносились.
- GUI `.7` взят без пересборки; SHA256 `8542215342004c1bed15657fe48e173eb6406e8ad26ea1cb3a0d2867e4fd729a`. В desktop-установщиках `.8` служба `.8` и GUI `.7` устанавливаются вместе.
- Desktop RPM обновлён на Fedora штатным DNF с отключёнными репозиториями. Ubuntu обновлена локальным DEB через dpkg. Системные пакеты не обновлялись. Первая попытка apt с `--no-download` дала внутреннюю ошибку пути до установки; успешный dpkg-прогон зафиксирован отдельно.
- На обеих ВМ публичный ключ, IP и FQDN сохранились. После обновления, отдельного перезапуска обеих служб и цикла переключателя GUI фактический порт автоматически равен 51830, routing mark — 114176; ручная корректировка портов больше не применялась.
- По три HTTP-запроса в каждую сторону — VPN IPv4, полное и короткое имя — прошли после обновления и после перезапуска: 12 ответов HTTP 200 с точным маркером второй ВМ и ожидаемым remote_ip. Ещё два запроса прошли после переключателя GUI. Статус подтверждает настоящее новое WireGuard-рукопожатие и P2P.
- GNOME Settings показывает Aheadscale в списке VPN. При отключении клиент становится Idle, подключение пропадает из активных в NetworkManager, обычный DNS работает. При повторном включении регистрация и передача данных восстановились.
- Fedora сохранила SELinux Enforcing и активный firewalld; отказов AVC для службы в просмотренном интервале нет. Firewall для диагностики и HTTP не менялся. `rpm -V aheadscale` и `dpkg --verify aheadscale` завершились с exit 0 без расхождений.
- Собственные HTTP-службы и их тестовые файлы удалены после проверки; оба клиента оставлены подключёнными.

Штатный `make lint` для отдельного исправления завершился с exit 0 и `0 issues` в Fedora SDK с CGO=1. SDK-контейнер работал без сети, привилегий и записи в исходники; GTK/WebKit-зависимости установлены только в образ. Исходные прогоны сначала упёрлись в тайм-аут и отсутствие SDK, а CGO=0 оказался неподходящим для SQLite-тестов общего репозитория. Финальный SDK-прогон устранил эти ошибки окружения. Прежние готовые frontend assets `.7` использованы без пересборки GUI.

CLI-варианты упакованы из того же бинарника, но отдельно на ВМ не устанавливались. SHA256 всех пакетов и исходников сохранены в `aheadscale_0.80.0-aheadscale.8_linux_arm64_public_transport-manifest.json`. Это собственные preview: релизной подписи и публикации на CDN нет. Первая сборка из архива потребовала `-buildvcs=false`, поскольку архив не является Git checkout; происхождение записано SHA256 архива и файлов исправления.

Перезагрузка всей ОС, удаление/повторная установка, свежий прогон CLI и другие дистрибутивы этим отчётом не подтверждаются. Проверка перезапуска службы не подменяет проверку загрузки ОС.

Поведение Reapply подтверждено [официальным исходником NetworkManager 1.56.0](https://github.com/NetworkManager/NetworkManager/blob/1.56.0/src/core/devices/nm-device-wireguard.c).

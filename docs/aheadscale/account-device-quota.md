# Квоты устройств в БД

По запросу владельца от 28 октября 2026 года числовой лимит и исключения из
окружения заменены постоянными записями SQLite. Клиенты не пересобираются.

## Где находятся значения

| Таблица | Запись | Назначение |
| --- | --- | --- |
| `account_device_quotas` | `account_id`, `max_devices` | Максимум зарегистрированных устройств конкретного аккаунта |
| `device_quota_policies` | `id='registration'`, `max_devices` | Значение, копируемое новому аккаунту при создании |

`NULL` означает безлимит. `0` запрещает добавление устройств. Отрицательные
значения запрещены ограничением БД. Offline-устройства учитываются. Уменьшение
квоты блокирует новые регистрации, сохраняя существующие устройства и ключи.
Изменение максимума аккаунта действует без рестарта сервера.

Значение бесплатного тарифа задаётся оператором как данные БД, а не константой
Go. Изменение политики новых аккаунтов не меняет уже назначенные квоты.
Сохранение профиля/настроек и повторный запуск миграции не сбрасывают значения.
Удаление аккаунта штатно удаляет его квоту. Таблицы не входят в пользовательский
API Settings: владелец обычного аккаунта не может самостоятельно повысить лимит.

В режиме Aheadscale (`AS_SELF_REGISTRATION=true`) регистрация читает квоту и
считает устройства внутри прежней транзакции и глобальной блокировки одного
сервера. Отсутствующая квота — ошибка конфигурации с отказом добавления, а не
безлимит. Сообщение содержит максимум из БД. `AS_UNLIMITED_DEVICE_ACCOUNT_IDS`
больше не используется; старые значения переменной не предоставляют исключений.
Для нескольких серверных реплик отдельно требуется распределённый admission gate.

## Изменение данных оператором

Примеры SQL после проверки точного ID аккаунта:

```sql
UPDATE account_device_quotas SET max_devices=20 WHERE account_id='ACCOUNT_ID';
UPDATE account_device_quotas SET max_devices=NULL WHERE account_id='ACCOUNT_ID';
UPDATE device_quota_policies SET max_devices=10 WHERE id='registration';
```

Это административные операции с закрытой БД. В интерфейс клиента или публичный
API редактор квот этим изменением не добавляется. В первом развёртывании у
обычных существующих аккаунтов сохраняется значение бесплатного тарифа, у
подтверждённого оператором аккаунта владельца — `NULL`.

## Миграция существующей SQLite

В platform находится `scripts/migrate-aheadscale-device-quotas.py`. Перед
применением сохранить закрытый локальный снимок SQLite и прежний override.
Инструмент требует существующий файл и явное начальное значение политики:

```sh
sudo python3 /home/adnako/Developer/platform/scripts/migrate-aheadscale-device-quotas.py \
  --db /var/lib/docker/volumes/aheadscale-prototype_netbird-data/_data/store.db \
  --default-limit 5 --unlimited-account ACCOUNT_ID
```

В одной транзакции создаются таблицы, инициализируется отсутствующая политика,
заполняются недостающие квоты существующих аккаунтов и задаётся согласованный
безлимит. Существующие политика/индивидуальные значения не перезаписываются,
кроме явно перечисленного `--unlimited-account`. Неизвестный аккаунт или
неверное значение отменяют операцию целиком. Схема проверена совместно с
повторным GORM AutoMigrate; числовые данные не сбрасываются при запуске сервера.

После миграции заменить только образ сервера, убрать прежнее env-исключение и
проверить данные/устройства/доступность. Откат — прежний образ и сохранённый
старый override; новые таблицы не удалять, рабочую SQLite не заменять копией.
Старый сервер не применяет новые квоты БД: такой откат предназначен для аварийного
восстановления. Локальный снимок не является независимым backup.

## Проверки

- Реальный SQLite admission: предел 2, изменение до 4, безлимит, нулевой предел,
  отсутствующая квота и игнорирование старого env; зарегистрированные узлы сохранены.
- Изоляция аккаунтов, конкурентное занятие последнего места и прежняя регистрация.
- Создание из политики БД, сохранение индивидуальной квоты при SaveAccount,
  повторное открытие/AutoMigrate, запрет отрицательных значений и DeleteAccount.
- Совместимость операторской схемы с AutoMigrate сервера.
- Миграция: идемпотентность, индивидуальные изменения, неизвестный ID/откат,
  отсутствие файла, отрицательное значение, нулевой предел и сохранность peers.

Полный management/server testcontainers-прогон ранее остановился на Docker/Redis
окружении; он не выдаётся за PASS. Здесь выполняются целевые SQLite-проверки
фактически используемого хранилища. Исходники и эксплуатационные изменения
сохраняются локально подписанными коммитами в main; серверный код не публикуется.

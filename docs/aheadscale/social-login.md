# Вход через российские сервисы

18 октября 2026 года согласован вход через VK ID, Яндекс ID, Mail.ru и
Одноклассники. Достаточно зарегистрировать **два приложения**: одно в VK ID для
ВКонтакте, Mail.ru и ОК, второе — в Яндекс ID. Менять установщики не требуется.

## Регистрация приложений

1. Создай **веб-приложение** Aheadscale в [кабинете VK ID](https://id.vk.ru/about/business/).
   Укажи сайт `https://aheadscale.ru` и разрешённый адрес возврата (Redirect URI):
   `https://aheadscale.ru/oauth2/callback`. Разреши доступ к email и включи
   предлагаемые провайдером способы входа через ВКонтакте, Mail.ru и ОК.
   Скопируй идентификатор приложения. Для используемого входа с PKCE секретный
   ключ старого приложения ВКонтакте не нужен.
2. Создай приложение **для авторизации пользователей** в
   [Яндекс OAuth](https://oauth.yandex.ru/client/new/id/). Выбери веб-сервисы,
   укажи тот же сайт и Redirect URI. Запроси доступ только к **электронной почте**
   (`login:email`). Скопируй ClientID и Client secret. Доступ к телефону,
   адресу проживания и дате рождения не требуется.
3. Сохрани два идентификатора и секрет Яндекса в закрытой конфигурации сервера.
   Секреты не отправляй в чат и не добавляй в репозиторий. Перед включением входа
   нужно пройти необходимые согласования и проверки провайдеров, затем проверить
   авторизацию настоящего пользователя.

Интерфейсы кабинетов могут меняться. Актуальные указания провайдеров:
[документация VK SDK](https://github.com/VKCOM/vkid-web-sdk),
[регистрация приложения Яндекса](https://yandex.ru/dev/id/doc/ru/register-auth).

## Настройка сервера

Файл `packaging/aheadscale/social-connectors.example.json` содержит **фрагмент
для добавления** в существующую конфигурацию. Сохрани настройки issuer, сессий,
владельца, SQLite и relay. Добавь массив `connectors` в раздел `server.auth`
закрытой конфигурации объединённого сервера.

Передай работающему серверу переменные окружения `AS_VKID_CLIENT_ID`,
`AS_YANDEX_CLIENT_ID` и `AS_YANDEX_CLIENT_SECRET` через существующий механизм
хранения секретов. Ссылки вида `$NAME` подставляются при открытии подключения к
провайдеру; без необходимых значений вход через него не работает. Также можно
сохранить сами значения в закрытой конфигурации через тот же механизм управления
секретами. После настройки перезапусти только сервер Aheadscale.

Пока провайдеры не настроены, доступны прежние Sign in / Sign up по email.
Настроенные способы входа появляются на странице выбора в оформлении Aheadscale.
При выборе email открывается прежняя форма с проверкой адреса. Неработающие
кнопки соцвхода не показываются.

Настройки подключённых провайдеров сохраняются в Dex: удаление записи из файла
не удаляет сохранённое подключение. Чтобы отключить провайдера, используй
существующий администраторский API удаления подключений.

## Учётные записи и сессии

Dex сохраняет исходный OAuth-запрос приложения, адрес возврата, PKCE и
идентификатор учётной записи. Подключения к провайдерам используют код авторизации,
параметр `state` и PKCE. VK ID дополнительно привязывает запрос к `device_id` и
проверяет `state` в ответе с токенами. Обмен токенами и секретами выполняется на
сервере; они не попадают в хранилище браузера или URL запросов.

Запросы к провайдерам ограничены по времени и размеру ответа; перенаправления
отклоняются, ошибки не раскрывают секреты. Токены обновления хранятся в данных
сессии подключения Dex. При обновлении повторно проверяется идентификатор
пользователя у провайдера; его смена приводит к отказу. Если провайдер не вернул
email, вход завершается ошибкой. Адрес и признак его подтверждения не подставляются
искусственно.

Учётная запись определяется парой «провайдер + постоянный идентификатор
пользователя». Одинаковые email не объединяют аккаунты, в том числе при входе
по локальному паролю.

## Проверки и оставшиеся действия

Автоматические тесты проверяют все четыре способа входа: обмен кода, PKCE,
получение профиля и обновление сессии через тестовые HTTP-провайдеры. Проверены
неверный `state`, отказ провайдера, отсутствие идентификатора или email,
несовпадение идентификаторов в токене и профиле, другое приложение Яндекса,
смена пользователя и пять отдельных аккаунтов с одним email. Тесты конфигурации
проверяют передачу настроек провайдеров и сохранение прежних значений по умолчанию.

18 октября 2026 года параметры обоих приложений подключены к рабочему серверу.
На `https://aheadscale.ru` доступны email, VK ID, Яндекс ID, Mail.ru и Одноклассники.
Секреты сохранены в зашифрованном хранилище проекта и передаются серверу через
закрытый файл окружения.

Проверены переходы ко всем четырём провайдерам: страницы открываются с кодом 200,
идентификаторы приложений, адрес возврата, `state` и PKCE передаются правильно.
Вход по email, проверка адреса, закрытая первоначальная настройка и защита API
сохранены. Существующие аккаунты и устройства остались на месте; эти проверки
не создавали пользователей.

В браузере владельца ещё нужно завершить настоящий вход через VK ID и Яндекс ID,
подтвердить выдачу разрешений и проверить возвращение в Aheadscale. Обмен кода
авторизации на токены и продление настоящих сессий требуют отдельной проверки с
пользовательскими аккаунтами; проверки переходов их не заменяют.

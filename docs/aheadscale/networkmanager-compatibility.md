# Совместимость Linux NetworkManager-плагина

Проверка от 28 октября 2026 года. Источник: официальный v0.1.12, коммит `1c1e87d67e2d1e20e52d40a752bae304a7f1d48a`; локальный форк Aheadscale. Go 1.26.7; daemon protocol upstream 0.73.2 и Aheadscale 0.80.0.

## Подтверждено автоматической проверкой

`TestAheadscaleDefaultDaemon` использует настоящий Unix socket и gRPC. Плагин собран со своим upstream proto, отдельный fixture — с актуальным `client/proto` Aheadscale; обе стороны не подменяют друг другу типы. Проверены GetFeatures, GetConfig, Login, WaitSSOLogin, Up, Status и Down. При DisableProfiles PrepareActivation/EnsureExists/Resolve возвращают пустой ProfileRef; тестовый сервер не реализует AddProfile/SwitchProfile, поэтому нежелательный вызов дал бы отказ. Пустой Login/Up и GetConfig(default) совместимы по wire-контракту.

Исходный RED: upstream обращался к `unix:///var/run/netbird.sock` и использовал чужой service-type. После адаптации socket/service/URL и видимых строк `go test -race ./internal/... -count=1` в форке прошёл во всех восьми пакетах. Сохранены BSD-3-Clause/notices и технический Go module. Тесты не используют рабочие учётные записи и не создают устройства.

## Что ещё не доказано

Синтетический протокольный fixture не является работающим VPN-движком. Реальные вход/отмена, IP/DNS, выбор интерактивного режима самим GNOME/KDE, root broker на установленной системе и миграция/lifecycle пока NOT RUN. Неинтерактивный reuse и границы broker проверены изолированными автотестами, без заявления живой приёмки. Наличие исходной поддержки default не доказывает регистрацию без новой вкладки. Живые проверки выполняются после согласования DNS/контроллера в задачах 4–8; текущая рабочая сеть ВМ не переводилась на новый плагин.

## Повтор проверки

В checkout клиента: `go build -buildvcs=false -o /tmp/aheadscale-nm-proto-fixture ./client/proto/testdata/networkmanager-daemon`.
Запустить fixture с отдельным Unix socket, затем в checkout форка задать `AHEADSCALE_COMPAT_DAEMON=unix:///путь/к/socket` и выполнить `go test -race ./internal/... -count=1`. После проверки остановить только свой fixture и удалить socket/бинарник. Без указанного fixture интеграционный тест завершается отказом, а не скрытым SKIP.

## Дополнительные подтверждения реализации

Плагин закреплён в `packaging/aheadscale/networkmanager-source.json`: архив upstream и patch проверяются по SHA256 перед исполнением. Все исходные лицензии сохранены. GTK3/GTK4 редакторы собираются; тест совместной загрузки libnm сначала воспроизвёл `cannot register existing type NetbirdEditorPlugin`, затем прошёл с отдельными типами Aheadscale. Это проверка загрузчика и модели, а не визуальная приёмка системной панели.

SELinux-модуль с собственными типами/точными путями собран против Fedora 44 и установлен в изолированную копию policy store. Проверка отпечатка перед удалением прошла негативный сценарий замены модуля. Политики рабочих ВМ этой проверкой не менялись; действующий SELinux в живой Fedora проверяется отдельно.

Изолированные тесты подтвердили: зарегистрированный SSO подключается неинтерактивно без новой вкладки и AddProfile; Cancel ждёт уборки; старые RPC не выключают новое поколение; поздний Begin отключаемого профиля отклоняется; изменённые квитанция/файлы/unit/модуль не перезаписываются. Подготовлены 16 сочетаний payload; до сборки и установки настоящих пакетов это не считается готовой матрицей дистрибутивов.

## Первые проверки установщиков и старой интеграции

На Ubuntu ARM64 (Plasma) и Fedora ARM64 (GNOME) сборки `.26` воспроизведён RG43: после restart NetworkManager системный Disconnect удалил адрес интерфейса, но демон продолжил показывать Connected. Первичные результаты сохранены приватно в `release29/evidence/*-rg43-before-native.json`. Это исходный отрицательный результат, а не приёмка нового плагина.

Пакет CLI `.28` отказал при конфигурации из-за прав 0664 у служебного manifest: guard корректно запретил групповой доступ на запись. Нормализация всех файлов проверена регрессией с umask 0002; CLI `.29` установился штатно. При его обновлении выявлено чтение устаревшего native-намерения вместо актуального состояния standalone CLI. Новый тест воспроизвёл оба направления ON/OFF, с отсутствующей и снятой Desktop-квитанцией; исправление прошло полный packaging-набор. Поэтому `.29` пока является диагностическим кандидатом, а не принятым установщиком.

Вход CLI-узла подтверждён пользователем; устройство сохранило прежние IP и FQDN и подключилось без создания новой регистрации. Живые R05/T01/C13 нового Desktop-плагина остаются открытыми до фактического выполнения.

Desktop `.29` штатно установлен на Ubuntu ARM64, но контроллер отказал на GetConfig с пустым profile handle. Запрос теперь явно использует существующий `default`; регрессионный тест воспроизвёл отказ и прошёл после исправления. Полный набор nmcontroller/packaging с race detector прошёл. Следующий кандидат — `.30`; это пока не результат живой приёмки.

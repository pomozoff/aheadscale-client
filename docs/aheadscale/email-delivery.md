# Отправка писем регистрации Aheadscale

## Рабочая конфигурация — 1 ноября 2026

По поручению владельца отправка переведена с Yandex Cloud Postbox на SMTP
Timeweb, тариф «Почтовый». Владелец создал support@aheadscale.ru для переписки
и noreply@aheadscale.ru для сервисных писем. Адрес отправителя должен совпадать
с SMTP-логином. Клиентский код, образ сервера и шаблон письма не менялись.

| Параметр | Значение |
| --- | --- |
| `AS_SMTP_HOST` | `smtp.timeweb.ru` |
| `AS_SMTP_PORT` | `587` |
| `AS_SMTP_TLS` | `starttls` |
| `AS_SMTP_USERNAME` | `noreply@aheadscale.ru` |
| `AS_SMTP_FROM` | `Aheadscale <noreply@aheadscale.ru>` |
| `AS_SMTP_PASSWORD_FILE` | `/run/aheadscale-secrets/smtp-password` |
| `AS_REGISTRATION_LINK_TTL` | `30m` |
| `AS_REGISTRATION_RESEND_AFTER` | `1m` |

[Официальные настройки SMTP](https://timeweb.com/ru/docs/pochta/osnovnye-voprosy-po-rabote-s-pochtoj/osnovnye-nastrojki-pochtovyh-klientov/).
Пароль передаётся закрытым файлом 0600/0400, не переменной окружения,
не аргументом команды и не через чат. Проверка TLS-сертификата обязательна;
вариант SMTPS на 465 поддерживается с режимом `implicit`.
При отказе SMTP не создавать аккаунт обходом проверки адреса.

## DNS

MX направлены на mx1.timeweb.ru и mx2.timeweb.ru. SPF должен оставаться
одной TXT-политикой; на время перехода она разрешает Timeweb и Postbox.
DKIM берётся из кабинета фактически подключённого тарифа; селектор не угадывать.
Наличие записи Postbox не доказывает DKIM-подпись Timeweb. Проверить результат
по заголовкам доставленного письма. MX и DMARC при уборке Postbox сохраняются.
NS остаются в LandVPS; сервис и сайт не переносятся.

## Проверка

SMTP AUTH и TLS Timeweb прошли. Владелец подтвердил доставку согласованного
проверочного письма во «Входящие» pomozoff@mail.ru. Рабочий сервер переключён,
HTTP и прежние ограничения доступа сохранены, другие контейнеры не менялись.
Это не заменяет полную проверку нового аккаунта и SPF/DKIM/DMARC.

Для повторной регистрации владелец поручил удалить тестовый аккаунт
pomozoff@yandex.ru и создать его снова. Аккаунт удалён штатным API,
связанные отключённые устройства удалены, остальные сети сохранены.
Новая pending-заявка отправлена через Timeweb; перед подтверждением password
identity отсутствовала. Владелец завершил регистрацию на aheadscale.ru:
Registration Successful. Read-only проверка подтвердила identity, отдельный
аккаунт с единственным owner, state=done и verified_at. Peers пока 0.
Письмо Yandex попало в «Спам»: это подтверждает доставку, но не готовность
канала для беты. DKIM/DMARC и доставляемость ещё требуют проверки.
Пароль и ссылку в диагностику не включать.

Обычные продуктовые тесты выполняются выборочно в GitHub Actions
с изолированным SMTP-приёмником и синтетическими аккаунтами. Секрет Timeweb
туда не загружается; проверка реальной доставки выполняется отдельно.
При смене только SMTP-конфигурации сборка приложения не нужна.

## Откат и вывод Postbox из эксплуатации

Старые smtp.env и smtp-password сохранены в закрытой локальной точке возврата
перед переключением. Это локальный checkpoint, не независимый backup.
При отказе восстановить оба файла и пересоздать только сервер через существующий
Platform override; не менять image и данные аккаунтов.

До успешного завершения регистрации старые ключ и DNS Postbox не отзывать.
После приёмки убрать выделенный ключ/ресурс Postbox при наличии доступа
к кабинету владельца, затем удалить только его ненужный SPF include и DKIM.
Облако, каталог и ресурсы других проектов не удалять. Только после завершения
отката/отзыва удалять ненужные локальные копии секретов.

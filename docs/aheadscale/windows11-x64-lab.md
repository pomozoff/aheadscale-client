# Стенд Windows 11 x64 на Mac mini

Дата подготовки: 23 октября 2026. Назначение — чистые проверки x64-установщиков Aheadscale. Подготовка Windows **не считается** пройденным smoke клиента.

## Образ и ВМ

- Официальный [Microsoft Evaluation Center](https://www.microsoft.com/en-us/evalcenter/download-windows-11-enterprise), ссылка загрузки `LinkId=2382600`; конечный сервер `software-static.download.prss.microsoft.com`.
- Образ: `26300.9457.260913-1737.26h2_ge_release_svc_refresh_CLIENTENTERPRISEEVAL_OEMRET_x64FRE_en-us.iso`.
- Размер: 8 225 329 152 байта. SHA256 скачанного файла: `bc3f24086ebadc94489066b5ad78089e2cf5c3491e90e790bb81a2b199c10e38`. Это записанный хеш локального скачивания; независимый опубликованный хеш Microsoft не получен.
- WIM: один образ, Windows 11 Enterprise Evaluation, x86_64, build 26300.9457, английский интерфейс. Оценочный срок — **90 дней**, затем стенд требуется переустановить либо заменить подходящей лицензированной установкой.
- Хост: Ubuntu на Intel Mac mini, i3-8100B, 4 физических ядра, 32 ГБ RAM. QEMU 10.2.1; QMP подтвердил `KVM enabled=true`.
- Гость: 2 vCPU, 8 ГБ RAM, отдельный разреженный qcow2 на 80 ГБ, OVMF UEFI с ключами Microsoft/Secure Boot, отдельный TPM 2.0.
- Процесс QEMU работает от `adnako`, не root. Пользователь добавлен в группу `kvm`. Создание ВМ не потребовало нового rootful container runtime или изменения Docker/маршрутов.
- Сеть: пользовательский NAT QEMU; гостевой адрес обычно `10.0.2.15`. Внешний прикладной RDP-порт гостя не публикуется в интернет.

## Доступ

На MacBook включить имеющийся Tailscale. В клиенте RDP указать:

- Компьютер: **`macmini.tailb71cbe.ts.net:3390`**; запасной адрес `100.67.149.44:3390`.
- Пользователь: `AHEAD-W11-X64\aheadtest`.
- Пароль: закрытый файл `/home/adnako/VMs/aheadscale/windows11-x64/rdp-credentials.txt` на Mac mini, права `0600`. В репозиторий/чат не включён.
- Готовые параметры подключения без пароля: `/home/adnako/VMs/aheadscale/windows11-x64/connect.rdp`.

Tailscale Serve TCP 3390 пересылает трафик на `127.0.0.1:13389`, а QEMU — на гостевой TCP 3389. Локальный слушатель QEMU привязан только к loopback. NLA и TLS обязательны; Windows firewall разрешает RDP только от NAT-шлюза `10.0.2.2`. Существующие HTTPS/TCP-маршруты Serve сохранены и сравнены с прежней конфигурацией.

В Windows используется собственный самоподписанный RDP-сертификат ВМ; при первом подключении клиент может запросить его принятие. Не отключать NLA ради входа. Политики tailnet продолжают ограничивать доступ.

## Управление и материалы

Постоянный каталог: `/home/adnako/VMs/aheadscale/windows11-x64`. ISO и его происхождение — `/home/adnako/VMs/aheadscale/iso`. В каталоге ВМ находятся launcher `start.sh`, диск, NVRAM, состояние TPM, QMP-сокет, журнал гостевой готовности и `manifest.json` без пароля. Каталог закрыт правами `0700`.

После штатного выключения Windows запускать `start.sh` от пользователя с доступом к `/dev/kvm`; текущему старому сеансу может потребоваться новый вход либо `sg kvm`. Не запускать второй экземпляр на том же диске/NVRAM/TPM. Выключать через меню Windows, не завершением процесса QEMU.

Не клонировать установленный Aheadscale с зарегистрированными ключами. Чистый образ до клиента использовать только после штатного выключения ВМ; согласованная точка восстановления включает диск, NVRAM и TPM. Простое копирование работающего qcow2 не является надёжным снимком.

## Чистая точка восстановления

На выключенной ВМ создан внутренний снимок qcow2 `clean-windows-no-aheadscale`. В тот же момент отдельно сохранены NVRAM `OVMF_VARS.fd` и состояние TPM `tpm2-00.permall` в `baseline-clean-windows` внутри каталога ВМ. Снимок содержит установленную ОС до Aheadscale, без сохранённой оперативной памяти.

Для отката сначала штатно выключить Windows и убедиться, что QEMU/TPM остановлены; затем применить снимок диска и вернуть **соответствующие ему** NVRAM/TPM. Запуск — прежним `start.sh`. Не применять снимок к работающему диску и не смешивать состояние TPM из другого прогона.

Установочный `seed.iso` и исходный XML с временным паролем удалены после установки; запуск проверен без установочных ISO. Пароль для подключения сохранён в закрытом файле доступа; локальная учётная запись Windows готова к входу.

## Фактическая проверка

- Windows установлена: `AHEAD-W11-X64`, EnterpriseEval 26H2, AMD64, `10.0.26300.9457`.
- Гость подтвердил TPM Present/Ready, Secure Boot, службу RDP Running, TCP 3389 Listen и NLA=1.
- NLA-аутентификация по `macmini.tailb71cbe.ts.net:3390` завершилась кодом 0. Затем открыт полноценный рабочий стол через FreeRDP/Xvfb; из RDP-сеанса выполнены `ver`, `whoami`, `hostname`, дата/время. Результат передан через отдельную пустую папку RDP: правильные build и `ahead-w11-x64\aheadtest`.
- Из Windows прошёл `curl.exe -fS` к `https://aheadscale.ru/`, получен маркер `HTTPS_OK`.
- Первоначальный часовой сдвиг исправлен; для следующих загрузок согласованы QEMU RTC UTC и Windows `RealTimeIsUniversal=1`. После выключения и повторного запуска ВМ проверены правильные дата/время и полноценный RDP-сеанс с выполнением команды.
- На время ожидания обновлений OOBE гостевая сеть отключалась; после завершения OOBE включена обратно. Постоянного отключения Windows Update/Defender нет.
- RDP проверен с Mac mini через адрес Tailscale Serve. Подключение непосредственно с MacBook ещё не выполнялось.
- Aheadscale в эту Windows пока не устанавливался: результаты клиента остаются NOT_RUN.

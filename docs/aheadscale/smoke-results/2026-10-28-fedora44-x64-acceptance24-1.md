# Fedora 44 x64: приёмка RPM .24.1

28 октября 2026. Продолжение матрицы x64, отдельное от [Fedora ARM64](2026-10-27-rpm37-fix.md). **Основные проверки установки, GUI/CLI и жизненного цикла завершены; 78 положительных HTTP/DNS-проверок прошли. Общая приёмка Fedora не закрыта: обнаружен RG42 системного Disconnect, остаётся RG38.**

## Стенд и комплект

Отдельная Fedora Workstation 44 x86_64 на Mac mini: QEMU/KVM, UEFI, 2 vCPU, 4 ГБ RAM, отдельный диск 24 ГБ. SELinux Enforcing; firewalld включён. Установка автоматизирована штатным netinstall с `liveimg` из официального Workstation Live 44-1.7, без установки серверной редакции с добавленным DE. Оба ISO проверены по подписанным Fedora SHA256: ключ `36F612DCF27F7D1A48A835E4DBFCF71C6D9F90A6`. Workstation ISO SHA256: `1620295f6a00c27c3208f0c00b8ece4eab1ec69b9002152d97488bf26a426ddf`.

Источники: [Workstation](https://fedoraproject.org/workstation/download/), [netinstall](https://fedoraproject.org/server/download/), [поддержка liveimg](https://pykickstart.readthedocs.io/en/latest/_modules/pykickstart/commands/liveimg.html). Автоматический Kickstart непосредственно на Live ISO [не поддерживается](https://anaconda-installer.readthedocs.io/en/latest/user-guide/troubleshooting/common-bugs.html).

Исходные RPM сохранены в `/home/adnako/VMs/aheadscale/release24-rpm1/`: public Desktop и CLI amd64. Установленная версия RPM `0.80.0-0.aheadscale.24.1.x86_64`; CLI/UI `0.80.0-aheadscale.24`. Новых бинарников и изменений продукта в этом прогоне нет. Пакеты preview не имеют публичной подписи: предупреждение DNF об unsigned local RPM сохранено, проверка подписи Fedora не отключалась. Дополнительно проверялись реальные старые RPM `.24` из `release24/linux-amd64/`.

Новый узел зарегистрирован владельцем после освобождения им одного слота. Fedora: `100.88.228.98`, `aheadscale-fedora-x64.aheadscale.internal`; второй узел — Ubuntu Server x64 CLI `.24`, `100.88.144.57`, `aheadscale-cli-x64.aheadscale.internal`. Существующие устройства аккаунта агент не удалял.

## RG42: системный Disconnect не синхронизирован с клиентом

1. При работающем T01 открыть настоящее меню GNOME и выключить синюю плитку VPN → Aheadscale.
2. В журнале NM: успешный `connection-deactivate`, инициатор GNOME Shell, uid 1000; состояние устройства `activated → deactivating → disconnected`, причина `user-requested`. NM снимает IPv4; `nmcli` показывает 30/disconnected, плитка VPN исчезает.
3. Через 12 секунд CLI всё ещё возвращает Connected и прежний VPN IP. В открытом Aheadscale переключатель также On и текст Connected; это зафиксировано вместе с системной панелью на `system-repeat-after.png`.
4. Все шесть диагностических HTTP после первого системного отключения недоступны. Следовательно, Connected не отражает реальный туннель. Внешний HTTPS работает.
5. Штатные `aheadscale down` / `aheadscale up` восстанавливают прежний узел; шесть HTTP проходят. Повтор системного отключения воспроизводит то же расхождение; второй down/up и ещё шесть HTTP успешны.

Граница отказа установлена: пользовательское отключение NM меняет реальный интерфейс, но не переводит клиент в соответствующее состояние. Проверенные адаптеры `ConfigureNetworkManagerInterface` и `PrepareInterfaceRemoval` обеспечивают ожидание видимости/DNS и прямое отключение NM при удалении интерфейса клиентом; это не подтверждает обработку обратного пользовательского действия. Полное архитектурное решение и исправление в этом QA-прогоне не выполнялись. Не маскировать дефект удалением системной строки, отключением NM или исправлением одного текста Connected.

В итоговом состоянии сеть восстановлена; это **не** исправление RG42. Нужна отдельная правка и повтор R05/T02/T03 на Fedora и Ubuntu. RG35 о наличии туннеля и RG07 о ложном предупреждении при GUI Disconnect остаются отдельными регрессиями.

## Открытые пункты

- RG38 воспроизводится и на x64: непривилегированный `aheadscale service start` возвращает 1 и только `Error: start service: exit status 1`, без объяснения необходимости прав. Защита не ослаблялась, исправление в этот прогон не включено.
- RG42 блокирует согласованное системное управление VPN. Проверенные RPM-переходы RG37 не превращают весь Linux GUI/lifecycle в PASS.
- Полные S01–U04/C01–C24, PKCE-вход в GUI, соцвход/регистрация, чистая CLI-установка, Relay, разные интернет-подключения, IPv6-трафик, изоляция аккаунтов и подписи остаются отдельными пунктами. Пустые `networks list` / `forwarding list` не подтверждают маршрутизацию; `profile list` не включает профили продукта.
- Замеры задержек подключения P01–P06 по решению владельца не выполнялись. Ожидание загрузки ОС не выдаётся за время Connect.

## Свидетельства и уборка

Закрытые локальные материалы: `/home/adnako/VMs/aheadscale/fedora44-x64/evidence/`; паспорт ВМ — `manifest.json` рядом. Есть журналы установки/транзакций, CLI с кодами завершения, снимки GUI и JSON каждого T01 с точным маркером/remote_ip. Приватные ключи, пароли и диагностические данные в Git не добавлялись.

Одна первая сетевая проверка service restart пересеклась с последующим намеренным Disconnect из-за ошибки последовательности оператора. Соответствующие материалы помечены `excluded-overlap-*`, в PASS и число HTTP не включены. Start/restart и постоянный Idle повторены последовательно одним оператором и прошли. Каталог синтетического HTTP fixture первоначально очистила штатная перезагрузка `/tmp`; после восстановления он размещён в `/var/tmp`, это не отказ VPN.

После первого успешного запуска удалены 4,06 ГБ собственных временных ISO, ядра/initrd и seed. В конце остановлены и удалены оба синтетических HTTP fixture, порт 8765 свободен, четыре временные копии RPM в Fedora удалены. Временных firewall-правил не создавалось. Исходная системная тема возвращена. Fedora оставлена Desktop `.24.1`, active/enabled и Connected, Launch UI at Login ON / Connect on Startup ON; SELinux Enforcing, firewalld active. Ключ/IP/FQDN прежние; второй узел также Connected. Диск ВМ, исходные установщики и нужные свидетельства сохранены.

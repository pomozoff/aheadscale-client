# RG37: исправление замены Desktop ↔ CLI RPM

27 октября 2026, Asia/Krasnoyarsk. Продолжение [Linux `.24` reboot/CLI](2026-10-27-linux24-reboot-cli.md). **RG37 исправлен в упаковщике; runtime-повтор пройден на Fedora 44 ARM64. Остальная релизная матрица не закрыта.**

## Причина и исправление

Новый RPM выполнял `%post`, включая службу, после чего старый вариант выполнял `%preun`, останавливая и отключая ту же `aheadscale.service`. Поэтому успешная транзакция DNF оставляла сервис inactive/disabled.

В `%pre` теперь сохраняются только активность и автозапуск службы в закрытом временном каталоге `/run/aheadscale-rpm`. `%posttrans` восстанавливает их после удаления старого пакета. Промежуточный `%post` больше не запускает клиент. Это работает и при миграции с уже выпущенной `.24`, чей старый `%preun` изменить нельзя. При первой установке сохраняется прежнее правило enable/start. Окончательное удаление по-прежнему останавливает службу и очищает только своё подключение. Ключи и настройки клиента этот код не читает и не переписывает.

Правка: `aheadscale.spec.in`, `scripts/rpm-lifecycle`, `rpm_package.py`. Источник упаковки — подписанный `3844195`; дальнейшее уточнение теста не меняло содержимое RPM.

## Проверки

Регрессия shell hooks сначала воспроизвела disabled/inactive вместо ожидаемых состояний, затем стала GREEN. Она исполняет настоящие `%pre/%post/%posttrans` с заменой только системных примитивов, включая остановку старой `.24`. Проверяются оба установленных имени, все четыре сочетания active/inactive × enabled/disabled и первая установка. Полный Go-набор `packaging/aheadscale` с `-race` и обязательный `make lint` прошли; shell/Python и diff также проверены. Один повтор Go сначала не получил запись в существующий кэш; повтор с доступом к кэшу прошёл, это не зачтено как ошибка продукта.

На существующей Fedora 44 ARM64 с независимым SSH выполнены настоящие локальные DNF-транзакции, без обновления других пакетов и без ручного enable/start после установки: Подготовительные stop/start/enable между кейсами задавали следующее исходное состояние; результат каждой транзакции проверен до такой подготовки.

## Отдельное наблюдение: RG39

Первая подготовка Idle не применила `--disable-auto-connect`: при уже Connected CLI возвращает `Already connected` до обработки флагов. Конфигурация осталась false, поэтому первоначальная Idle-проверка не прошла и не зачтена. GUI в этот момент не работал. Повтор с предварительным down и проверкой сохранённого true прошёл. После тестов отдельно воспроизведено: Connected → up с флагом → exit 0 / Already connected, значение по-прежнему false.

Это отдельный дефект CLI C15/RG39, **этой правкой не исправлен**. Постоянная настройка DisableAutoConnect и временный down различаются: временное намерение хранится в памяти процесса. Нового обещания сохранять его при любом restart эта правка упаковки не вводит; поведение требует отдельной проверки CLI/lifecycle.

## Завершение и границы

Fedora оставлена на Desktop RPM `.24.1`, CLI/UI `.24`; исходное DisableAutoConnect=false восстановлено. Fedora и Ubuntu Connected, GUI toggle checked, NM active, служба enabled, публичный HTTPS 200. Установленные CLI/UI по SHA256 совпадают с прежними бинарниками. Снимок RPM-транзакции удалён, временные HTTP-службы остановлены, слушателей 8765 нет. Защита ОС/проверка TLS не ослаблялись, правила firewall не менялись. Закрытая резервная копия регистрации сохранена в самой Fedora.

Runtime проверен **только Fedora ARM64 public**. x64/internal имеют проверенные упаковку и хеши, runtime отдельно открыт; это не приёмка чистого Linux-сервера, всех C01–C24, всего GUI или всего сервиса. RG38/RG39, подписи и прежние релизные ограничения остаются открытыми. P01–P06 не выполнялись.

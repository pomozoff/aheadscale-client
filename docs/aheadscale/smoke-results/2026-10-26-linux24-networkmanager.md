# Linux `.24`: восстановление NetworkManager, RG35

Дата: 26 октября 2026. Продолжение [проверки `.23`](2026-10-26-windows11-arm64-ubuntu23-network.md). Проверка одного дефекта не заменяет полную релизную матрицу.

## Причина и исправление

В Ubuntu 26.04.1 ARM64 `.23` управляющий канал и WireGuard работали, но активного подключения Aheadscale в NetworkManager не было. Фактический интерфейс назывался `Aheadscale`: имя сохранилось от прежней установки. NetworkManager 1.54.3 использовал режим `systemd-resolved`, а клиент выбирал прямую настройку resolved и создавал собственное временное правило `managed=0` для этого интерфейса. Это воспроизведено отдельной проверкой активного NM-подключения с отказом.

В общей версии не оказалось ранее принятых изменений из старой рабочей копии. В изолированную ветку перенесены только изменения Linux: выбор NetworkManager как владельца DNS, когда он передаёт настройки в resolved; ожидание активации внешнего WireGuard-подключения перед применением DNS; поддержка актуальных NetworkManager 1.x; имя Aheadscale для нового и прежнего стандартного интерфейса. Пользовательские имена сохраняются. При обновлении конфигурации сохраняются ключи и исключения сетевых интерфейсов.

При DNS Reapply сохраняются внешние адреса/маршруты и фактические порт/fwmark WireGuard. Флаг сохранения внешних IP предусмотрен [официальным API NetworkManager начиная с 1.42](https://networkmanager.dev/docs/api/latest/gdbus-org.freedesktop.NetworkManager.Device.html). Исправлен формат приватных routing-only DNS-доменов. Для систем без NetworkManager и для других ОС интеграция остаётся безопасной пустой операцией. Системные библиотеки, firewall и NetBird/Tailscale не перенастраиваются.

## Сбой Fedora в способе удалённого управления окном

Во время проверки зарегистрирован SIGSEGV. Он воспроизведён после внесённого оснасткой `SIGUSR1`, при отмене входа и повторном подъёме окна. В core исходный PC соответствует `WTF::Thread::signalHandlerSuspendResume + 48` из `libjavascriptcoregtk-6.0.so.1`. В [официальном исходнике WebKitGTK 2.52.1](https://github.com/WebKit/WebKit/blob/webkitgtk-2.52.1/Source/WTF/wtf/posix/ThreadingPOSIX.cpp) этот сигнал по умолчанию принадлежит остановке/возобновлению потоков JavaScriptCore; произвольная доставка процессу попадает в обработчик без подготовленной целевой нити. Это не доказательство падения обычного запуска или ошибки NetworkManager.

Оснастка переключена на существующий штатный механизм единственного экземпляра — повторный запуск бинарника. На том же установленном `.24`, без отладчика и изменения библиотек/графики, пройдены четыре цикла отмены и повторного открытия входа без падения. Графические флаги не менялись в исходниках/пакете, экспериментальное окружение отдельного запуска отменено; SELinux остался Enforcing. `SIGUSR1` исключён из инструкции автоматизации.

Первая диагностическая GDB-попытка завершилась по собственному ограничению времени и не считается продуктовым падением. В разборе core первоначально был выбран PC последующего Go SIGQUIT; причина установлена только после сопоставления PC первого SIGSEGV. Защитная проверка версии DEB первоначально ожидала дефис вместо штатного `~` и остановилась до установки; после исправления оператора пакет установлен. Краткий SSH-таймаут также был до изменения Ubuntu. Эти отказы оснастки сохранены отдельно.

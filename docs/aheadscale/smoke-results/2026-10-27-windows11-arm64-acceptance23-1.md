# Windows 11 ARM64: продолжение проверки `.23.1`

27 октября 2026 года. Отдельный ARM64-прогон, результаты x64 не переносятся.

## Точный комплект

Windows 11 Pro ARM64, CIM build 26300, ВМ UTM на MacBook. Клиент `.23`, MSIX `0.1.62.1` ARM64. Единый EXE `.23.1` SHA256 `1a5208da4f236f5e5bab8e75c8595a62d744f6a803256b942540950955fc7bc2`; исправление упаковки `8e62c36`, бинарники из `f9a52d82026c4abde721ed10b11e25170f19dd4c` не пересобирались. Локальный preview, публичная подпись не принята.

## Подтверждено

- SSH восстановлен по сверенным ключам; Windows Update не запускался. Исходно служба автоматическая/Running, CLI Idle, GUI не запущен, пользовательский автозапуск выключен (нет собственной задачи).
- Настоящий единый установщик запущен в интерактивном сеансе владельца; exit 0. SHA256 default/active profile/UI preferences до и после установки полностью совпадают. Выключенный запуск сохранён; системный VPN Disconnected соответствует исходному Idle.
- Общие восемь Windows-регрессий helper прошли непосредственно на ARM64, случайные задачи и значения реестра убраны тестом. Это не заменяет полный lifecycle установленного комплекта.

## GUI, CLI и сеть

- Вход завершён владельцем в свежей вкладке; callback закрылся, получен Connected, прежний адрес `100.88.77.246/16`, FQDN `win-s5jsuhs8ctr.aheadscale.internal`, четыре соседа.
- Первые шесть прикладных HTTP/DNS по IP, полному и короткому имени в обе стороны с чистым Linux CLI x64 прошли. Сравнивались HTTP 200, точное тело, remote_ip и системное разрешение имён; прокси отключён для тестового запроса.
- 30 CLI-команд без тайм-аутов: справка, текст/JSON/YAML/IP, health-check, списки и отрицательные аргументы дали ожидаемые exit codes. JSON разбирается, IPv4 совпадает с живым интерфейсом. `update` и `kubeconfig` отсутствуют в этой сборке; ожидаемый unknown command не считается функциональной приёмкой этих возможностей. Справка не заменяет работу SSH/подсетей/прочих дополнительных функций.
- Настоящий GUI Disconnect: Idle, native VPN Disconnected, VPN IPv4 отсутствует, запрос к заведомо работающему Linux-сервису отклоняется, обычный HTTPS остаётся 200. Повторный Connect — без SSO с прежним ключом/IP/FQDN.
- Настоящая страница Windows Settings → VPN открылась: Aheadscale / Connected / Disconnect видны и через UI Automation, и на снимке; зависание в этом открытии не воспроизвелось. Это не доказательство отсутствия любых зависаний Settings.
- T03-SVC: PID службы изменился, PID GUI сохранился; native VPN и CLI снова Connected с прежней идентичностью. После восстановления ещё шесть двусторонних HTTP/DNS прошли. С учётом последующего reboot всего 18 положительных запросов.

Первый скрипт отрицательного HTTP попал в особенность PowerShell 5: ожидаемый stderr curl с тайм-аутом стал terminating error. Такой прогон не принят. После явного чтения stdout/stderr процесса и exit code весь Disconnect повторён и проверен; это исправление оснастки. Служба не объявлялась восстановленной до завершения её оператора и проверки нового PID.

## Полная переустановка и автозапуск

Для отдельной проверки явно включён запуск GUI при входе; первоначальное выключенное состояние записано и возвращено при уборке. Настоящие uninstall/install `.23.1` завершились с exit 0. Между ними отсутствовали служба, CLI, MSIX и запись автозапуска; SHA256 всех трёх конфигураций не изменились на каждом этапе. После установки собственная enabled-задача восстановлена. Это проверка полного remove/reinstall, отличная от исходной установки поверх с сохранением OFF.

Фактическая новая загрузка `18:54:25.7343 +03:00` подтверждена CIM; после обычного входа владельца GUI появился сам в Session 1 (PID 5532). Первый снимок `18:56:09` застал Idle, затем без ручного Connect/SSO зарегистрировано Connected с прежним ключом/IP/FQDN и native VPN Connected. Последующий полный T01 дал ещё шесть положительных HTTP/DNS. Первый снимок не объявляется окончательным отказом автоподключения. Пустой ключ в Idle-ответе не означает удаления ключа из конфигурации. В чате преждевременное объявление сбоя исправлено после следующего наблюдения.

Это функциональный T03-OS, без PASS бюджета скорости: загрузка Windows/GUI не измерялась как установка VPN, исследование задержек остаётся отложенным. Обновления Windows не запускались, перед reboot проверено отсутствие WindowsUpdate/CBS RebootPending.

Продолжение оставшихся сценариев — [итоговый ARM64-прогон](2026-10-27-windows11-arm64-final.md); перечисленные ниже ожидания относятся к моменту этого первого отчёта.

## Осталось

Команды Connect/Disconnect из системной панели, disabled full remove/reinstall и GUI ON / auto-connect OFF именно на ARM, чистая установка, остальная полная GUI/CLI-матрица и публичная подпись остаются открытыми. Успешный одиночный reboot не закрывает все прежние сообщения RG19 на всех ОС. Отсутствие главного окна при первом фоновом запуске само по себе не считается падением: окно создаётся по открытию приложения.

## Уборка

Исходный выключенный launch-on-login возвращён штатным helper; текущий GUI/VPN Connected и прежняя регистрация сохранены. Удалены собственные временные HTTP-процессы, узкие firewall-правила, 17 задач QA и 48 временных файлов ВМ, включая копию EXE. Linux HTTP-fixture также остановлен и удалён, порт освобождён. Постоянное продуктовое UDP-правило, настройки/ключи, существовавшие ранее задачи и обе ВМ сохранены.

При уборке имя фильтра временного firewall-правила оказалось GUID старого интерфейса после remove/reinstall; перед удалением проверены конкретный GUID и остальные атрибуты своего правила. Повторный HTTP-оператор встретил уже работающий собственный listener; запросы проверены по точному телу и адресу, дублирующий запуск сервера не считается дополнительным тестом.

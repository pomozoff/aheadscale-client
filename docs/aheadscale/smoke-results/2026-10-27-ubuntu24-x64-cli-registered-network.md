# Ubuntu Server x64 CLI: регистрация после освобождения слота и сеть

27 октября 2026 года. Продолжение [чистой установки CLI](2026-10-27-ubuntu24-x64-clean-cli.md)
и [отказа шестому устройству](2026-10-27-limit6-windows-followup.md).
Исходники, серверная конфигурация и установленные пакеты не менялись.

## Стенд и регистрация

- Ubuntu Server 24.04.5 x64, отдельный CLI DEB `.24`, KVM, без GUI и NetworkManager.
  Происхождение пакета и SHA256 приведены в отчёте чистой установки.
- Второй узел: Ubuntu 26 ARM64 `.24`, `ubuntu-ahead`, `100.88.19.208`.
- Владелец самостоятельно удалил Fedora через веб-панель. На существующей Ubuntu
  осталось три соседа и сама Ubuntu: четыре зарегистрированных устройства.
- Новый Linux-узел выполнил `up --no-browser`. Владелец подтвердил свежий
  Device Authorization Flow в своём браузере; локальный callback не требовался.
- Получены Connected, имя `aheadscale-cli-x64.aheadscale.internal` и
  `100.88.144.57/16`. Оба каталога содержат четыре соседних устройства:
  в аккаунте снова пять. Это подтверждает освобождение и повторное занятие слота.
  Конкурентные регистрации на последнее место этим прогоном не проверялись.

Отпечаток публичного ключа (SHA256 от текстового значения) после повторного `up`,
restart и reboot совпал:
`b8e10e11ba7061c1da8ab72ca9eff36a8510aa73457a93083e40ba75bd792d64`.
После перезагрузки сначала прочитан статус, без ручного `up` или запуска GUI.
Для последующей сетевой пробы восстановлен только временный HTTP-сервис:
Ubuntu очистила его каталог в `/tmp` при reboot. Первая попытка переиспользовать
исчезнувший каталог остановилась на проверке оснастки до сетевого теста;
это не отказ VPN. Настройки клиента, маршрутов и firewall вручную не менялись.

В исходном каталоге связь двух Linux-узлов обозначена Relayed. Это наблюдение
рабочего соединения, а не приёмка принудительного Relay/Direct failover T06.

## Границы и уборка

Это приёмка конкретных C03/C07 и восстановлений C09 на чистом headless Linux,
а не полный C01–C24 или матрица Ubuntu Desktop x64. Setup key/C04,
зарегистрированный remove/reinstall, изоляция аккаунтов, T04–T07 и полный
жизненный цикл остаются открытыми. RG38 не исправлялся; RG39 не изменялся.
Исследование задержек по решению владельца отложено; скорость загрузки ОС
и подключения этим прогоном не оценивалась.

Оба тестовых HTTP-процесса остановлены, порты освобождены, временные каталоги
и использованные файлы браузерного входа удалены. Одноразовые ссылки/коды
и приватные данные в Git не сохранялись. Нужная ВМ и регистрация остаются
для дальнейшей проверки; устройство автоматически из аккаунта не удалялось.

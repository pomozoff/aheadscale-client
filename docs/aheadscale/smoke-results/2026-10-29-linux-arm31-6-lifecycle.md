# Linux ARM64 `.31.6`: перезагрузка, CLI и переустановка

29 октября 2026 года. Продолжение [системной отмены](2026-10-29-linux-native31-6.md).
Проверены public Desktop и самостоятельные CLI-пакеты на существующих
Ubuntu 26.04.1 ARM64 Plasma и Fedora 44 ARM64 GNOME. Это целевые сценарии
R01/R03/R04, C09/C13 и T01; полного принятия платформ они не означают.

Fedora, 8 между CLI ARM64 и CLI x64, 4 после завершения Fedora и 4 после завершения Ubuntu. Использовался
существующий CLI x64 с отдельными временными HTTP-службами. Connected не
подменял проверку передачи данных. Это не замер времени загрузки или VPN.

## Сохранность и состав пакетов

Переход Desktop → CLI убрал GUI, controller, службу плагина и собственный
профиль NetworkManager; daemon остался active/enabled, работал с прежним
VPN-IP. Пользовательские preferences и XDG autostart сохранены. Это установка
CLI на существующих Desktop-ВМ, **не проверка чистого Server ARM64** и не полный
набор всех CLI-команд. NetworkManager ОС продолжал обслуживать обычную сеть.

Автоподключение выключалось штатным самостоятельным CLI:
`down` → `up --disable-auto-connect` → `down`. Возврат на Fedora выполнен через
`up --disable-auto-connect=false`. В Desktop эти флаги намеренно недоступны;
проверки ограничений CLI не ослаблялись. Клики по переключателям Settings в
этом прогоне не приняты: доступность окна найдена, но системное действие
`select` у меню не открыло нужные элементы. Это ограничение автоматизации,
а не установленный дефект меню.

Изменялся только `DisableAutoConnect`: канонический SHA остальных полей профиля
совпал с исходным на обеих ВМ. Во время remove/reinstall четыре файла
(профиль, active_profile, UI preferences, XDG autostart) дали одинаковые SHA
до удаления, после удаления и после установки. В конце Fedora полный SHA
профиля вернулся к исходному
`c862d47a74def1942fc02b7337dce3bb643fd5cbc44a0176bf29e0ad2a5a11f6`.
SELinux Fedora оставался **Enforcing**. Удаление RPM отключало автоматическое
удаление зависимостей: проверялось удаление Aheadscale, не системного окружения.

## Неудачная попытка смешать ревизии

В начале оператор выбрал новый Desktop `.31.6` и старый CLI `.31.3`.
Старый установщик не знает добавленного пути модуля Plasma и отклонил квитанцию
с сообщением «Чужой ресурс в квитанции Aheadscale». В Ubuntu отказ произошёл
до замены Desktop. DNF Fedora после отказа нового `%prein` всё же удалил
прежний Desktop; установленных пакетов Aheadscale не осталось, регистрация
сохранилась. Восстановлен Desktop `.31.6`, возвращены исходные enabled/active.
Первый немедленный Up попал до создания профиля NM и вернул отсутствие UUID;
после готовности controller профиль появился и Up прошёл.

Это **не успешный переход** и не основание обходить проверку квитанции.
Проверка повторена с согласованными CLI `.31.6`: оба направления на обеих ВМ,
которые перечислены PASS выше, прошли штатно. Старые опубликованные артефакты
не переписывались, защитный код не менялся. В инструкции и будущих обновлениях
нужно выбирать Desktop/CLI одной ревизии; downgrade на старый CLI `.31.3`
не принят.

- RPM CLI SHA256: `608607fb404c0286a8b00552a63a2285b327992974cc0a651f7cfc87fec9eb34`.

Каталог: `/home/adnako/VMs/aheadscale/linux-native-preview31/preview31p6/`,
отдельные `cli-manifest.json` и `CLI-SHA256SUMS`. GUI и ядро не пересобирались.
Сырые протоколы приватно:
`/home/adnako/VMs/aheadscale/release29/evidence/arm31p6-lifecycle/`.
Сохранены также неуспешные попытки, чтобы не смешивать их с принятыми.
Временные HTTP-службы/каталоги/правила firewall и host staging/rpmbuild удалены.

Обе ВМ возвращены к Desktop, VPN ON и исходному автозапуску. Полный SHA профиля
Ubuntu снова `a20b412d3fbe8d682759852c80c9f1e22f8e7ed0f6c48b7a78c2e59c8823a93c`.
Ненужные копии установщиков удалены на обеих ВМ; стабильные установщики и
свидетельства сохранены на Mac mini. HTTP-службы остановлены, порт 8765 свободен
на Ubuntu после уборки.

После восстановления Ubuntu проверен новый boot ID
`0f101861-d2f0-4833-82e0-f895328298cb`. Процесс GUI был запущен именно
`app-aheadscale@autostart.service`, а не вручную. После финального возврата
Desktop переключатель настоящего GUI через AT-SPI имел CHECKED=true,
ENABLED=true, VISIBLE=true. Первая дополнительная проба не нашла переключатель,
поскольку окно было скрыто; после штатного открытия уже работающего приложения
проверка прошла. Это не считается сбоем GUI.

## RG42: системное отключение

На Fedora x64 нажатие выполнено в настоящей плитке GNOME, состояние снято также
на снимках экрана. На Ubuntu ARM64 и Fedora ARM64 пользователь вручную нажал
системный Disconnect/OFF и оставил его выключенным. На обеих ARM64 через SSH
после выдержки 12 секунд подтверждены одновременно:

1. CLI `Idle`, VPN-IP пустой, интерфейса `Aheadscale` нет.
2. Переключатель в действующем окне Aheadscale выключен.
3. Самоподключения нет; последующее нажатие переключателя самого Aheadscale
   восстанавливает соединение без повторной авторизации.
4. После восстановления проходят двусторонние HTTP по IP/FQDN/короткому имени.

Отдельные отключения через `nmcli` на обеих ARM64 дали такое же согласованное
состояние. Они не подменяют ручные проверки кнопок KDE/GNOME.
**Ветвь системного Disconnect RG42 принята на трёх Desktop-стендах.**
Системный Connect/Cancel и перезапуск самого NetworkManager в этот прогон не входят;
весь R05 остаётся частичным.

## Сеть, CLI и восстановление

Существующий T01 проверял реальный HTTP 200, точное синтетическое тело и ожидаемый
VPN-IP назначения: по IP, полному и короткому имени, в обе стороны с CLI x64.
Приняты **12 полных серий, 72/72 HTTP/DNS**:
Fedora x64 — 18, Ubuntu ARM64 — 24, Fedora ARM64 — 30.
Последние серии ARM64 выполнены после ручного системного OFF и восстановления GUI,
а также после перезапуска CLI-узла. Чтение каталога само по себе не считалось T01.

Перезапуск `aheadscale.service` проверен на всех четырёх ВМ; действующие регистрации
восстановлены, прикладной трафик подтверждён. На CLI x64 дополнительно выполнены
справка, JSON/YAML, IPv4/IPv6, detail, `--check live|ready|startup` с кодом 0.
Это только положительные health-check, не полный C10. Вывод IPv6 не является
проверкой IPv6-трафика. `--check ready` мог вернуть 0 при переходном Connecting;
готовность VPN установлена по последующему Connected и T01, не по одному health-check.
Скорость подключения и загрузки ОС не измерялась.

## Не принятые попытки и условия стенда

- Попытка локального DEB через APT с `--no-download` завершилась ошибкой APT
  `Pathname to install is not absolute`. Альтернативный `dpkg -i` завершился успешно;
  первая команда не засчитывается как установка или дефект payload.
- В первой автоматизированной попытке KDE действие accessibility не выключило VPN.
  Последующее нажатие GUI фактически отключило ещё работающую сеть, и T01 дал 0/6.
  Эта неверная последовательность исключена из 72 положительных запросов;
  исходные файлы сохранены. Настоящая кнопка проверена отдельно пользователем, PASS.
- Первый remote-запуск Ubuntu без Xauthority не представлял штатный запуск сеанса.
  Использованы параметры действующей Plasma-сессии. После завершённого onboarding
  приложение штатно стартует в tray; окно открыто поддерживаемым SIGUSR1.
- Первая CLI-команда `status --check` была без обязательного значения и завершилась
  ненулевым кодом; повтор по справке с тремя значениями прошёл.
- Часы Fedora ARM64 отставали примерно на 23 часа. Исправлено время только этой ВМ,
  включён NTP; это коррекция стенда, сервер/проверка TLS не менялись.

Закрытый preview для собственной ВМ. Это не публичный стабильный выпуск и не полный PASS платформенной матрицы. Предыдущие отчёты `.1` и `.10` сохранены.

## Исправления

Перенесён проверенный опытный native backend с отдельным каналом IP-пакетов и AppService для управления. Добавлена архитектура x64 рядом с ARM64. Стандартный CLI сохраняет Wintun; desktop preview переключает собственную службу на установленный WindowsApps-компонент. Системный VPN и UI используют единый контроллер намерений; позднее завершение Connect не должно отменять более новое Disconnect.

Для Aheadscale отключено ленивое установление peer-соединений по умолчанию; явные ENV/MDM-настройки имеют приоритет. Обычный upstream сохраняет серверную политику. Это устраняет ожидание первого полезного пакета при обычном восстановлении.

Первая проверка автозапуска native-пакета `0.1.51.1` завершилась FAIL: после входа UI стартовал, но сеть оставалась Idle. Реальный журнал показал `resolve profile: profile handle is empty` в ResumeOnLaunch. Вместо пустого GetConfig теперь передаются ID и пользователь активного профиля. Регрессия воспроизвела отказ старого кода и прошла с исправлением; настройка DisableAutoConnect учитывается.

Единый EXE проверяет вложенные файлы и удерживает их открытыми без записи/удаления во время выполнения. Длинный EncodedCommand оказался несовместим с ограничением stock NSIS в 1024 символа: вместо усечения используется короткий bootstrap с закреплённым SHA256 загрузчика. При ошибке переключения предусмотрен возврат исходной службы; этот аварийный путь не следует считать полностью проверенным только по успешной установке.

## Автоматические проверки и границы

- `make test-unit`: exit 0, 244 пакета с тестами; SQLite, Go 1.26.7, `TZ=UTC`, `GOMAXPROCS=4`, `GOFLAGS='-buildvcs=false -p=2'`. Полная матрица PostgreSQL/MySQL этим не проверена.
- Целевые тесты с `-race` контроллера и startup прошли; строгая проверка профиля сначала дала RED на прежнем пустом запросе, затем GREEN.
- `make lint GOLANGCI_LINT=/tmp/aheadscale-fix-tools/bin/golangci-lint LINT_BASE=3eef054 LINT_TIMEOUT=4m`: 0 issues (golangci-lint v2.15.0).
- PowerShell parser установленной Windows: ошибок нового desktop-install.ps1 нет.

Preview требует Windows 11 24H2+ и запуск установки от текущего административного пользователя. Не проверены установка из отдельной непривилегированной учётной записи, Windows 10, IPv6 native-трафик, переключение пользователей, полный новый браузерный вход, отрицательные runtime-пробы чужой PFN/SID именно этой сборки и вся CLI-приёмка. ARM64 и macOS этим повтором не проверены. Подпись для публичного распространения и общая приёмка остаются отдельными условиями.

Закрытые первичные измерения: `/home/adnako/VMs/aheadscale/windows11-x64/smoke-20261024/share/` и `native-20261024/`; опубликованы только результаты без токенов и ключей.

Первый холодный запуск стенда потребовал `sg kvm`: пользователь уже был членом
kvm, но процесс агента запущен со старым набором групп. После запуска QEMU с
правильной группой Windows загрузилась. Это не изменение привилегий Windows.
Первичное наблюдение холодной загрузки пересеклось с двумя RDP-подключениями,
поэтому его 95,6 с от ответа NAT/RDP до VPN не считаются чистым замером
скорости native-автозапуска и не дают PASS бюджета T03.

При повторной загрузке Windows процесс UI создан через 108,54 с после события
начала ОС; native-channel.json обновился ещё через 13,24 с. Это наблюдение
отделяет ожидание запуска UI от подключения самого канала, но пока не
доказывает конкретную внутреннюю причину задержки Windows. Финальный повтор с одним RDP-входом приведён ниже; бюджет native не пройден.

## Финальный штатный reboot native 52

В проверяющем скрипте устранён повторный RDP-вход при кратком отказе handshake:
теперь за прогон выполняется только одна авторизация Windows. Connect вручную
не нажимался. Восстановление зафиксировано настоящим X.224 Connection Confirm
через VPN с Ubuntu, а не только статусом приложения.

| Событие | От начала наблюдения |
| --- | --- |
| VPN перестал отвечать | 29,37 с |
| NAT/RDP перестал отвечать | 44,63 с |
| NAT/RDP восстановился | 102,68 с |
| Единственный RDP-вход начат | 102,77 с |
| VPN/RDP восстановился | 181,66 с |

Функциональное автовосстановление — **PASS**, скорость — **FAIL**:
152,29 с недоступности VPN и 78,98 с после первого успешного NAT/RDP.
Нативная сеть поднимается после входа пользователя; обычная CLI-служба
проверялась отдельно до входа. Эти результаты нельзя объединять в один PASS.

Следующая задача для стабильного desktop-выпуска — уменьшить задержку
пользовательского автозапуска, сохранив DisableAutoConnect, управление
автозапуском из UI и безопасное удаление. Глобальные настройки очереди
автозапуска Windows ради теста не менялись.

После финального reboot повторены все шесть запросов: IPv4, FQDN, короткое
имя в обе стороны — 200 с точными маркерами; проверен именно native backend.
Хеш публичного ключа, IP и FQDN совпали с пакетом 51 и обычной `.11`.
Временные HTTP-ответчики после проверки удалены; рабочий VPN оставлен включённым.

Проверенная реализация зафиксирована подписанным локальным коммитом
`d5d8825` в ветке `codex/windows-vpn-finish-20261024`. Подпись GPG проверена;
она не отключалась. 25 октября перед фиксацией повторно выполнен
`make test-unit` с прежним окружением: exit 0. Код переносится в локальный
main вместе с этим отчётом; приватная история на GitHub не отправляется.
Артефакт и резерв патча сохранены отдельно в `native-20261024/artifacts/`.

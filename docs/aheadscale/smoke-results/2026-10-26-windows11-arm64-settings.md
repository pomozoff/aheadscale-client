# Windows 11 ARM64: повторная проверка Settings

Страница `Settings → Network & internet → VPN` работает на установленном комплекте `.18` / MSIX `0.1.61.1`. Прежнее зависание на заставке сейчас **NOT_REPRODUCED**, его причина остаётся неизвестной. Исправление кода или Windows не выполнялось; устранение первопричины не заявляется.

## Условия и результаты

- Windows 11 ARM64, build `26300`; исходник клиента `840c9a9b85b6fbb1a116e54eb88f1709d73d10dc`, тот же пакет, что в [предыдущем отчёте](2026-10-25-windows11-arm64-native-disconnect.md).
- При первой проверке до любых изменений видны строка Aheadscale, Connected и доступная кнопка Disconnect; процесс Settings отвечает. Сохранён снимок именно этого окна.
- Три новых запуска процесса Settings текущего пользователя: каждый раз открыты главная страница и затем VPN, найдены строка Aheadscale и доступная кнопка Disconnect. PID менялся `8644 → 3592 → 9112 → 8652`; все три проверки PASS.
- Реальная кнопка **Disconnect в Settings**: PASS. Служба Idle, системный профиль Disconnected, VPN-адрес отсутствует, ложных перезапусков интерфейса нет.
- **Connect в Aheadscale после системного отключения**: PASS. В конце служба, профиль и строка Settings показывают Connected, адрес `100.88.77.246/16`, callback 53000 не слушает.
- Defender, все профили firewall и постоянное UDP-правило службы включены. Собственные семь диагностических задач удалены.

Обновления, перезагрузка Windows, переустановка/сброс Settings, удаление VPN-профиля и повторная авторизация не выполнялись. Точечное завершение только своего SystemSettings использовано для трёх проверок нового запуска после уже успешной первой проверки; это не доказательство исправления исходного зависания.

Проверены видимость и обновление статуса строки, системный Disconnect и последующий Connect из приложения. Системная кнопка Connect, повторное измерение сетевого обмена, вся последовательность T02, перезагрузка и другие ОС этим прогоном не закрываются. Ранее сетевой обмен проверен в отчёте `.18`.

## RG29 и порядок повторной диагностики

Текущий блокер проверки кнопки снят; RG29 оставить **NOT_REPRODUCED / причина открыта**. Если зависание вернётся, сначала сохранить снимок только Settings, его PID/Responding, точную сборку, состояние профиля и события активации. Отдельно сравнить открытие `ms-settings:` и `ms-settings:network-vpn`. Проверять готовность по строке Aheadscale и доступной кнопке, а не только по наличию процесса. Не записывать успешный системный API как успешный UI-тест. Сброс пользовательских данных, удаление профиля и отключение защиты для этой проверки не нужны.

## Открытый дефект S04 / RG35

В `.23` Ubuntu отсутствует активное подключение Aheadscale в NetworkManager при работающем туннеле. `nmcli` показывает только физическое соединение и loopback. Отдельный NetworkManager VPN-плагин в пакете не заявляется: ранее согласованное отображение реализовывалось через внешнее WireGuard-подключение.

Прежние [KDE](2026-10-19-ubuntu26-arm64-kde.md) / [Xfce](2026-10-19-ubuntu26-arm64-xfce.md) отчёты относятся к другой исходной рабочей копии. В `aheadscale-client.worktrees/client-builds` обнаружены незакоммиченные изменения `network_manager_visibility_linux.go`, вызова из engine, Linux-имени интерфейса и связанных файлов; в общем исходнике `.23` их нет. Ранее закрытая сверка наличия всех принятых исправлений была преждевременной — пункт дорожной карты открыт повторно. Старая рабочая копия сохранена без изменений. Требуется отдельная интеграция с RED/GREEN, сохранением DNS/WireGuard-параметров и повтором Ubuntu/Fedora; до этого S04 Linux — FAIL.

## Готовность времени и ошибки оснастки

В конце прогона обнаружено отставание Ubuntu примерно на 43 минуты: chrony получал время от существующего NTS-источника, но большая поправка применялась постепенно. Выполнен `chronyc makestep`; итоговые `chronyc tracking` и `NTPSynchronized=yes` подтверждают синхронизацию. Ключ/IP и Connected сохранились, приватный SSH через Windows повторно прошёл после коррекции. Первый немедленный assert готовности после скачка часов не прошёл; последующая проверка сохранена отдельно. Серверы времени и параметры их аутентификации не менялись. Проверки истечения токенов/сессий и времени подключения этим прогоном не принимаются.

Первый Windows HTTP-сценарий не запустился из файла из-за ExecutionPolicy Restricted; выполнен проверенный командный запуск, политика осталась Restricted. Ранняя диагностическая команда ожидала старое имя `Aheadscale Prototype`; фактическое имя — `Aheadscale`. После GUI-цикла истёк 20-минутный срок временного HTTP-сервиса Ubuntu; повтор выполнялся после локального подтверждения готовности обоих сервисов. Таймаут наблюдателя уборки Windows проверен нативными `schtasks`/`netsh`: действия уже завершились. Первые отказы оснастки сохранены отдельно и не засчитаны как успешный T01 или сбой VPN.

## Завершение и оставшаяся приёмка

Временные HTTP-сервисы/слушатели, четыре задачи Windows, узкое временное TCP-правило и тестовый SFTP-файл удалены. Три профиля Windows Firewall остались включены. Обе ВМ оставлены Connected; постоянное UDP-правило VPN-службы не менялось.

Не выполнены: T03-OS/reboot, смена сети/NAT, принудительный Relay и возврат, изоляция аккаунтов, чистые CLI-установки и полный CLI up/down, uninstall/reinstall, UI Settings и полный набор тем/масштабов. P01–P06 по решению владельца отложены. Успешный P2P этой пары не закрывает T05/T06 и другие ОС/архитектуры.

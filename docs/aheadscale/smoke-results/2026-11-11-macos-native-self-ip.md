# macOS native: доступ к собственному IPv4

Задача: AHEAD-18. Согласованный владельцем способ: локальная доставка исходящих пакетов с source=destination=назначенный IPv4 текущей сессии через NEPacketTunnelFlow.writePackets. Прочие исходящие пакеты сохраняют WireGuard-путь. Команды изменения маршрутов не добавлены.

## Нативное воспроизведение до исправления

macOS 27.0.1 ARM64, подписанное расширение 0.1.0/3, native.1. HTTP-сервер на временном порту, привязка 0.0.0.0: запрос через 127.0.0.1 вернул HTTP/1.0 200 OK, через собственный 100.88.213.250 завершился timeout за 3 секунды. Сервер остановлен после опыта. Маршрут собственного адреса — utun4/LOCAL. На utun4 виден исходящий ICMP source=destination=100.88.213.250 без ответа.

Ранее на этом же native-комплекте подтверждены ping и TCP22 в обе стороны с Ubuntu 100.88.19.208, приватные имена, Disconnect/reconnect без повторного входа. Это не доказывает исправления self-IP.

## Регрессии и Actions

- RED: [42912213678](https://github.com/pomozoff/aheadscale-client/actions/runs/42912213678), source 92de764. TCP/ICMP self-пакеты уходили в канал WireGuard вместо локальной доставки. Регрессия компилировалась и падала на нужном поведении.
- Промежуточный 42912797480: тест malformed использовал допустимый длинный IPv4-заголовок; тест уточнён на IHL меньше минимальных 20 байт.
- GREEN: [42912853963](https://github.com/pomozoff/aheadscale-client/actions/runs/42912853963), source 6e4be2b4e6deaf5661f02b7368cac995f68bf909. 60 тестов, 1 прежний skip, 0 ошибок; ARM64 bundle собран.

Проверены TCP/ICMP self-delivery через реальный PacketSocket и подменённую OS-границу, сохранность пути чужих source/destination, malformed IPv4, поздний callback после Cancel. Входящая доставка и локальная доставка используют одну блокировку с stop и обрабатывают отказ writePackets. Источник собственного адреса — проверенная конфигурация текущей сессии.

# Linux `.26`: перезагрузка и сохранение настроек

28 октября 2026 года. Продолжение [приёмки пакетов](2026-10-28-linux26-packages.md),
сценарии R01/R03/R04 и C09/C13 существующего тест-плана.
Это целевая проверка lifecycle, не приёмка всей матрицы UI/CLI.
**Результат:** headless reboot с ON/OFF, переходы Desktop ↔ CLI на обеих ARM64 ОС
и сохранение OFF при удалении/переустановке приняты; **42/42 HTTP/DNS PASS**.
Самостоятельное завершение graceful reboot Ubuntu Desktop остаётся неподтверждённым.

## Проверяемые сборки

Используются прежние public-пакеты из `38af543889518c0956fc0f2c46564d7bc990174c`:
CLI/UI `0.80.0-aheadscale.26`, DEB `0.80.0~aheadscale.26`,
RPM `0.80.0-0.aheadscale.26.1`. Новые сборки и обновления ОС не запускались.
SHA256 установщиков сверяется с сохранёнными CI-файлами; внутренний канал,
публичная подпись и CDN этим прогоном не принимаются.

На Desktop файлы `ui-preferences.json` и `autostart/aheadscale.desktop`

Время загрузки ОС/UI и скорость VPN не измеряются: исследование задержек отложено.

## CLI x64: удаление и повторная установка

Выполнено настоящее `dpkg --remove aheadscale`, затем установка того же CLI DEB.
Между операциями отсутствовали CLI/UI и unit службы; VPN-интерфейс и собственные
маршруты удалены, обычный маршрут и systemd-resolved сохранены. Обращение Fedora
к прежнему VPN-IP завершилось отказом. Два файла регистрации сохранили SHA256.
Установка вернула active/enabled и прежнюю версию без графических зависимостей.

Отдельно через штатные команды задан `DisableAutoConnect=true`, выполнены Down,
удаление и повторная установка. Новый SHA256 профиля, обусловленный явным выбором
OFF, сохранился на обоих этапах; служба active/enabled, management Disconnected,
VPN-IP отсутствует, флаг остался true. OFF не подменяется отключением systemd:
служба доступна клиенту, но не должна сама поднимать VPN.
После ещё одной настоящей перезагрузки OFF сохранился: новый boot ID,
Disconnected, нет VPN-IP, те же SHA256 и `DisableAutoConnect=true`.
Затем исходный ON возвращён штатной командой; полный SHA256 профиля снова совпал
с исходным, новое устройство/SSO не потребовались, T01 прошёл.

## Desktop ↔ CLI и повторная установка ARM64

На Fedora и Ubuntu штатно завершён GUI, установлен CLI-вариант `.26`.
Проверены отсутствие `/usr/bin/aheadscale-ui` и UI-процесса, active/enabled,
неизменность системных профилей, пользовательских предпочтений и XDG autostart.
На Fedora DNF swap удалял и устанавливал ровно по одному пакету;
Debian-варианты используют одно имя `aheadscale` и меняются через `dpkg -i`.
В CLI-режиме обе ВМ прошли по шесть запросов T01 с headless x64.

Далее через Down → Up с `--disable-auto-connect` → Down выбран явный OFF.
Возврат Desktop сохранил новый SHA256 профиля и пользовательские файлы;
служба active/enabled, management Disconnected, VPN-IP/активной строки NM нет.

Desktop действительно удалён целиком на обеих ВМ: нет CLI/UI и unit, только
обычные сетевые адреса/подключения; данные и предпочтения сохранены.
Повторная установка того же Desktop вернула компоненты и сохранила OFF.
Проверка обычного HTTPS без VPN дала HTTP 200. Обращение CLI x64 к каждому
выключенному ARM64 VPN-IP отказало с curl exit 7, как и ожидалось.

Исходный ON возвращён штатно, GUI запущен в существующих пользовательских
сеансах без графических обходов. На обеих ВМ полный SHA256 системного профиля
вернулся к исходному; предпочтения и XDG autostart не изменились. Хеш работающего
`/proc/PID/exe` GUI совпал с `/usr/bin/aheadscale-ui`; оба узла Connected с прежними
IP/FQDN, `Aheadscale:wireguard:activated`, без SSO. Финальный T01 прошёл.

Это сохранение выбора VPN ON/OFF и файлов автозапуска. Отдельный выключенный
выбор запуска GUI и новый графический вход именно после последней переустановки
не проверялись; сохранённый XDG-файл не подменяет этот функциональный сценарий.

## Ограничения оснастки

- Первая команда удаления ошибочно использовала имя `aheadscale-cli` из суффикса
  файла. DEB содержит пакет `aheadscale`: удаления не произошло, прогон не принят.
  Повтор выполнен по имени из метаданных с проверкой отсутствия программы/unit.
- Передача ARM64-пакетов превысила первоначальный тайм-аут. Неполные файлы нельзя
  устанавливать; недостающие файлы переданы повторно, все четыре SHA256 совпали
  с CI до установки.
- В проверке HTTPS после удаления был ошибочно выбран отсутствующий путь
  `/.well-known/openid-configuration`: сервер вернул 404, команда остановилась
  до переустановки. Проверка повторена на существующем `/` с HTTP 200,
  переустановка завершена. Это ошибка тестового URL, а не сбой сети/установщика.
- Первая операторская команда возвращения GUI имела синтаксическую ошибку
  подстановки переменной окружения. Исправлена только команда запуска;
  бинарники и графические настройки не менялись. Принят реально работающий GUI.
- Краткая недоступность SSH сама по себе не объявляется дефектом VPN.
- RG39 не исправляется; этот прогон не проверяет изменение параметров через
  повторный `up` уже подключённого устройства.

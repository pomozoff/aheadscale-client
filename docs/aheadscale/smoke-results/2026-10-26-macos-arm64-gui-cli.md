## RG30: машинный статус с неизвестными датами

На `.5` отсутствующее время обновления соседа превращалось в `0000-12-31T16:07:02-07:52`: перевод нулевого Go-времени в локальный отрицательный часовой пояс переносил дату в год 0. Стандартный YAML-парсер Python отвергал документ. Такая же конверсия применялась к времени WireGuard handshake.

Исправление сохраняет нулевое время без локализации; известные даты по-прежнему переводятся в локальный часовой пояс. Регрессия `TestStatusSerializationPreservesUnknownPeerTimestampsInLocalTimezones` проходит через настоящий mapper и сериализацию JSON/YAML для UTC−8, UTC и UTC+3. На прежней реализации получен RED с годом 0, после исправления — GREEN:

```bash
go test -tags devcert -race ./client/status
PATH=/tmp/aheadscale-fix-tools/bin:/tmp/aheadscale-fix-tools/go/bin:$PATH make lint GOLANGCI_LINT=/tmp/aheadscale-fix-tools/bin/golangci-lint LINT_BASE=030e2bd
```

Тесты пакета прошли; линтер — 0 issues. После установки CI-пакета `.19` его настоящий YAML разбирается `yaml.safe_load`, дата года 0 отсутствует, Connected и идентичность устройства сохранены. Результат не переносится на ещё не пересобранные Ubuntu/Windows.

## Открытые наблюдения и ограничения

- **Обращение к собственному VPN IPv4 на macOS не работает:** HTTP к `100.88.213.250:8766` на самой macOS завершается тайм-аутом на `.5` и `.19`, хотя Ubuntu получает от того же слушателя HTTP 200. Повтор с явным исходным VPN IP также отказал. Маршрут к собственному адресу указывал utun; первопричина пока не установлена. Не смешивать это с успешным обменом двух устройств; маршруты и firewall для обхода не менялись.
- В справке унаследованной опции анонимизации есть текст `non-netbird.io domains`. Это открытое замечание к справке; механическая замена текста без проверки поведения анонимизации не выполнялась.
- Контроль `https://aheadscale.ru` возвращал HTTP 200 до и после down, TLS проверен штатно. `https://example.com` завершался тайм-аутом и до, и после отключения: общий интернет-тест по нему не засчитан; вывод о причине не делается.
- Не проверены C03 с новой регистрацией без GUI, C04 setup key, полный C06 с выключением соседа, C10–C12, C15–C24 и изоляция аккаунтов. Наличие пяти уже зарегистрированных устройств не обходилось удалением или клонированием ключей.
- Windows ARM64 в этом продолжении: SSH завис на обмене banner, CLI-пробы не начались. Fedora также недоступна через прежний SSH-проброс. Это ограничения доступа к стендам, не результаты тестирования VPN. Windows x64 в этой серии не тестировалась.

## Ошибки средств проверки

Первые вспомогательные Ruby-программы останавливались из-за интерполяции heredoc и US-ASCII для русского текста. Первый вариант unit-теста вызывал избыточный mapper без обязательного ManagementState; после исправления тестового входа отдельно подтверждён реальный RED года 0. Ранний оператор up чрезмерно требовал буквальный суффикс в `scutil --dns`, хотя системное разрешение обоих имён и весь T01 уже работали; этот операторский отказ не засчитан как дефект DNS. Первый оператор очистки Ubuntu не запускался из-за нулевого байта в исходнике, затем исправлен и выполнен. Исходные результаты сохранены отдельно от повторов.

Доступ к заведомо работающему Linux HTTP-сервису прекращён, обычный HTTPS вернул 200. После выдержки отключение сохранилось. ## Отмена Connecting — PASS после восстановления стенда

Во время первого оператора отмены Windows перезагрузилась сама; владелец подтвердил отсутствие ручного reboot. Этот оператор не успел записать результат. Команды reboot, uninstall и install в этом этапе до аварии не выдавались. Отмена не объявляется PASS либо доказанным дефектом Aheadscale.

WER 1001 и Kernel-Power 41 подтверждают bugcheck 0x7e (0x1000007e в дампе), access violation 0xc0000005, PC fffff801f019b52c. Дамп 102726-10187-01.dmp, SHA256 b1e2e597d801a1931da25e142e473404336ecadd01bf93f7ac8925c63d30e4d0. Официальный CDB Microsoft после проверки подписи указал модуль viogpudo.sys, смещение 0xb52c; в стеке также viogpudo+0xb524. Установленный драйвер — Red Hat VirtIO GPU DOD controller, версия 22.7.38.43, подпись Microsoft действительна. [Исходники графического драйвера VirtIO](https://github.com/virtio-win/kvm-guest-drivers-windows/blob/master/viogpu/viogpudo/viogpudo.cpp), [официальный WinDbg](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/).

Точка исключения подтверждена в графическом драйвере ВМ; первопричина повреждения памяти и связь с конкретным действием не установлены. Драйвер/Windows не обновлялись, защитные механизмы не отключались. Сбой не переносится в список подтверждённых продуктовых регрессий. Для повторения оператор сохраняет промежуточные шаги до Connect/Cancel.

Время сессии дампа 19:44:40.856 +03:00, uptime 50:17.152, соответствует исходной загрузке 18:54:25 +03:00. Часть System events после reboot записана с отклонением часов +4 часа; нельзя смешивать эти отметки для измерения времени VPN. После аварии новая загрузка 19:49:07 +03:00 и штатный запуск GUI восстановили прежний Connected без SSO. Это не отдельный PASS автозапуска: GUI запускался вручную оснасткой.

Повтор после reboot встретил только оболочку Settings без кнопок VPN, как в RG29. CLI/native/GUI Connected при этом согласованы. Запрошен активный экран и открытая страница VPN; отсутствие кнопок при неподтверждённом состоянии дисплея не объявляется новым зависанием.

Повтор с подтверждённо открытой владельцем страницей VPN завершён: настоящая кнопка Cancel наблюдалась при Connecting и нажата в 20:16:28 +03:00. В 20:16:30 получены Idle/native Disconnected/GUI Off без IPv4; после 12 секунд состояние сохранилось. Отрицательный HTTP дал exit 28, обычный HTTPS — 200. GUI Connect в 20:16:54 восстановил прежние ключ/IP/FQDN без SSO. Сохранён cancel-system-pass.json, pass=true, observedCancel=true, sameIdentity=true. Нового сбоя ОС в этом повторе не наблюдалось. Это закрывает данный живой R05/RG10 на ARM64, сохраняя аварийную попытку как отдельное свидетельство окружения.

## Disabled full remove/reinstall и вход после reboot — PASS

Первый прогон отклонён из-за ошибки оснастки: замена Start-Process -Wait на ожидание только исходного процесса не дождалась дочернего скопированного деинсталлятора NSIS. Переустановка пересеклась с удалением службы и показала ошибку PathName. Это не продуктовый FAIL: ошибочный прогон сохранён отдельно, штатный пакет восстановлен, ожидание дерева процессов возвращено; перед новой установкой добавлена обязательная проверка фактического удаления компонентов.

Повтор завершился uninstall/install exit 0. Между ними отсутствовали служба, CLI и native MSIX, отсутствовали собственные Task/Run; после установки служба Automatic/Running. SHA256 default.json, active_profile.json и ui-preferences.json совпали на всех трёх этапах. Выключенный автозапуск сохранился. Свидетельства: disabled-reinstall.json.

После проверки отсутствия WindowsUpdate/CBS RebootPending выдана отдельная штатная команда reboot с причиной Aheadscale ARM final controlled startup acceptance. Новая загрузка подтверждена CIM: 20:26:52.6042070 +03:00. В пассивном снимке 20:27:38 до входа GUI отсутствует, CLI Idle, задача запуска отсутствует/disabled, Connect on Startup сохранён ON. Владелец вошёл в 20:32 +03:00. Пассивная проверка 20:33:04 +03:00 (28 октября 00:33:04 +07:00) подтвердила активный console-сеанс: GUI отсутствует, CLI Idle, native Disconnected, startup disabled. Все три SHA256 совпали с before/removed/after reinstall; Aheadscale вручную не открывался. Случай OFF после полного удаления/установки и настоящей загрузки принят.

## GUI ON / Connect on Startup OFF — GUI и upgrade PASS

В настоящих настройках приложения через UI Automation переключены Connect on Startup → Off и Launch Aheadscale UI at Login → On. Меню использует ExpandCollapsePattern, а не InvokePattern; первый неподдерживаемый вызов оснастки не изменил настройки и не считается дефектом клиента. В успешном повторе состояния обоих переключателей, DisableAutoConnect=true и enabled-задача запуска сверены, затем настоящий GUI Disconnect привёл к согласованным Idle/native Disconnected/GUI Off без VPN IPv4.

Установка того же EXE поверх завершилась exit 0: оба выбора сохранены, SHA256 трёх конфигураций до и после совпали. Свидетельства: configure-auto-off.json, auto-off-upgrade.json. Перед второй контролируемой перезагрузкой снова проверено отсутствие ожидающих WindowsUpdate/CBS обновлений; CIM подтвердил вторую новую загрузку 20:38:31.4717160 +03:00 (28 октября 00:38:31 +07:00). Пассивный снимок 20:42:55 +03:00 до входа: startup enabled, DisableAutoConnect=true, GUI отсутствует, VPN Idle. После обычного входа предстоит пассивно подтвердить появление GUI без подключения VPN; текущий снимок до входа не считается PASS.

## R05: системные Disconnect и Connect — PASS

В настоящем Windows Settings → VPN нажаты Disconnect и Connect через UI Automation. После Disconnect одновременно получены CLI Idle, native Disconnected, GUI Off и отсутствие VPN IPv4. Доступ к заведомо работающему Linux HTTP-сервису прекращён, обычный HTTPS вернул 200. После выдержки отключение сохранилось. Системный Connect без SSO восстановил Connected, GUI On, прежние IP/FQDN и SHA256 публичного ключа.

По три исходящих HTTP-запроса к Linux до/после цикла прошли по VPN IP, полному и короткому имени, с проверкой HTTP 200, точного тела и remote_ip. Это шесть исходящих запросов, не новый полный двусторонний T01. Сырой журнал: system-cycle2.json, время гостя 19:40:45–19:41:11 +03:00 (в Красноярске 23:40:45–23:41:11 +07:00).

## Отмена Connecting — PASS после восстановления стенда

Во время первого оператора отмены Windows перезагрузилась сама; владелец подтвердил отсутствие ручного reboot. Этот оператор не успел записать результат. Команды reboot, uninstall и install в этом этапе до аварии не выдавались. Отмена не объявляется PASS либо доказанным дефектом Aheadscale.

WER 1001 и Kernel-Power 41 подтверждают bugcheck 0x7e (0x1000007e в дампе), access violation 0xc0000005, PC fffff801f019b52c. Дамп 102726-10187-01.dmp, SHA256 b1e2e597d801a1931da25e142e473404336ecadd01bf93f7ac8925c63d30e4d0. Официальный CDB Microsoft после проверки подписи указал модуль viogpudo.sys, смещение 0xb52c; в стеке также viogpudo+0xb524. Установленный драйвер — Red Hat VirtIO GPU DOD controller, версия 22.7.38.43, подпись Microsoft действительна. [Исходники графического драйвера VirtIO](https://github.com/virtio-win/kvm-guest-drivers-windows/blob/master/viogpu/viogpudo/viogpudo.cpp), [официальный WinDbg](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/).

Точка исключения подтверждена в графическом драйвере ВМ; первопричина повреждения памяти и связь с конкретным действием не установлены. Драйвер/Windows не обновлялись, защитные механизмы не отключались. Сбой не переносится в список подтверждённых продуктовых регрессий. Для повторения оператор сохраняет промежуточные шаги до Connect/Cancel.

Время сессии дампа 19:44:40.856 +03:00, uptime 50:17.152, соответствует исходной загрузке 18:54:25 +03:00. Часть System events после reboot записана с отклонением часов +4 часа; нельзя смешивать эти отметки для измерения времени VPN. После аварии новая загрузка 19:49:07 +03:00 и штатный запуск GUI восстановили прежний Connected без SSO. Это не отдельный PASS автозапуска: GUI запускался вручную оснасткой.

Повтор после reboot встретил только оболочку Settings без кнопок VPN, как в RG29. CLI/native/GUI Connected при этом согласованы. Запрошен активный экран и открытая страница VPN; отсутствие кнопок при неподтверждённом состоянии дисплея не объявляется новым зависанием.

Повтор с подтверждённо открытой владельцем страницей VPN завершён: настоящая кнопка Cancel наблюдалась при Connecting и нажата в 20:16:28 +03:00. В 20:16:30 получены Idle/native Disconnected/GUI Off без IPv4; после 12 секунд состояние сохранилось. Отрицательный HTTP дал exit 28, обычный HTTPS — 200. GUI Connect в 20:16:54 восстановил прежние ключ/IP/FQDN без SSO. Сохранён cancel-system-pass.json, pass=true, observedCancel=true, sameIdentity=true. Нового сбоя ОС в этом повторе не наблюдалось. Это закрывает данный живой R05/RG10 на ARM64, сохраняя аварийную попытку как отдельное свидетельство окружения.

## Disabled full remove/reinstall и вход после reboot — PASS

Первый прогон отклонён из-за ошибки оснастки: замена Start-Process -Wait на ожидание только исходного процесса не дождалась дочернего скопированного деинсталлятора NSIS. Переустановка пересеклась с удалением службы и показала ошибку PathName. Это не продуктовый FAIL: ошибочный прогон сохранён отдельно, штатный пакет восстановлен, ожидание дерева процессов возвращено; перед новой установкой добавлена обязательная проверка фактического удаления компонентов.

Повтор завершился uninstall/install exit 0. Между ними отсутствовали служба, CLI и native MSIX, отсутствовали собственные Task/Run; после установки служба Automatic/Running. SHA256 default.json, active_profile.json и ui-preferences.json совпали на всех трёх этапах. Выключенный автозапуск сохранился. Свидетельства: disabled-reinstall.json.

После проверки отсутствия WindowsUpdate/CBS RebootPending выдана отдельная штатная команда reboot с причиной Aheadscale ARM final controlled startup acceptance. Новая загрузка подтверждена CIM: 20:26:52.6042070 +03:00. В пассивном снимке 20:27:38 до входа GUI отсутствует, CLI Idle, задача запуска отсутствует/disabled, Connect on Startup сохранён ON. Владелец вошёл в 20:32 +03:00. Пассивная проверка 20:33:04 +03:00 (28 октября 00:33:04 +07:00) подтвердила активный console-сеанс: GUI отсутствует, CLI Idle, native Disconnected, startup disabled. Все три SHA256 совпали с before/removed/after reinstall; Aheadscale вручную не открывался. Случай OFF после полного удаления/установки и настоящей загрузки принят.

## GUI ON / Connect on Startup OFF — GUI, upgrade и reboot PASS

В настоящих настройках приложения через UI Automation переключены Connect on Startup → Off и Launch Aheadscale UI at Login → On. Меню использует ExpandCollapsePattern, а не InvokePattern; первый неподдерживаемый вызов оснастки не изменил настройки и не считается дефектом клиента. В успешном повторе состояния обоих переключателей, DisableAutoConnect=true и enabled-задача запуска сверены, затем настоящий GUI Disconnect привёл к согласованным Idle/native Disconnected/GUI Off без VPN IPv4.

Установка того же EXE поверх завершилась exit 0: оба выбора сохранены, SHA256 трёх конфигураций до и после совпали. Свидетельства: configure-auto-off.json, auto-off-upgrade.json. Перед второй контролируемой перезагрузкой снова проверено отсутствие ожидающих WindowsUpdate/CBS обновлений; CIM подтвердил вторую новую загрузку 20:38:31.4717160 +03:00 (28 октября 00:38:31 +07:00). Пассивный снимок 20:42:55 +03:00 до входа: startup enabled, DisableAutoConnect=true, GUI отсутствует, VPN Idle. Этот снимок до входа не считался PASS. Завершение 28 октября: по отдельному запросу владельца настроен автоматический вход Windows через подписанный Microsoft Autologon ARM64; пароль введён владельцем только в локальном окне. Проверены AutoAdminLogon=1, локальный adnako и отсутствие значения DefaultPassword в Winlogon; пароль не читался и в скрипты не передавался.

После очередной контролируемой перезагрузки CIM подтвердил boot 28 октября 06:10:06.062738 +03:00 (10:10:06 +07:00). Пассивный снимок 06:11:25 +03:00: console-сеанс adnako Active после автоматического входа, один автоматически запущенный aheadscale-ui.exe в Session 1 (PID 2132), startup enabled, DisableAutoConnect=true, CLI Idle/native Disconnected без VPN IPv4. Все три SHA256 совпали с принятым overlay; GUI/Connect оснасткой до снимка не запускались. Случай GUI ON / auto-connect OFF после новой загрузки принят. Главное окно при этой пассивной проверке специально не открывалось.

После принятия случая через GUI возвращены исходные Launch Aheadscale UI at Login OFF / Connect on Startup ON, затем выполнен ручной Connect. В 06:13:11 +03:00 (10:13:11 +07:00) получены согласованные CLI/native Connected/GUI On, прежние ключ/IP/FQDN без SSO. Автологин Windows остаётся включённым по запросу владельца и не зависит от автозапуска Aheadscale.

## Финальный T01 и сохранность устройства — PASS

После возврата исходных переключателей прошли шесть HTTP/DNS-запросов в обе стороны между Windows ARM64 и чистым Linux CLI x64: по VPN IPv4, полному FQDN и короткому имени. Проверены системное разрешение IPv4, точное синтетическое тело, HTTP 200 и настоящий remote_ip; прокси не использовался. Финальные Windows-запросы — 28 октября 06:14:39 +03:00 (10:14:39 +07:00), обратная серия Linux — 03:16:04 UTC (10:16:04 +07:00). Свидетельства: final-outgoing.json, final-incoming.json. Вместе с шестью исходящими запросами R05 это 12 положительных приватных HTTP в данном продолжении; локальные пробы готовности HTTP-сервиса не прибавлялись.

Окончательный пассивный снимок после уборки подтвердил Connected, прежние IP/FQDN, тот же процесс GUI и исходные Launch UI at Login OFF / Connect on Startup ON. Public key SHA256 совпал с исходным в финальной сетевой серии. active_profile.json и ui-preferences.json побайтно совпали с исходными.

Первоначальная проверка полного побайтного возврата default.json после GUI-изменений не прошла; причина установлена без изменения рабочего файла. GUI сохранил шесть необязательных полей явно: EnableSSHRoot, EnableSSHSFTP, EnableSSHLocalPortForwarding, EnableSSHRemotePortForwarding, DisableSSHAuth — false; SSHJWTCacheTTL — 0 вместо исходных null. Возврат только этих шести полей в null в памяти восстановил в точности исходный SHA256 CA46EF39…ADA7. Сервер GetConfig выдаёт для отсутствующих флагов false, defaultJWTCacheTTL=0. Других различий нет; секреты и полный конфиг с ВМ не копировались. Это сериализация значений по умолчанию, не принятый продуктовый дефект. Точные SHA256 при reinstall/overlay сравнивались до осознанных изменений GUI и действительно совпали. Свидетельство: config-null-roundtrip.json.

## Итог текущего этапа и уборка

Три выбранных сценария завершены: настоящие системные Connect/Disconnect/Cancel; disabled full remove/reinstall с новой загрузкой и входом; GUI ON / Connect on Startup OFF через GUI/overlay/новую загрузку. Исходные переключатели Aheadscale возвращены, действующее устройство Connected. Это завершение согласованного этапа, а не всей платформенной матрицы: чистая установка, полный UI/CLI по перечням и публичная подпись остаются отдельными задачами.

По просьбе владельца Windows ARM теперь входит автоматически под adnako. Реальная перезагрузка это подтвердила; AutoAdminLogon остаётся 1, конечного AutoLogonCount нет, открытого DefaultPassword в Winlogon нет. Пароль вводился владельцем в подписанный [Microsoft Autologon](https://learn.microsoft.com/en-us/sysinternals/downloads/autologon), только внутри ВМ. Настройка автологина сохраняется после удаления самой временной утилиты.

Удалены временный Windows HTTP-процесс, его узкое TCP-правило, ровно три собственные задачи QA и 39 файлов рабочего каталога (1578109 байт), включая Autologon64a.exe и копию дампа. Ярлык временной утилиты также удалён. Ранее отдельно убраны копия EXE (38241033 байт), переносимый отладчик и кеш символов. Linux HTTP-процесс и каталог остановлены/удалены, порт освобождён. Последняя квитанция уборки из ВМ забрана и удалена. Постоянное продуктовое UDP-правило, рабочие конфигурации/ключи, штатная утилита запуска, исходный системный дамп, данные ВМ и нужные дистрибутивы сохранены.

После уборки служба Running, VPN Connected; автологин Windows включён. Закрытые свидетельства сохранены в указанном стабильном каталоге, в Git находятся только русскоязычные отчёты/планы. Временные локальные рабочие копии и файлы оснастки удаляются после подписанного переноса этих документов в main.

# Проверка шестого устройства и повтор Windows `.23`

27 октября 2026 года. Исходники клиента и серверная конфигурация не менялись.

## Шестое устройство: реальный отказ

Исходная сеть содержала пять зарегистрированных устройств, включая offline.
Существующая Ubuntu ARM64 `.24` показывала Connected и четыре соседних записи.
Новый чистый Ubuntu Server 24.04.5 x64 с CLI `.24` прошёл авторизацию того же
аккаунта через `up --no-browser` / Device Authorization Flow в браузере Windows.
Локальный callback и SSH-туннель этому потоку не нужны; подготовленный туннель
после выяснения фактического потока удалён.

После подтверждения нового кода CLI вернул:

```text
Error: daemon up failed: sso login failed: waiting sso login failed with: rpc error: code = PermissionDenied desc = Aheadscale Free supports up to 5 registered devices; remove a device before adding another
```

Новый узел остался NeedsLogin, VPN-IP пуст, доступного каталога нет.
Существующая Ubuntu по-прежнему Connected и видит ровно пять устройств вместе
с собой. На работающем сервере подтверждено только `AS_SELF_REGISTRATION=true`;
секреты контейнера не выгружались, лимит не менялся. Шестая запись не появилась.

**Ограничение — PASS для одиночной живой попытки. Понятность — частично:**
смысл лимита и действие присутствуют, но английское сообщение обёрнуто длинным
техническим префиксом. Это не приёмка удобного русскоязычного GUI-сообщения.
Целевой пользовательский текст: «Достигнут лимит бесплатного тарифа: 5 устройств.
Удалите ненужное устройство в аккаунте и повторите подключение». Этот текст
пока не реализован; нельзя выдавать перевод за увиденное сообщение.

Первый одноразовый код истёк до завершения входа. Старую попытку отменили,
подготовили свежую и подтвердили её отдельно. Страница Device Authorized
подтверждает авторизацию аккаунта; она не означает успешную регистрацию
VPN-узла. Доказательство отказа — фактический результат CLI и каталог.
Конкурентное добавление и GUI-отказ шестому устройству отдельно не проверены.

## Как освободить слот

1. Открыть `https://aheadscale.ru/peers` под владельцем аккаунта.
2. В списке Peers найти ненужное устройство и открыть его меню `⋮`.
3. Выбрать Delete, сверить имя в диалоге и подтвердить Delete.

Путь и подтверждение сверены по `PeerActionCell.tsx` / `PeerProvider.tsx`
действующего репозитория dashboard. Встроенный графический Control Center
также имеет удаление узла с подтверждением; простая инструкция выше относится
к списку Peers. Если Delete недоступен, проверить права текущего пользователя.
Выключенные устройства учитываются в лимите. Disconnect и удаление приложения
не освобождают серверную запись. Чужие устройства в этой проверке не удалялись;
повтор успешной регистрации после освобождения слота ещё ожидается.

## Уточнение Windows: автоподключение и установка поверх

На неизменённом `.23` / native `0.1.62.1` выполнен новый штатный reboot.
LastBootUpTime изменился с 12:45:02 на 13:51:07 по UTC+3; GUI автоматически
создан (PID 5720), Connected и системный VPN Connected, ключ/IP/FQDN прежние.
Ручного запуска GUI и Connect до фиксации результата не было. Это один
успешный повтор; прежний Idle после другого reboot не объявляется исправленным.
Скорость загрузки ОС не измерялась; отдельный сетевой T01 после этого reboot
ещё не завершён.

Тот же единый EXE `.23` с прежним SHA256 установлен поверх Connected-клиента
при включённом запуске при входе. Exit 0, Connected и идентичность сохранились.
До установки была включённая задача; после неё задачи нет, но есть собственная
запись Run для `C:\Program Files\Aheadscale\native\aheadscale-ui.exe`.
По исходнику установщик возвращает выбор через Run, а штатный helper умеет
мигрировать её в задачу. Поэтому вывод предыдущего отчёта «нет задачи — значит
автозапуск потерян» был преждевременным. Для полного удаления/повторной установки
в старой оснастке наличие Run не записывалось: потеря автозапуска не доказана.
Нужен фактический вход/новый reboot после переустановки, проверка Run и
StartupApproved вместе с задачей, а также сохранение явно выключенного выбора.

Ссылки/коды входа, приватный одноразовый SSH-ключ и исходные журналы авторизации

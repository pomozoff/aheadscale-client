# Linux `.24`: перезагрузка и начало CLI-проверок

Дата: 26 октября 2026, 20:57 MSK (27 октября в ранее принятом для серии Asia/Krasnoyarsk). Продолжение [сетевого smoke Ubuntu/Fedora](2026-10-27-linux24-ubuntu-fedora-network.md). Сборки и исходники не менялись.

## Перезагрузка: пока BLOCKED

Перед началом обе ARM64-ВМ Connected, служба и SSH включены в автозапуск; сохранены boot ID, публичный ключ, адреса, порт `51830`, fwmark `0x1be00` и пользовательский `aheadscale.desktop` с `Exec=/usr/bin/aheadscale-ui`. На обеих ВМ предварительно проверен SSH через VPN с соседней машины с проверкой прежнего ключа сервера. Приватный ключ SSH остаётся на Mac mini.

Ubuntu приняла `sudo systemctl reboot`, SSH-команда завершилась с кодом 0. После этого обычный проброс `2222` не получает SSH banner, а резервный маршрут через Fedora к VPN-адресу Ubuntu возвращает `No route to host`. Повторная проверка обычного SSH также не прошла. Новый boot ID, состояние службы и локальный адрес Ubuntu прочитать не удалось. Владелец получил запрос о том, что видно на консоли ВМ.

Это **не PASS T03-OS** и пока не доказанный дефект Aheadscale: без консоли нельзя отделить незавершённую загрузку, смену локального адреса и отказ автоподключения. Fedora оставлена работающей, её перезагрузка отложена до восстановления Ubuntu. После восстановления сначала проверить службу и передачу данных без входа в рабочий стол, затем обычный вход владельца и автозапуск GUI. Автовход и обход блокировки не включались.

Первый сбор результатов остановился в самой оснастке: YAML-парсер преобразовал дату в datetime, которую JSON-сериализатор не принимал. Сериализация исправлена, весь этот набор повторён и проверки прошли. Это не ошибка CLI.

Статически проверен отдельный ARM64 CLI DEB: пакет aheadscale `0.80.0~aheadscale.24`, зависимости только iproute2/iptables; GUI-бинарника в содержимом нет. Это проверка содержимого пакета, **не C01 на чистой системе**. В справке есть `up --no-browser` и `--setup-key-file`, но реальный headless-вход C03/C04 ещё не выполнен.

В справке status остались upstream-примеры `peer-b.netbird.cloud` и описание anonymize с `netbird.io`. Это видимый остаток брендинга, записан для последующего исправления; текущий этап не менял бинарники.

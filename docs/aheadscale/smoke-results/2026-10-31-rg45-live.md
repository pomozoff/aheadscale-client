## Исходное состояние

Доступ к Ubuntu ARM64 Plasma и Fedora ARM64 GNOME восстановлен через прежние SSH-пробросы 2222/2224; серверные ключи сверены с сохранёнными записями по IP. Сами ключи, пароли и SSO-ссылки в отчёт не копируются.

На обеих ВМ CLI/daemon `0.80.0-aheadscale.33`, службы aheadscale и nm-controller active. Desktop работает с `--disable-profiles --native-networkmanager`. Единственный сохранённый профиль `vpn`, service-type `org.freedesktop.NetworkManager.aheadscale`, внешний timeout 720 секунд. В начале VPN неактивен, CLI Idle, интерфейса нет. Владелец открыл системные панели.

- Ubuntu: UUID `c701447b-709b-4d4b-b46f-1498235d301c`.
- Fedora: UUID `38e464d1-b98c-4d3b-b245-58a97a4babc4`.

## Контроль способа запуска

Вызов nmcli из пользовательского SSH-сеанса получил `Not authorized to control networking`. Вызов с sudo начал активацию, но при запросе SSO NetworkManager сообщил `No agents were available for this request`. Эта удалённая попытка не доказывает ошибку штатного системного переключателя: необходимый пользовательский агент не ответил. При повторе использован переключатель самой GNOME-сессии, владелец выполнил вход.

AT-SPI обнаружил две надписи Aheadscale в GNOME: label внутри check menu item и label внутри заголовка toggle button. Они относятся к разным элементам меню; считать количество надписей количеством VPN нельзя. Владелец подтвердил одну строку при Connected.

## Fedora: первое штатное подключение

Владелец: «Fedora Connected, одна строка». CLI Connected, Management/Signal true, VPN-IP `100.88.54.63/16`, профиль default. В NM один сохранённый и один активный собственный UUID; внешнего профиля wireguard с тем же именем нет. Интерфейс Aheadscale существует, адрес совпадает с CLI. Панель и NetworkManager не перезапускались.

Это один успешный сценарий, не доказательство устранения RG45. Остальные сценарии и визуальное подтверждение после перезапуска NM ещё не завершены.

## Границы

Изменений кода и новых пакетов пока нет. Исследован закреплённый plugin v0.1.12 и текущий patch: поле tundev уже передаёт имя интерфейса, его отсутствие не подтверждено как причина. Архив проверен по SHA256; для patch нужен принятый формат git-unified-0 (`git apply --unidiff-zero`), обычный git apply ожидаемо не применил патч без контекста. Компиляция на Mac mini не запускалась.

Диагностика владельческих ВМ выполняется непосредственно через SSH и подтверждения интерфейса владельцем; закрытый продуктовый GUI runner ещё не подключён. Это не полный автоматизированный acceptance и не основание допуска платформ к публичной бете. Целевые Actions понадобятся при изменении кода; уже успешные незатронутые наборы повторно не запускаются.

## Ubuntu и двусторонняя сеть

Владелец: «Ubuntu Connected, одна строка». CLI Connected, Management/Signal true, адрес `100.88.19.208/16`, имя `ubuntu-ahead.aheadscale.internal`. Fedora сохранила `100.88.54.63/16` и `fedora.aheadscale.internal`. На каждой стороне один собственный профиль и один реальный интерфейс.

Приватные имена обеих ВМ разрешились в ожидаемые адреса, TCP по VPN получил SSH banner в обе стороны. SSH-аутентификация по VPN не выполнялась, временные серверы и firewall-правила не создавались.

## NetworkManager restart при ON

Последовательно перезапущен NetworkManager на Fedora и Ubuntu, при Connected и оставленных владельцем открытыми панелях. GUI/панели и ВМ не перезапускались. Обе восстановили Connected автоматически, с прежними UUID и адресами; Management/Signal true. В текущих списках сохранённых и активных подключений по одному своему VPN, отдельного wireguard-профиля Aheadscale нет. После перезапусков заново прошли приватный DNS и TCP в обе стороны.

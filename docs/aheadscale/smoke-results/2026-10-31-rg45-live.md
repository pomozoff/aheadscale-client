## Отмена через CLI

Первая попытка ориентировалась на CLI daemonStatus, но на обеих ВМ первым наблюдался Connected. Остановка привела к правильному Idle, без активного VPN и интерфейса, однако отменой Connecting это **не засчитано** (NOT_EXERCISED).

Повтор использовал другую опору: после подтверждённого Idle запускали CLI up и отслеживали собственный UUID в `org.freedesktop.NetworkManager.Connection.Active.State`. На обеих зафиксирован State=1 (Activating), после чего отправлен CLI down. Оба up-процесса завершились с кодом 1 как отменённые, затем CLI Idle, собственного активного UUID и интерфейса нет, сохранённый профиль один. Через две секунды после окончания прежней команды нежелательного подключения не наблюдалось. Это ограниченное окно проверки, не 24-часовой soak.

**PASS** для отмены через CLI на Ubuntu/Fedora. Задержки сети, firewall, режим службы, профили и часы для этого не менялись. Искусственного удержания engine нет; факт незавершённой системной активации подтверждён D-Bus.

После CLI-отмены владелец подтвердил: «OFF совпал; GUI Connect успешен на обеих, одна строка». Системные панели показывали OFF, сами приложения — Disconnected; подключение кнопкой GUI восстановило Connected без второй строки. **PASS** для этого визуального перехода на обеих ВМ. Это не проверка GUI Cancel.

## Disconnect и попытка Cancel из GUI

Её штатное действие отключило VPN: CLI Idle, VPN-IP пуст, собственного активного UUID нет. **PASS** для Disconnect из GUI. После следующего нажатия той же кнопки NetworkManager прошёл состояния 1 (Activating) → 2 (Activated), восстановлены Connected и прежние адреса; сохранённый профиль Aheadscale по одному.

Кнопка GUI оставалась недоступна для отмены во время наблюдаемой активации; соединение успело установиться до её разблокировки. Поэтому GUI Cancel — **NOT_EXERCISED**, а не PASS или доказанный отказ отмены. В текущем исходнике переключатель разрешает принудительную отмену через семь секунд; искусственную задержку ради проверки не вводили. Обе ВМ после этой попытки оставлены Connected. Периодические наблюдения D-Bus не исключают более короткого состояния между чтениями.

# Windows ARM64: переподключение и завершение системного VPN

Установлена и проверена `.18` / MSIX `0.1.61.1`. Семь последовательных GUI-переподключений, системное отключение через RAS, последующий GUI Connect и автоматическое восстановление после перезапуска службы — PASS. Обмен с Ubuntu по IP, полному и короткому имени прошёл в обоих направлениях. При исходном прогоне проверка кнопки в Windows Settings осталась NOT_COMPLETED. В [повторе 26 октября](2026-10-26-windows11-arm64-settings.md) страница и кнопка работают; дальнейшая диагностика связала недоступность UI с погасшим виртуальным экраном.

## Исправленные ошибки

**RG27 — ложный restart движка.** На `.15` штатное удаление интерфейса Windows при Disconnect вызывало `WireGuard interface monitor: ... restarting engine`. В нативной сборке наблюдатель больше не управляет интерфейсом, принадлежащим Windows VPN. Его закрытие обслуживают системный канал и посредник. Обычные сборки продолжают наблюдать за своим интерфейсом.

**RG28 — незавершённая задача AppService.** На `.16` повторён RG11: второй цикл завершился `broker-configuration`, `0x800704D4`, `appservice-lost`, EOF движка и Idle/Disconnected. На диагностической `.17` при отключениях зафиксирована поздняя отмена фоновой задачи с причиной [SystemPolicy, значение 7](https://learn.microsoft.com/en-us/uwp/api/windows.applicationmodel.background.backgroundtaskcancellationreason). Закрытие соединения не обеспечивало явного завершения выданного задаче deferral.

В `.18` native-канал явно завершает свой ServiceSession до остановки системного канала: снимает обработчики, освобождает deferral и убирает запись соединения. Доступ к записям синхронизирован; закрытие старого соединения учитывает его идентичность. Ошибка удаления записи активного посредника не пропускает освобождение собственного сеанса. После каждого из семи Disconnect проверены свежая причина `native-channel-closed` и отсутствие посредника. Между циклами host и службу вручную не перезапускали.

Временные отметки передачи конфигурации `.17` удалены из исходников `.18`; оставлены безопасные сведения о закрытии сеанса и ошибке регистрации посредника. Проверки пакета, SID, сертификатов, pipe и firewall сохранены.

## Автоматизация и качество свидетельств

- `TestNativeWGIfaceMonitorLeavesLifecycleToWindows`: Windows ARM64 red → green. Проверка обычного наблюдателя на Linux с `-race` — PASS.
- Клиентские UI/controller-тесты с `-race` — PASS; Windows CI исполнил native-регрессии перед сборкой. Линтер изменённого кода — 0 замечаний. Для AppService выполнены реальные циклы установленного пакета.
- Перед исправлением `.15` выдержала 14 переподключений, включая серию с 558 успешными HTTP-запросами. Поэтому отсутствие редкого отказа в короткой серии не принималось за исправление. На `.16` отказ повторился во втором цикле.
- Первая проверка после установки стартовала до готовности UI. В другом повторе общий двухминутный бюджет наблюдателя закончился, хотя все три цикла `.17` впоследствии завершились Connected. Исправлены ожидание состояния и бюджет всей серии; эти ошибки наблюдателя не записаны как отказы VPN.

Полный серверный набор и общий линтер имеют прежние отказы, перечисленные в [предыдущем отчёте](2026-10-25-windows11-arm64-service-recovery.md). Их общий PASS не заявляется. Анализ задержек, reboot `.18`, остальные ОС/архитектуры и весь UI/CLI-план этим прогоном не закрыты.

## Очистка и итоговое состояние

Удалены 23 собственные задачи, временное TCP-правило и оба HTTP-ответчика по квитанциям. При очистке Windows вернула GUID прежнего интерфейса вместо имени: перед удалением сверены точное имя правила, группа, программа, порт, адреса и сохранённый GUID. Первые остановки проверки сохранены; чужие правила не удалялись. Временные диагностические сведения сохранены в свидетельствах; файлов RG11 в LocalState не осталось.

VPN оставлен Connected, запуск UI при входе — Off. Defender, все профили firewall и постоянное UDP-правило native-службы включены. Runtime использует установленный пакет Windows, а не временный worktree.

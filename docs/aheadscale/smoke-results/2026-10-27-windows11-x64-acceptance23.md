# Windows 11 x64: приёмка preview `.23`

27 октября 2026 года. Продолжение общего плана, один агент. Сеть, управление
из двух интерфейсов и переустановка проверены; вся строка платформы ещё не принята.

## Точный комплект

- Windows 11 Enterprise Evaluation, AMD64, CIM build 26300; KVM, 2 vCPU, 8 ГиБ.
- Единый `aheadscale_0.80.0-aheadscale.23_windows_amd64_native-preview.exe`:
  SHA256 `a050ffe81e8964f12d64dc0f2778d08ad23197b220990ab6ceef719461b3c4f4`.
- Клиент `.23`, native MSIX `0.1.62.1` x64; исходник
  `f9a52d82026c4abde721ed10b11e25170f19dd4c`, CI `40310076177`.
- Установленные native GUI и CLI сверены с манифестами. Native GUI подписан
  тестовым сертификатом, стандартный CLI — NotSigned; публичная подпись не принята.
- Сосед: существующая Ubuntu ARM64 `.24`, тот же аккаунт. Windows
  `100.88.12.187`, Ubuntu `100.88.19.208`; имена `ahead-w11-x64` и `ubuntu-ahead`
  в `aheadscale.internal`. HTTP связан только с VPN-IP; входящее временное
  правило Windows разрешало TCP 8765 исключительно от Ubuntu.

Для обратной части сразу после Settings MacBook стал offline. SSH exit 255
не засчитан ни как отрицательный сетевой PASS, ни как дефект VPN. После его
возвращения выполнены полноценные сетевые серии переустановки и T03-SVC.
Транспорт к Ubuntu в итоговой серии — Relayed; принудительная проверка всех
вариантов NAT/P2P этим прогоном не закрывается. IPv6 здесь не проверен.

## Открытые результаты: RG19 и RG22

**T03-OS / RG19 — FAIL в одном штатном reboot `.23`.** Смена LastBootUpTime
подтверждена: 25 октября 18:29 → 27 октября 12:45 по UTC+3. После входа GUI
появился автоматически (PID 5412), служба Running, пользовательская задача
включена. Однако в окне наблюдения клиент остался Idle, системный VPN —
Disconnected. Отдельно прочитаны только два флага: `DisableAutoConnect=false`,
`OnboardingCompleted=true`. Ручной Connect до фиксации результата не выполнялся.
Это не потеря ключа: последующая переустановка и запуск подключились с прежним
ключом без входа. Причина отказа автоматического подключения ещё не установлена;
нужны диагностика запуска и повтор. Скорость загрузки ОС/UI не измерялась.

**C13 / RG22 — неполное сохранение выбора автозапуска.** Перед удалением задача
запуска была включена. После silent reinstall и первого запуска GUI её нет,
хотя файлы UI preferences сохранены. Поэтому весь C13 не PASS: сохранение
регистрации не доказывает сохранение этого системного выбора. Для возврата
исходных условий включён штатный `startup-task.ps1`, SHA256 которого совпал
с исходником; после этого `exists=true, enabled=true`. Это явное восстановление
при уборке, а не автоматический успех установщика.

## Среда и границы результата

В начале QEMU был paused/io-error из-за прежнего nospace. После проверки
свободного места VM продолжена через QMP без reset; замерший RDP не считался
зависанием Aheadscale. Часы гостя отстали примерно на семь часов: исправлены
с текущим UTC хоста; штатный w32tm не получил time data. Проверки сертификатов,
PKCE/state, UAC, Defender и Firewall не отключались; Windows Update не запускался.

Оснастка отдельно исправлялась: неверный владелец окна Settings, обработка
ожидаемого curl stderr, CRLF и PowerShell-фильтр. Эти ошибки не являются
дефектами продукта. Полные UI-проверки, все C01–C24, чистая установка, чужой VPN,
другие версии Windows и публичные подписи остаются открытыми.

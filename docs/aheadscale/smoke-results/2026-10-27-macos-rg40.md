## Причина и принятое изменение

На `.22` и `.23` macOS направляет пакеты к собственному VPN-IPv4 в utun120.
Захват только тестового TCP-порта показал SYN без ответа на UTUN и отсутствие
этих пакетов на lo0. Двусторонний HTTP с Ubuntu по IP/FQDN/короткому имени
продолжает работать. Назначение адреса как CIDR/alias проблему не устраняет.

Изолированный UTUN с адресом 192.0.2.217 воспроизвёл отказ HTTP, после
`route change -host IP -ifp lo0 -ifa IP` получен HTTP 200 с исходным IP
192.0.2.217. Это согласованный владельцем вариант исправления. Маршрут через lo0
остаётся после закрытия UTUN, поэтому одной команды недостаточно.

Новый selfroute проверяет собственный kernel LOCAL /32 и адрес на текущем UTUN,
сохраняет намерение в существующем закрытом журнале statemanager, повторно
проверяет маршрут и меняет его на lo0. После изменения сверяет фактический RIB.
Close и восстановление службы удаляют только точное совпадение сохранённого
адреса, gateway, lo0 index и признаков HOST/LOCAL. Ошибка уборки сохраняет
состояние для повтора; чужой изменённый маршрут остаётся нетронутым.

Проверка показала, что штатный `route change` не сохраняет PROTO2, а -proto3
вообще не поддерживается утилитой. Владение определяется журналом и атрибутами
реального маршрута; на неработающие метки исправление не полагается.

IPv6, netstack, firewall, sysctl, серверная регистрация и RG39 не меняются.
Network Extension и появление системного VPN macOS остаются отдельным блокером.

## Автоматические проверки

- Unit: порядок journal → persist → move; отказ записи; отсутствие журнала;
  чужой маршрут; изменение маршрута во время persist; повторные Set/Close;
  ошибки изменения/удаления; сохранение состояния для повтора; старый журнал;
  некорректные IPv4/IPv6/loopback/multicast. `go test -race` проходит.
- Darwin: отдельный динамический UTUN, HTTP 200 к собственному IPv4 и проверка
  исходного IP, штатный Close, исчезновение UTUN без Close и восстановление
  из настоящего сериализованного statemanager. Повторная уборка безопасна.
- Затронутые iface/device/server/internal проходят `go test -race -tags devcert`.
  Найденная гонка в существующем TestServer_SubcribeEvents устранена в fixture:
  параметры записаны до Start, автоподключение отключено для теста подписки.
  Production-поведение сервера этим изменением не затронуто.
- Darwin lint и общий `make lint`: 0 issues. Перед общим lint штатно собраны
  bindings и frontend закреплёнными Wails beta.3, Node 24.19.0, pnpm 11.4.0.
  `git diff --check` проходит; зависимости и lockfile не менялись.

## Пакет и приёмка macOS 27 ARM64

[CI 40451885685](https://github.com/pomozoff/aheadscale-client/actions/runs/40451885685)
завершился успешно: unit, Windows identity и единственная сборка macOS ARM64.
На macOS 26 runner прошли unit/race и новый изолированный UTUN regression.
Установщики других платформ не пересобирались.

- Source: `45210ec76d7cb43e31cc641fdf83622638eed6bb` (подписанный коммит).
- PKG: `aheadscale_0.80.0-aheadscale.25_darwin_arm64_public.pkg`.
- SHA256: `bd7d361074614b31f6cb2e240b0694b9395e836f4edf68dead75f281872ed13a`.
- Стенд: macOS 27.0.1, build 26A434, ARM64; второй узел — Ubuntu 26.04.1 ARM64 `.24`.
- Проверены все файлы исходного CI-манифеста; нужный public PKG сохранён,
  временная локальная копия internal PKG удалена. Хеш повторно сверен в ВМ.
- Обновление `.23 → .25`: installer exit 0, GUI запущен, Connected;
  ключ, VPN-IP и FQDN прежние, новый SSO не требовался.

Четыре серии по девять HTTP: после обновления, CLI down/up, остановки/запуска
службы и аварийного SIGKILL службы. В каждой серии шесть запросов macOS ↔ Ubuntu
по VPN IP/FQDN/короткому имени и три macOS → собственный IP/FQDN/короткое имя.
**Все 36 HTTP 200**: разные маркеры обработчиков, правильный remote_ip, а тело
ответа подтверждает исходный VPN-IP вызывающего устройства. Собственный ping
macOS — 2/2. Подмена на LAN, hosts, localhost и ручные DNS-исправления не нужны.

| Сценарий | Результат |
| --- | --- |
| CLI down | Idle; собственного /32 нет, lookup возвращает физический default en0 |
| CLI up | Connected без SSO, прежняя идентичность, 9 HTTP PASS |
| service stop | Собственного /32 нет; рабочий физический default сохранён |
| service start | Connected с прежней идентичностью, 9 HTTP PASS |
| launchctl SIGKILL службы | PID изменился; в журнале штатное `cleaning up state darwin_local_route`; Connected, lo0 LOCAL /32 восстановлен, 9 HTTP PASS |

В конце macOS и Ubuntu Connected, ключи/IP/имена прежние, GUI macOS запущен.
Временные HTTP-слушатели и их файлы удалены в каждой серии. Тестовый
192.0.2.217 не имеет остаточного host route. `net.inet.ip.check_interface`
сохраняет 1; firewall и системные защитные настройки не менялись.

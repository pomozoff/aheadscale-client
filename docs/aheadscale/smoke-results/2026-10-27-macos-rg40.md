# RG40: локальный IPv4 macOS

27 октября 2026, Asia/Krasnoyarsk. Продолжение
[предыдущей серии CLI/macOS](2026-10-27-cli-macos23-linux24.md)
и [плана исправления](../../superpowers/plans/2026-10-27-rg40-macos-own-address.md).

## Причина и принятое изменение

На `.22` и `.23` macOS направляет пакеты к собственному VPN-IPv4 в utun120.
Захват только тестового TCP-порта показал SYN без ответа на UTUN и отсутствие
этих пакетов на lo0. Двусторонний HTTP с Ubuntu по IP/FQDN/короткому имени
продолжает работать. Назначение адреса как CIDR/alias проблему не устраняет.

Изолированный UTUN с адресом 192.0.2.217 воспроизвёл отказ HTTP, после
`route change -host IP -ifp lo0 -ifa IP` получен HTTP 200 с исходным IP
192.0.2.217. Это согласованный владельцем вариант исправления. Маршрут через lo0
остаётся после закрытия UTUN, поэтому одной команды недостаточно.

Новый selfroute проверяет собственный kernel LOCAL /32 и адрес на текущем UTUN,
сохраняет намерение в существующем закрытом журнале statemanager, повторно
проверяет маршрут и меняет его на lo0. После изменения сверяет фактический RIB.
Close и восстановление службы удаляют только точное совпадение сохранённого
адреса, gateway, lo0 index и признаков HOST/LOCAL. Ошибка уборки сохраняет
состояние для повтора; чужой изменённый маршрут остаётся нетронутым.

Проверка показала, что штатный `route change` не сохраняет PROTO2, а -proto3
вообще не поддерживается утилитой. Владение определяется журналом и атрибутами
реального маршрута; на неработающие метки исправление не полагается.

IPv6, netstack, firewall, sysctl, серверная регистрация и RG39 не меняются.
Network Extension и появление системного VPN macOS остаются отдельным блокером.

## Автоматические проверки

- Unit: порядок journal → persist → move; отказ записи; отсутствие журнала;
  чужой маршрут; изменение маршрута во время persist; повторные Set/Close;
  ошибки изменения/удаления; сохранение состояния для повтора; старый журнал;
  некорректные IPv4/IPv6/loopback/multicast. `go test -race` проходит.
- Darwin: отдельный динамический UTUN, HTTP 200 к собственному IPv4 и проверка
  исходного IP, штатный Close, исчезновение UTUN без Close и восстановление
  из настоящего сериализованного statemanager. Повторная уборка безопасна.
- Затронутые iface/device/server/internal проходят `go test -race -tags devcert`.
  Найденная гонка в существующем TestServer_SubcribeEvents устранена в fixture:
  параметры записаны до Start, автоподключение отключено для теста подписки.
  Production-поведение сервера этим изменением не затронуто.
- Darwin lint: 0 issues. Общая проверка и приёмка пакета пока выполняются.

## Статус пакета

Кандидат `.25` готовится только для macOS ARM64. Приёмка рабочего пакета,
сохранение регистрации, own-IP, обмен с Ubuntu, Disconnect/Connect и restart
пока не закрыты этим документом. Это не публичный стабильный выпуск;
Developer ID и нотариализация отсутствуют.

# Linux native `.31.6`: системная отмена и восстановление

Дата: 29 октября 2026 года. Это целевая проверка public Desktop ARM64 на
Ubuntu с Plasma и Fedora с GNOME. Полная матрица Linux ещё не принята.

## Что изменилось

Plasma требует собственный VpnUiPlugin: GTK-компонента недостаточно для
системного Connect. Добавленный модуль прошёл загрузку и целевую проверку
Connect в `.31.4`; `.31.6` сохраняет этот модуль и добавляет исправление RG47.
Позднее завершение старого Disconnect теперь не отправляет Stopped новой
активации. Исходники плагина: `73db6ab`; упаковки: `35d397b`.
Клиент, демон и controller не пересобирались: версия `.31`, исходники `2140d3b`.

RPM больше не требует KDE безусловно на GNOME. Все 43 прежние зависимости
сохранены; зависимости собственного модуля Plasma включены условием
`if plasma-nm`. Реальная установка Fedora изменила только пакет Aheadscale,
не установила KDE и сохранила SELinux Enforcing. Промежуточный `.31.5`,
отклонённый проверкой зависимостей, не устанавливался и удалён.

## Фактические результаты

| Сценарий | Результат |
|---|---|
| Установка `.31.6` на обе ARM64 ВМ | PASS: проверены версия, SHA установленной службы и сохранность конфигурации устройства |
| RG47, быстрое повторное подключение Fedora | Целевой PASS: та же новая активная запись дошла до Activated и CLI Connected; оставшаяся часть той диагностической команды завершилась ошибкой разбора пустого D-Bus-ответа и не засчитывалась как Cancel |
| Системный API: Connect → Cancel при Activating | PASS на обеих ВМ через привилегированный nmcli; по 20 наблюдений с интервалом 2 секунды без позднего Up |
| T01 до отмены и после восстановления | PASS: 16 двусторонних HTTP-запросов по IP и приватным именам между обеими ARM64 ВМ и существующим CLI x64 |
| HTTP при OFF | PASS: четыре ранее работавших адреса недоступны; curl завершился с кодом 7, а не ошибкой SSH |
| Настоящая панель Plasma: Cancel до Connected | PASS: три новые активации прошли Activating → Deactivating → Deactivated без Activated |
| Настоящая панель GNOME: Cancel до Connected | PASS: четыре новые активации прошли ту же последовательность без Activated; ещё одна более ранняя попытка успела подключиться и затем была отключена, она не засчитывается как Cancel |
| Обычный пользователь в системных панелях | PASS: журнал NM связывает действия с UID 1000 и процессами Plasma/GNOME, а не с root/nmcli; Polkit не менялся |
| Согласованность окон после системной отмены | Владелец подтвердил: оба приложения Disconnected |
| Реальное состояние после отмены | PASS: Management/Signal Disconnected, VPN-IP отсутствует, активного VPN в NM нет, intent Connected=false, PendingCancel=false |
| Отсутствие самопроизвольного подключения после UI Cancel | PASS: ещё по 12 проверок с интервалом 2 секунды на обеих ВМ; состояние OFF сохранилось |

Проверки через root/nmcli и настоящий пользовательский UI разделены: API-проба
не заменяла проверку кнопки. Сигналы D-Bus и аудит NM записаны наблюдателем,
запущенным до действий владельца. В Ubuntu это активные пути 7–9, в Fedora —
14–17. Путь Fedora 13 включал Activated и учтён только как Connect/Disconnect.
Обе ВМ оставлены **отключёнными**, как требовалось для проверки Cancel.

Полные SHA256 конфигураций до/после совпадают:

- Ubuntu: `a20b412d3fbe8d682759852c80c9f1e22f8e7ed0f6c48b7a78c2e59c8823a93c`.
- Fedora: `c862d47a74def1942fc02b7337dce3bb643fd5cbc44a0176bf29e0ad2a5a11f6`.

## Что остаётся открытым

Этот прогон не включает свежий браузерный SSO из GNOME/KDE auth-dialog:
существующие регистрации действовали. Также ещё нужны ARM boot/autostart,
remove/reinstall и Desktop ↔ CLI на native-кандидате, самостоятельный CLI
ARM64, Desktop Ubuntu amd64 и остальные каналы/архитектуры. Для amd64 пока
нет собранного модуля Plasma; общий producer/CI для KDE ещё не завершён.
Другие ABI Qt/Plasma и KDE 5 не проверены. RG45 остаётся наблюдением:
перезапуск панели устранил две строки, но исходный триггер не установлен.

Три прежних диагностических запуска не считаются успешными Cancel:
отказ Polkit неактивной SSH-сессии, неверное предположение о скалярном JSON
состояния и попытка прочитать пустой ответ DeactivateConnection как JSON.
После исправления способа проверки использованы обычные команды nmcli и
реальная пользовательская панель; продуктовые исправления по этим ошибкам
инструмента не делались. RG39 и поиск задержек не затрагивались.

Полные R05/C13 и RG43 остаются открыты до окончания матрицы. Публичного релиза,
отправки в GitHub и переноса всей незавершённой функции в main не было.

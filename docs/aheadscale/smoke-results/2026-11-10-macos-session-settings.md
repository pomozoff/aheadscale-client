# macOS: настройки сессии и условие Connected

## Реализованный шаг AHEAD-18

Добавлен общий JSON-контракт Go/Swift: версия, UUID поколения, адрес с префиксом,
MTU, DNS-серверы и домены. Размер ограничен 4096 байтами; ключи WireGuard в
контракт не входят. Swift строит NEPacketTunnelNetworkSettings через публичный
API: один маршрут выделенной подсети, MTU и split DNS. Default route и выход
в интернет не добавляются. DNS-серверы должны находиться в этой подсети.

Первый внутренний контракт ограничен IPv4 и MTU 1280. Это не объявление
готовности всей macOS-платформы или поддержки IPv6-настроек: IPv6-пакетный
транспорт проверялся отдельно, а полноценная dual-stack конфигурация потребует
расширения контракта до допуска соответствующего сценария.

NativeReadinessGate требует три подтверждения одного поколения: channel,
settings, engine. Порядок их получения произвольный, Ready выдаётся один раз.
Чужой/старый generation игнорируется. Cancel и ошибка терминальны; ошибка после
Ready снимает готовность. Короткие callbacks сериализованы recursive lock,
включая повторный Cancel из callback. Проверена конкурентная доставка трёх
подтверждений одновременно с Cancel (100 независимых итераций).

## Исправление ложного статуса Actions

Во время RED найден дефект нового Go workflow: неявный shell не включал pipefail,
поэтому `go test | tee` скрывал failure и Actions42819017513 показал success при
реальном compile failure. Этот прогон НЕ считается PASS. Добавлен явный
`set -euo pipefail`; stderr также записывается в журнал. Следующий RED42819371882
подтвердил failure, а GREEN42819749197 содержит фактические PASS/ok.
Ранее опубликованные результаты Go42816083450 проверены по фактическому ok,
но один зелёный значок pipeline сам по себе больше не используется как evidence.

## Граница готовности

Эти компоненты пока не вызываются рабочим PacketTunnelProvider и daemon.
Следующий этап — реальная передача descriptor между root broker и Go,
согласование authoritative конфигурации/готовности сессии, отключение старых
ifconfig/route/DNS действий native-режима и проверка настоящего peer HTTP/DNS.
Установленный fail-closed прототип и рабочий клиент не заменялись. Новый комплект
не следует подписывать ради одних неиспользуемых компонентов: подпись/native gate
выполняются после соединения полного пути. AHEAD-18 остаётся In Progress.

Самопроверка выполнена одним агентом по требованию владельца: рассмотрены
пределы JSON/MTU, маска подсети, split DNS, отсутствие default route,
сериализация Ready/Cancel и игнорирование устаревших ответов. Независимого
review не было.

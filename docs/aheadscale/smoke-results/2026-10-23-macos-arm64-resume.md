# macOS ARM64 — продолжение проверки 23 октября 2026

Прогон по [единому плану](../smoke-test-plan.md) продолжается после
[первичной установки и диагностики HTTPS](../2026-10-22-macos-arm64-smoke.md).
Это проверка установленного preview, без повторной сборки.

## Паспорт

- macOS 27.0.1, build `26A434`, ARM64, существующая тестовая ВМ.
- Пакет: `aheadscale_0.80.0-aheadscale.5_darwin_arm64_public.pkg`.
- SHA256: `17b42d37df3abca6410f8e738ceeb0a77040988396aba17717684954f34d657d`.
- Исходник: `b4bceed3f2a1d3879fb373a8d20554c2050fa1bc`;
  [CI 39697784297](https://github.com/pomozoff/aheadscale-client/actions/runs/39697784297).
- CLI и daemon по фактическому `status --json`: `0.80.0-aheadscale.5`.
- Служба: launchd `system/aheadscale`; приложение: `/Applications/Aheadscale.app`.
- Подпись: ad-hoc, без TeamIdentifier; Developer ID и нотариализация отсутствуют.
- Встроенный application firewall macOS исходно выключен (`State = 0`).
  Во время проверки его настройки, SIP и TCC не менялись; этот стенд не
  подтверждает поведение установщика с включённым firewall.
- Второй узел: планируется ранее зарегистрированная Ubuntu ARM64 того же аккаунта;
  её доступность и актуальный статус в этом прогоне пока не подтверждены.

| HTTPS сервера из гостевой сети | PASS | `curl --connect-timeout 8 --max-time 15 -o /dev/null -w '%{http_code}' https://aheadscale.ru` вернул 200 |
| Установленная служба и GUI | PASS | Запущены оба процесса из `/Applications/Aheadscale.app/Contents/MacOS/`; служба использует собственные socket, журнал и `--disable-profiles` |
| Целостность приложения | PASS | `codesign --verify --deep --strict /Applications/Aheadscale.app` завершился успешно; это проверка ad-hoc подписи |

| DNS при LoginFailed | Частичное наблюдение | `scutil --dns`: основной резолвер LAN на `en0`, приватного резолвера Aheadscale в выводе нет. Цикл очистки после Disconnect ещё не выполнен |
| R04: штатный деинсталлятор | NOT_RUN | Файл `/Applications/Uninstall Aheadscale.command` присутствует и прочитан; исполнение и очистка не проверены |

Положительный HTTPS получен непосредственно из macOS-ВМ, а не на сервере.
После этого доступ прервался: новые SSH-подключения к пробросу macOS завершились
тайм-аутом, отдельная проверка `tailscale ping` до MacBook также не получила
ответа. Запрошено восстановление доступности MacBook и сохранение ВМ включённой.
Это ограничение стенда; причины поведения клиента из него не выводятся.

Неинтерактивный SSH-сеанс не находит `aheadscale` через свой PATH. Для следующих
CLI-проверок используется установленный `/usr/local/bin/aheadscale`; изменение
системного PATH не выполнялось. Попытки расширенной CLI-проверки после потери
SSH не засчитаны.

## Следующая последовательность

1. Восстановить SSH и завершить новый браузерный вход через Connect; сохранить
   обезличенные идентичность, адрес, имя и фактический статус.
2. Подключить Ubuntu того же аккаунта; выполнить T01: шесть HTTP-проверок по
   VPN IP, полному и короткому имени в обе стороны. Записать Direct/Relay.
3. Выполнить S07/S08 и T02: Disconnect с выдержкой 12 секунд, проверка отказа
   VPN-трафика и сохранности обычного интернета/DNS, повторное подключение.
4. Проверить закрытие/открытие UI, restart службы и отдельно всей macOS;
   повторить прикладной обмен, сравнить идентичность, проверить автозапуск.
5. Выполнить оставшиеся UI, CLI, upgrade/uninstall и сетевые регрессии по
   соответствующим разделам единого плана.

S03, S05–S08, T01–T07, R01–R04, U01/U02, расширенные C01–C24 и остальные
регрессии в этом продолжении не завершены. Визуальный осмотр интерфейса не
засчитан по наличию процесса. Системный VPN остаётся отдельным пробелом;
полного smoke PASS для macOS пока нет.

Временные HTTP-сервисы, правила firewall и новые регистрации этим продолжением
не создавались. Приложение и служба оставлены на месте для повторного входа.

# Windows VPN: управление из Aheadscale и системных настроек

Дата обновления: 21 октября 2026. Работа выполняется одним агентом. **На сборке 47 проверены постоянное правило установщика, удаление/повторная установка и реальный обмен после перезагрузки ОС.** Обычный публичный установщик и CDN ещё не обновлены. После первого прогона был выполнен откат. По последующему обращению владельца комплект 47 восстановлен и оставлен установленным: текущее состояние приведено ниже.

## Текущее состояние ВМ после восстановления

Владелец показал отсутствие системного VPN после отчётной очистки. Причина — выполненный нами откат на обычный клиент .8 с удалением опытного пакета; это не новый сбой VPN. Для дальнейших проверок восстановлен тот же проверенный комплект 47 без новой сборки.

Профиль **Aheadscale Prototype** виден в Windows Settings → Network & internet → VPN; Connected и активная кнопка Disconnect подтверждены через UIAutomation. Служба и GUI относятся к комплекту 47; единственный VPN-адрес находится на Aheadscale Prototype, as0 отсутствует. Постоянное разрешённое правило UDP установлено; временных UDP-правил нет.

Автоматическая задача отката удалена после сверки её владельца и точной команды. На рабочем столе создан ярлык **Aheadscale VPN**; запись HKCU Run `AheadscaleVpnPreview` запускает проверенный AheadscaleNativeUI.exe при входе пользователя. Wails определяет запись по пути своего исполняемого файла, поэтому она распознаётся штатным управлением автозапуском. Сам запуск через новую запись после следующего входа в ОС в этом восстановлении отдельно не проверялся.

Комплект, профиль, сертификат и правило оставлены установленными. Защищённый резерв настроек службы и метаданные сохранены в `C:\ProgramData\AheadscaleVpnPrototype`; автоматического удаления работающей конфигурации больше нет. Документированная выше/ниже окончательная очистка относится к предыдущему прогону, а не к текущему состоянию ВМ. Новых HTTP-прогонов при этом восстановлении не выполняли; 24 проверки относятся к ранее испытанному идентичному комплекту 47.

Доказательства текущего состояния: `native-ui47-keep-install.log`, `native-ui47-keep-start.log`, `native-ui47-keep-finish2.log`, `native-ui47-keep-state.log`, `native-ui47-keep-rule.log`; UIAutomation — `native-ui47-keep-settings.log`. Первый вспомогательный шаг сохранения остановился на чтении отсутствующего значения реестра до изменений; после корректного чтения опционального поля повтор прошёл полностью.

## Причина показанной ошибки

В ВМ оставались плагин/контроллер0.1.44.1 и обычная служба0.80.0-aheadscale.8. Опытный GUI пытался подключить системный VPN, а служба не предоставляла требуемый канал пакетов. Журнал показывал отказ открытия канала. Тот же системный Connect воспроизведён в пользовательском сеансе: exit status1. После воспроизведения исходный клиент восстановлен в finally.

Установлен согласованный комплект 46: проверенные MSIX, GUI и опытная служба. Обычный Connect из настоящего GUI прошёл; движок и профиль Windows Connected. В опытном режиме используется единственный интерфейс Aheadscale Prototype с100.88.77.246/16; as0 отсутствует. Обычная сборка использует прежний путь.

## Условие передачи пакетов

Без входящего разрешения UDP у обеих ВМ были каталог/ICE Connected, но WireGuard handshake и HTTP не проходили. Временное правило только для UDP 51830 конкретного exe и LAN-адреса Ubuntu192.168.1.156 восстановило реальный HTTP 200. Это подтверждено отдельно для обычной службы.8 и опытной службы46.

Основной прогон 46 использовал такое же узкое временное разрешение с автоматической очисткой через 10 минут и явным удалением после проверок. Открытия UDP для всех источников в этом прогоне не было. HTTP-приёмник Windows дополнительно ограничивался портом8765, локальным VPN IP и VPN IP второй ВМ; он также удалён.

Перед прогоном 46 автоматическая проверка отклонила изменение установщика без явного согласия на постоянное правило. Затем владелец явно согласовал эту область; скрипты изменены, а полный комплект 47 проверен с постоянным правилом без временного UDP-разрешения. После предусмотренного планом удаления пакета правило также удалено. Готовность обычной публичной установки этим экспериментом не заявляется.

## История отмены и ограничение первой проверки46

На 43 отмена оставляла Connecting и ложный context canceled. На 44 ложный диалог убран, но поздний Login менял Idle на LoginFailed. Новый тест Login сначала дал RED, затем GREEN на Windows ARM64; все TestLogin_ на Linux с -race прошли. В 45 отменённый Login проверяет актуальность контекста под mutex; посредник завершает старый CLI up до финального Down.46 наследует это исправление.

Первая проверка отмены 46 дала FAIL: цикл прекращал ожидание после Idle/Disconnected, затем через12 с требовал также отсутствия адреса и посредника. Снимок конкретного оставшегося ресурса до отказа не сохранялся. Повтор ожидал все четыре предиката в исходном пределе35 с, сохранял результат и проверял12 с стабильности; PASS за9,26 с, диалогов ошибки0. Первый FAIL сохранён в журнале и не считается успешным прогоном.

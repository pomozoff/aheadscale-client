# Windows 11 x64: автозапуск и обновление, 25 октября 2026

Закрытый preview `.12`, не публичный выпуск. Предыдущий [FAIL бюджета восстановления](2026-10-24-windows11-x64-native.md) сохранён. Этот прогон проверяет пользовательский автозапуск; обещание headless-подключения до входа к native VPN не относится.

## Причина и изменение

В исходном прогоне Windows запускала UI из Run через **61,04 с после входа**. Контрольная задача InteractiveToken/Limited с тем же бинарником уменьшила задержку до **1,39 с**. При этом сеть восстановилась через **56,58 с после готовности NAT/RDP**: ускорение создания процесса само по себе не доказывает устранение всех задержек.

Native UI использует собственную задачу `Aheadscale-Startup-<SID>` при входе владельца. Пароль не хранится, повышения прав при запуске нет. Учитываются SID, путь, аргументы, триггер и права задачи. Неизвестная/изменённая задача сохраняется с ошибкой. Мигрируется только собственная включённая запись Run; выключенная настройка не включается. Настройки Windows для остальных приложений не меняются. Стандартная сборка сохраняет прежний механизм Wails/Run.

Общий модуль Task Scheduler используют интерфейс и установщик. Обновление переносит актуальный выбор пользователя, удаление убирает собственную задачу. Добавлены локальные отметки начала/конца команды подключения для разделения задержки UI и RAS.

При реальном обновлении найден ещё один FAIL: после удаления старого native-пакета базовый NSIS повторно вызывал его деинсталлятор из старого UninstallString и зависал. Исправление возвращает указатель на исходный стандартный деинсталлятор после проверки владельца и сохранённого SHA256. Зависшее собственное дерево установки остановлено с проверкой PID/времени/хеша; работающая стандартная служба сохранена.

Первое подключение `.12` отправило команду RAS через 1,36 с после создания UI, затем потребовало браузерный вход. После итоговой перезагрузки команда отправлена через 5,10 с после создания UI (21,98 с после входа в Windows). Это не замер готовности VPN. Не переносить ResumeOnLaunch до ApplicationStarted без доказательства задержки: прежняя Linux-регрессия требовала готового notifier/session bus.

Итог: установленный пакет сократил задержку создания UI с 61,04 до 16,87 с в одном повторе. Контрольные 1,39 с не выдаются за результат итогового комплекта. Бюджет готовности VPN 60 с остаётся открытым до авторизации и DNS/HTTP в обе стороны. Сохранение прежней сетевой идентичности после обновления тоже пока не подтверждено новым Connected-статусом.

Остаются публичная подпись, вся матрица OS/архитектур, полный UI/CLI и проверка реального DNS/HTTP после нового входа.

# Проверки CLI Aheadscale

Это отдельный план для CLI, включая безэкранный сервер. Матрица и сетевые критерии — в [едином плане](smoke-test-plan.md). Команды проверять на точном установленном бинарнике: сначала сохранить `aheadscale --help` и справку доступных подкоманд. Пример команды из исходников не доказывает её наличие в конкретной сборке.

На Linux выполнить отдельную установку `_cli.deb`/`_cli.rpm` без GUI и без графических библиотек. На Windows/macOS, где CLI поставляется общим установщиком, закрыть UI и проверить сценарии без него. Отдельный минимальный CLI-установщик для этих ОС пока не подтверждён — записывать фактический способ доставки. Проверки, зависящие от GUI/native VPN, не объявлять headless PASS.

## Основной поддерживаемый сценарий

| ID | Действие | Критерий |
| --- | --- | --- |
| C01 | Чистая установка нужной архитектуры; `aheadscale version`, `--help`, `up --help`, `status --help`, `service --help` | Бинарник запускается, имя/версия корректны; CLI-пакет не требует GUI; служба установлена штатно |
| C02 | `aheadscale service status`; штатные start/stop/restart; проверить без повышения и с необходимыми правами | Ясные сообщения о правах, реальное состояние службы совпадает; нет повторной регистрации и зависшего процесса |
| C03 | На desktop `aheadscale up` либо `login` с браузером; на сервере `up --no-browser`, если этот поток доступен | Сервер Aheadscale выбран заранее; показанная ссылка открывается на другом устройстве и вход завершается штатным поддерживаемым потоком. Если поток требует локальный callback на исходном сервере и не работает без браузера — FAIL, не подменять ключом |
| C04 | Подключить headless-узел через одноразовый setup key этого аккаунта из закрытого файла; повторить с истёкшим/отозванным ключом | Корректный ключ регистрирует одно устройство; неверный отклоняется, без дубликата. Ключ не попадает в argv/журнал/отчёт. Если выдача ключа недоступна — BLOCKED |
| C05 | `aheadscale status`, `status --detail`, `status --json`, `status --yaml`, `status --ipv4`, `status --ipv6` | Машинные форматы разбираются, адрес/имя/статус совпадают с каталогом. Отсутствие IPv6 не выдаётся за успешный IPv6-тест; при необходимости пометить отдельную возможность незаявленной |
| C06 | Детальный каталог, фильтр статуса и P2P/Relayed по справке; выключить B и включить обратно | Правильные соседи, offline-статус, адреса/имена; чужие устройства отсутствуют. Пустой фильтр не меняет сеть |
| C07 | T01: IP/FQDN/короткое имя, оба направления | Реальный DNS/HTTP, не только Connected |
| C08 | `aheadscale down`, выдержка 12 секунд; повторный `down`; обычный DNS/интернет; P05: три отдельных `up` с T01 на прогретой ОС | Идемпотентное отключение, нет самоподключения; без нового SSO, прежняя идентичность. Раздельно длительность команды/exit code и готовность шести HTTP от старта `up`; до 30 с |
| C09 | T03-SVC, T03-OS и T04 отдельно; P05: без входа в рабочий стол и GUI | На поддерживаемом headless backend соединение восстановлено автоматически, прежний узел, T01; измерены сеть и готовность трафика. Native Windows preview с пользовательским компонентом не считается headless PASS |
| C10 | `status --check live`, `--check ready`, `--check startup`: служба работает/остановлена, клиент подключён/отключён | Проверить значение каждого health-check по справке и коды 0/1; готовность трафика отдельно T01, не выводить её из одного health-check |
| C11 | `debug bundle`, доступные `debug log level`, `debug config`, `debug for`, `debug persistence` по справке | Локальная диагностика создаётся, уровень журналов возвращён к исходному; нет автоматической отправки upstream. Закрытые данные не публикуются; strict-анонимизация проверяется на реальном содержимом |
| C12 | Неизвестная команда/флаг, неверное значение, недоступная служба, отсутствующий/нечитаемый файл ключа; Ctrl+C во время login/up | Ненулевой код и полезный stderr, без паники/зависания/позднего подключения. Секреты в ошибку не выводятся |
| C13 | Обновление предыдущего выпуска, замена Desktop ↔ CLI на Linux, перезагрузка и T01; удаление/переустановка | Сохранены аккаунт, ключ/ID устройства, имя/IP; очищены только свои службы/сеть, GUI и чужие VPN не затронуты |
| C14 | `deregister` только на одноразовом тестовом узле; затем повторное подключение | Наблюдать фактический отзыв регистрации, очистку локального состояния и изменение каталога; повторный up требует штатной регистрации. Освобождение места проверить на сервере, не предполагать по выводу CLI |
| C15 | Пользовательские hostname, пути конфигурации/журнала и `AS_`-переменные; недоступный путь; legacy `NB_CONFIG`/`WT_CONFIG` | Допустимые настройки работают; неправильные безопасно отклоняются. Чужой профиль NetBird не подхватывается, дефолтный endpoint не меняется без явного параметра |

Ключ подготовить вне отчёта с правами `600` на Unix или эквивалентным ACL текущего пользователя/службы в Windows. Пример регистрации: `sudo aheadscale up --setup-key-file /абсолютный/путь/к/файлу`. После успеха удалить файл и отозвать оставшийся действующий ключ. Пароль аккаунта не передавать CLI-аргументом.

## Унаследованные команды и границы обещаний

Ни одну видимую команду нельзя молча объявить проверенной. Для каждой группы ниже записать: есть ли в `--help`, включена ли на сервере и обещана ли в выпуске. Если функция обещана, выполнить функциональный сценарий на каждой применимой ОС/архитектуре. Если выключена, проверить понятный отказ и явно исключить её из документации первой версии. Это **не разрешение удалить команды** в рамках данной задачи.

| ID | Команды / возможность | Проверка |
| --- | --- | --- |
| C16 | `profile list/add/select/rename/remove` | В текущем продукте профили отключены. Если включаются: два независимых аккаунта, один активный профиль, имена/ключи не смешиваются, удаление только выбранного профиля; повторить весь базовый набор |
| C17 | `networks list/select/deselect`, exit node и маршрутные настройки `up` | Для сервера с тестовым ресурсом проверить маршруты, выбор/снятие, split tunneling и очистку после down. В базовой личной сети список может быть пустым; пустой список не PASS маршрутизации |
| C18 | `forwarding list` и перенаправление портов | Проверить выдачу только разрешённых правил и прикладной трафик/отказ; без настроенного ресурса NOT_RUN или явно вне поддержки |
| C19 | `ssh`, доступные `ssh exec`/`ssh sftp` | Отдельно от обычного OpenSSH поверх VPN: встроенный сервер/клиент, разрешение/запрет политикой, команда/выход/передача файла; матрицу отличающихся Unix/Windows подкоманд взять из справки |
| C20 | `expose` | Публикация вовне не входит в первую версию; проверить отсутствие/понятный отказ при выключенном сервисе. Не публиковать тестовый endpoint без отдельного согласования |
| C21 | `state list/clean/delete`, диагностическая `trace`, если доступны | На одноразовом снимке проверить корректные/несуществующие имена, предупреждения, очистку только своих остатков. Не выполнять разрушительные state-команды на рабочем узле |
| C22 | `service install/uninstall/run` и локальный JSON API, если доступны | Служба создаётся/удаляется штатно; ручной run не конфликтует с работающей службой; API выключен по умолчанию, права и неверный адрес проверены. Не открывать API наружу для smoke |
| C23 | `update` и фоновые обновления | Preview не загружает NetBird/upstream. До готовности собственного подписанного канала не объявлять автообновление PASS; обновление пакетным менеджером проверяет C13 |
| C24 | completion, kubeconfig и прочие дополнительные команды, найденные в справке конкретной сборки | Перечислить каждую в отчёте и назначить тест/причину исключения. Для kubeconfig нужен реальный разрешённый кластер; генерация текста не подтверждает доступ к нему |

Все реально поддерживаемые дополнительные флаги `up` (DNS, интерфейс, маршруты, параметры безопасности) инвентаризировать из справки кандидата и проверить минимум допустимое/недопустимое значение и восстановление исходных настроек. Перекрывающийся или намеренно опасный режим выполнять только в отдельном снимке. Отчёт с непросмотренными командами не считается полным CLI-прогоном.

## Время CLI и backend

[Общий протокол P01–P06](connection-performance-test-plan.md) применяется и к CLI. В отчёте закрепить backend: одна версия бинарника не делает стандартный Wintun и native-плагин одинаковыми сценариями. Чтение `status` после GUI-подключения проверяет C05, но не запуск headless. Запуск `up`, его код выхода, системный интерфейс и первая реальная HTTP-передача имеют отдельные времена. Во время GUI-замера не запускать параллельную команду подключения для наблюдения.

Для RG37 начать с подключённой службы с включённым автозапуском. При смене Desktop ↔ CLI выполнить каждую замену одной штатной транзакцией менеджера пакетов, без ручного enable/start после неё: служба должна остаться включённой и восстановить прежний узел/трафик. На RPM `.24` это FAIL RG37; на Fedora ARM64 с RPM `.24.1` соответствующий повтор [прошёл](smoke-results/2026-10-27-rpm37-fix.md); чистая установка, смена варианта и обычный upgrade — разные проверки. Отдельно повторить с исходным Idle и отключённым пользователем автозапуском: исправление не должно молча отменять выбранное отключение.

C15/RG39: фиксировать поведение up с параметрами отдельно из Idle и Connected. В CLI `.24` Already connected означает сохранение действующих настроек; применение --disable-auto-connect подтверждено после down. По решению владельца от 27 октября 2026 года это наблюдение не исправлять и не считать подтверждённым дефектом: идемпотентность up может быть ожидаемой. Код 0 не трактовать как подтверждение изменения параметров; после проверки возвращать исходные настройки.
